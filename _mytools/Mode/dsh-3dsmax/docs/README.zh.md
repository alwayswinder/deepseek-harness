# 3ds Max 角色适配流程（Biped 搭建 → 控制器迁移）

[English](README.md) | 中文

本目录指导你为新角色准备身体骨架、拟合 Biped，并按参考 rig 的语义迁移身体控制层。角色自己的骨架保留为导出对象。先记录本轮输入、几何和骨轴，再选择能执行的分支；Stan 和 Chiya 是案例，不能直接沿用它们的尺寸、节点数量或测试位移。

## 从哪里开始

先填[新角色适配记录](character-adaptation-guide.md)，再按[操作清单](quick-runbook.md)推进。当前配置为 Seven 兼容的 55 身体骨；参考 Biped 为 71 对象。这些是配置数量，Skin 并集、控制层节点、髋宽、段长与伸缩参数按角色和源 rig 实测。

| 输入情况 | 起点与限制 |
|---|---|
| 静态人形、无骨架 | 先按身体骨架指南建立实测 55 骨；Chiya 参数仅供案例参考 |
| 同拓扑、骨轴相容 | 按操作清单拟合并逐阶段验证控制器迁移 |
| 同拓扑、完整骨轴不相容 | 做整链拟合与固定旋转偏移参考层验证；最终控制器输出适配未完成，不能继续普通双树复制 |
| 其他骨数、层级或源控制器结构 | 先建立新映射与配置适配；现有脚本不能直接套用 |
| 无 Skin | 可以测试骨架和满足分支条件的控制行为；蒙皮与变形标为不适用 |

## 执行顺序与通过范围

每阶段另存 `<角色>_<阶段>_<日期>.max`，外部保存身体骨名/父节点、原始静止矩阵、映射和测试记录。会话全局不承担持久化；文件名也不代表验收通过。

| 阶段 | 输出或检查 |
|---|---|
| 0 输入 | 原始输入与工作副本、单位、绑定状态、身体骨清单、落盘静止表 |
| 1–2 Biped | 源配置与本轮 figure、目标髋宽、逐侧长度及骨轴分类；转换分支在映射验证后停止 |
| 3 测量层 | 相容分支的 BIPDRV，Root/twist 分别处理，原身体骨静止不变 |
| 4–5 控制层 | 按碰撞清单合并隔离名字、复制双树、重指约束及全部绑定 |
| 6–7 几何 | 先摆环再拟合静止链、对齐偏移、复核段长，最后求脊柱 percent |
| 8–9 行为 | 双手双脚弯曲、根平移/转向、环响应、四肢越界、全体节点直接复位 |
| 10 保存 | 按源清单设置显示；保存重开，按名字重新解析并逐节点比较 |
| 导出 | bake → FBX → UE 尚未验证，暂无完成验证的操作规范 |

严格整体验收尚未全部通过：Stan 两轮有复位和行为失败；Chiya 已验证身体骨架与轴转换参考层，完整控制器迁移尚未验证。分项结果、失败数值与本地报告位置集中在[适配指南的证据表](character-adaptation-guide.md#6-已有证据与边界)，不能以静止合格或重载恢复替代整体验收。

## 窗口与显示态（每轮开工前先切好）

A、B 各用一个 Max 实例，按完整文件路径和 PID 确认身份。A 只读取证，B 在另存工作副本中施工。显示态存入场景，重开后按保存时状态恢复。

| 用途 | 操作 |
|---|---|
| 取源结构 | 按本轮源图层清单放通控制器层及全部父层，同时隐藏无关旁支 |
| 目标施工 | 按本轮目标图层清单显示网格、控制环和目标 Biped；隐藏源遗留及测量点 |
| 视口对照 | 两窗口统一 Front / Standard / Edged Faces，再检查三视图中的关节与骨轴 |

`PrinceofStan`、`不导出/控制器` 是历史图层名，不是新角色必须具备的名字。图层自身勾选位不能证明有效可见：父层也会隐藏子层；放通父层可能放出面部等旁支。按实际节点可见状态复核，逐节点移层，显示实现见重建指南步骤 6。

## 测量与恢复纪律

写入后用 `completeRedraw()`；判定前退出 Figure Mode，强制求值并在同一次调用内连续读两遍。以本轮外部静止表作为拟合真值，不读取已受约束影响的骨当前值。逐骨比较静止与姿势误差，避免静态补偿掩盖运动错误。

试动后直接复位并比较全部受影响 Biped、测量点和身体骨。失败记录节点与残差，再重载里程碑隔离下一组；重载不算直接复位通过。重开后丢弃旧节点/控制器包装器，按名字重新解析。引用检查使用正向依赖并核对显式绑定，详见控制器指南步骤 6。

Seven 源设计中动控制环不会反驱 Biped；其他源按实测行为验收。仅看控制器是否可见、静止是否重合或末端单点是否复位，均不足以判定迁移成功。
