## 端到端自检清单

### 阶段 0 · 前置（只有骨架的新角色）

- [ ] 骨架是 **55 个 `Dummy`**，UE 规范命名、名字唯一
      ⚠ 这条**只能在建 Biped 之前**用：Biped 的 13 个 `*Nub` 的 `classof` **也是 `Dummy`**，建成后数会变成 68（实测）。已建 Biped 的场景要按名字表筛。
- [ ] 各网格 Skin 名单属于这 55 骨，其**并集**应符合绑定清单（2026-10-16 复现实测 `Body` 54 / `Face` 3 / `Eye` 1 / `Hair` 1；`Root` 不参与蒙皮 ⇒ 并集 **54**，不是 55）
- [ ] 骨架处于**绑定姿势**：静止时网格无变形
- [ ] 「骨架自由」的可执行判据：55 根骨的 pos/rotation 控制器**都是** `Position_XYZ`/`Euler_XYZ`（约束数为 0）。反向依赖还可能有子骨、蒙皮网格等；结合对象归属与控制器检查，不能将依赖类固定白名单当作自由骨架的充分判据
- [ ] 已另存"**建 Biped 之前**"的干净快照（后面所有真值以它为准）
- [ ] **55 根骨的原始世界变换已落盘**：会话全局 `gRest` 不是持久化，重开后必须按落盘数据恢复，而 Max 安全模式禁止 MAXScript 写文件（`createFile` 被拦）⇒ 必须由外部落盘（本次：`work/gRest_Stan.txt`）

### 阶段 1–3 · Biped

- [ ] `bip001*` = **71** 个对象；结构读回与源一致（脊柱 3 / 颈 1 / 腿 3 / 手指 5×3 / 趾 1×1 / `forearmTwist` 2）
- [ ] 装载源 figure 后 `#scale` 与源 rig 同名骨**逐位一致**（否则"长度对、粗细如发丝"）
- [ ] 位置残差 ≤0.05（0 根 >1.0）、朝向残差 ≤0.1°
      ⚠ **读数协议**：判定前必须 `figureMode = false` + `completeRedraw()`，在**同一次调用内**读值并连读两次（调用内读 = 假阳性 `0.0398`；新调用不刷新 = 假阴性 `6.96`；强制求值后真值 `0.0399 / 0.056°`）。并用"Biped 骨指向 vs UE 骨指向"的**纯几何**指标交叉验证（实测 ≤`0.028°`）。
- [ ] 四条肢长 = B 的骨长（本案例 `19.7845 / 20.6696 / 35.3003 / 45.3889`；旧文写 `45.3890`，末位差属取整）
- [ ] `BIPDRV_*` ×55 已建；`Root` 与 `lowerarm_twist_01_l/r` 两个例外已处理
- [ ] 动脚 / 手 / 根之后**再量一次**：误差不增长（只看静止会漏掉刚性缺陷）

### 阶段 4–9 · 控制器迁移

- [ ] 合并后名字隔离：我们的 `bip001*`=71、源的 `SV_bip001*`=71、`SV_` 合计 126（**B 侧前缀必须含 Biped**，实测 126）
- [ ] 链的**静止几何**落在 B 的骨关节：中关节 <0.02、段长与 B 骨长逐位一致（腿 `35.3003/45.3889`、臂 `19.7845/20.6696`）
- [ ] 引用重指后先摆全部环再解链；起环和腕/踝环按静止/BIPDRV 落位，膝/肘环保持近链关节语义，解链后允许小幅对齐，不能靠吸附到骨掩盖链平面错误
- [ ] 54 根 UE 骨的**位置 + 旋转两棵控制器树**从 `SV_*` 复制（含两根 twist）；Root 独立约束到 `BIPDRV_Root`，不得从 `SV_Root` 复制（只复制旋转 ⇒ 动控制器不驱动角色）
- [ ] `lowerarm_twist_01_l/r` 按**源结构**复制（位置→臂中点环、旋转→`Euler`+`LookAt → 腕环`）；改成裸 `Orientation → BIPDRV_*` 会手/前臂扭转
- [ ] **静止偏移对齐**已做，对齐后按 BIPDRV 静止骨长再归一化链段；脊柱 `Path_Constraint.percent` 在最后按当前场景扫描，不能照抄案例值
- [ ] `LookAt.pickUpNode` 与 `LookAt` 目标里**没有** `SV_*` 引用
- [ ] `BIPRoot`（控制层根）→ 本角色的 UE 根 `Root`（位置 + 方向）
- [ ] 参数线 / 表达式里没有**写死的源骨长或距离阈值**（伸缩、midpoint follow）；有就先在源 rig 抄下来、按目标骨长重写
- [ ] 越界伸展行为与源一致（末端环拉到超过 `L1+L2`）：是"停在最大长度"还是"两段平分超出量"，二者观感完全不同；必须同时比较实际段长增量与链末端到环的误差
- [ ] **保留节点不引用源骨架**：按控制器指南步骤 6 检查约束、pickUpNode、ExposeTm、wire/script；从保留节点以 `refs.dependsOn` 查正向依赖，先 `isValidNode` 再读名字，覆盖 UE 骨、BIPDRV、目标 Biped、环、IK 与辅助节点。反向 `refs.dependents` 出现源骨不能作为泄漏证据。
- [ ] **差分验收**：静止 / 双脚分别 +25Z / 双手分别 +25Z / 根骨 +10Z，最大位置差 ≤0.1、最大朝向差 ≤1°
- [ ] 三条驱动测试：动环 +5 → 目标骨 5.000；动根 +5 → 手足 5.000；动 Biped 骨 → 环/骨跟随；全体受影响节点直接复位 ≤1e-4；重载里程碑仅用于恢复，不算直接复位通过
- [ ] 每完成一大步都**另存里程碑文件**（Hold 会连合并一起回退）

### 阶段 10 · 显示与交付

- [ ] `boxMode` 与源一致（本案例 56/71）
- [ ] 只显示：B 的网格 + 源的控制环；源骨架 / 源网格 / 面部表情层隐藏（注意隐藏父层会级联）
- [ ] 另存 → **重新打开** → 复测差分（重开后句柄全变，一切按名字重新解析），按名字逐节点比较保存前后的位置与旋转；不能只检查重开后是否低于静止门槛

## 窗口与显示态（每轮开工前先切好）

源窗口 A 与目标窗口 B 各占一个 Max 实例；**显示态存在文件里**（重开文件会回到保存时的状态）。

| 用途 | 图层操作 |
|---|---|
| 源 A（只读 + 取源真值） | 网格层可见即可；要动/看控制器时：`不导出` **可见** + `控制器` **可见**，并先把 `表情控制器`、`bip` 的**自身勾选位**设成 hidden（同父层，不锁会一次放出约 125 个面部控制器 / 57 根 Biped 骨） |
| 目标 B（施工） | `PrinceofStan`（网格）+ `控制器` + `BIP不导出`（Biped）可见；`FBX`/`Seven`/面部层/驱动点层隐藏 |
| 两窗口统一视口 | `[Front] [Standard] [Edged Faces]`（`set_viewport view="front" shading="smooth" edges=true`） |

> 坑：`控制器` 是 `不导出` 的**子层**，父层隐藏会连带隐藏——"切到显示控制器"没生效，九成是父层没放通。

## 常见误判（先看这里，别急着报 bug）

1. **动控制器时 Biped 不动**——源 rig 的设计（源窗口实测同为 0.0）。环是"偏移/微调 + 可视化"层，摆姿势靠 Biped；要"环反驱 Biped"是源没有的**新增能力**。
2. **复位"看起来"成功但姿势没回去**——单个末端或 `biped.getTransform` 读数不能证明整条链复位；强制求值后比较全体受影响节点的世界变换。历史上出现过 API 与世界位置不一致，另有场景两者一致，不能一概判断该 API 失真。
3. **控制器看不见/选不中**——先查父层，再查图层自身勾选位（`manage_layers list` 报自身位，`Layer.isHidden` 报合并后状态）。

## 工作方式约定（避免"改了但不知道改了什么"）

1. **两个窗口分工**：源 rig（A）只读——只在里面取"源真值 / 源结构"；目标（B）施工。**不修改 A 的文件**。
2. **每完成一大步另存一个里程碑文件**，不要依赖 `Hold`：`fetch` 会把合并一起回退，中间态只能靠文件。
3. **测量纪律**：每次写入后用 `completeRedraw()`，判定前退出 Figure Mode、强制求值并在同一次调用内连续读两次（Max 对 Biped 与约束是惰性求值，第一次常拿到旧值）。
4. **一次只改一件事，改完立刻量**：批量脚本遇到失败要报告节点与操作并停止依赖步骤，不能用空 catch 隐藏错误；恢复到里程碑后重新验证。
5. **移动类试验必须能复位**：`try ( 移动… 测量… ) catch ( … )`，失败路径也须尝试复位并校验残差；无法确认状态时重载里程碑，重新解析节点。
6. **绝对量 vs 差分量的纪律**：任何"静止时的误差"都要再问一句"摆个姿势它会长吗？"——本目录里绝大多数坑都藏在后者。
7. **引用检查按方向与归属判读**：保留节点用 `refs.dependsOn` 查源骨依赖；`refs.dependents <SV_对象>` 可辅助反查保留节点，但源 rig 自身的依赖不必为空。完整检查见控制器指南步骤 6。

## 两条反复出现的经验

1. **静止对准是必要不充分条件。** 下面这些错误都可能在静止时被掩盖：静态补偿偏移、多目标等权混合、指向源骨架的 `LookAt` 上方向节点。只有**差分门槛**（摆姿势后再量）看得见它们。
2. **不要把残差吸收进静态偏移。** 为了让静止"好看"而加的固定偏移，会随关节一起旋转，运动时以同量级回来（本案例：静止 0.0045 → 抬脚 +10 变 2.76）。
