# 新角色适配：输入检查、profile 记录与分支选择

本页定义**换角色时必须重新测量和重新决定的东西**。执行顺序见[操作清单](quick-runbook.md)，算法见[Biped 重建指南](biped-rebuild-guide.md)与[控制器迁移指南](controller-migration-guide.md)。

核心约定：**流程是通用的，数值不是**。同一套阶段适用于不同骨数、不同段数、不同手指配置、不同源 rig；但段长、髋宽、环名、链结构、试动量必须每轮重测并落盘。任何写死在脚本或记忆里的数量都视为缺陷。

---

## 1. 先判断能走到哪一步

| 输入 | 可执行范围 | 继续条件 |
|---|---|---|
| 静态人形、无骨架 | 先按[静态身体骨架指南](static-body-skeleton-guide.zh.md)用实测 profile 建骨架（节点数由 profile 定，样例 55） | 每角色独立测量；其他角色的参数不能按身高缩放照搬 |
| 有骨架、拓扑与源控制器相容 | Biped 拟合、测量驱动层、路线 1 控制器迁移、完整验收 | 每阶段实测通过；已有实验也未全部通过整体验收 |
| 有骨架、相邻关节完整骨轴不相容 | 整链几何拟合、冻结旋转偏移、映射参考层验证 | 当前止于映射验证；最终控制器输出适配未完成 |
| 骨数/层级/手指/脊柱/twist 配置与源不同 | 先做 §4 的配置适配 | 现有脚本不能直接套用 |
| 无 Skin | 骨架、关节拟合、控制器行为测试 | 蒙皮与变形验收标为"不适用"，不得计为通过 |

同名、同层级、每段局部 +X 沿骨长，只说明**部分**条件一致。还必须检查完整静止旋转、双侧髋关节布置、整链弯曲平面与源控制器语义；外观接近不能替代这些检查。

## 2. 三级 profile 与记录模板

每轮在 `work/<角色>_<日期>/` 下产出三份记录（不纳入版本库，交接时随场景一起提供）：

| 文件 | 内容 | 谁来用 |
|---|---|---|
| `adaptation.md` | 本页 §2 模板 | 全程 |
| `gRest_<角色>.txt` | 每骨 `name|parent|row1|row2|row3|worldpos` | 拟合、驱动层、验收 |
| `rig_semantics.md` | 链/环/极向点/辅助点/Expose/控制器树/wire 的语义表 | 迁移阶段 |

### 2.2 body profile

已有骨架时，profile 至少包含：**节点名、父节点、角色标签、世界静止矩阵**。角色标签用于自动推导 posOK、特例与验收集合：

| 标签 | 用途 |
|---|---|
| `root` | 导出根；驱动点例外；不复制控制器树 |
| `spine` / `neck` / `head` | 可与 Biped 链一一对应 |
| `clavicle` | 只有 2 个自由度，用方向指标判定 |
| `limb.upper` / `limb.lower` / `hand` / `foot` / `toe` | 链段与端点；`#pos` 可设性需试探 |
| `finger.<组>.<节>` | 手指链；按组计数 |
| `twist` | 驱动点挂到对应前臂驱动点下；旋转结构按源复制 |

从静态网格新建骨架时，直接复用 `tools/body55/profiles/*.json` 的字段（`format` / `layer` / `meshes[]` / `nodes[]`），并在 `nodes[]` 上补角色标签。

**静止矩阵必须落盘**：每骨记录 `name|parent|3×3 旋转|世界位置`。会话全局变量在重载后失效；被控制器拉偏的当前值不能当拟合真值。

### 2.3 rig 语义表

至少包含：每侧的起环、膝/肘环、腕/踝环、脚掌环、链起/中/末关节、极向点、Expose 助手、控制层根、脊柱 Path 点、共享手指环，以及每一项的**父级类型、控制器树、约束目标、wire 绑定、试动结论**。

最近距离只用于找候选；职责必须由层级、引用和**源窗口试动**确认，不能凭 `CircleNNN` 之类的编号推断。

## 3. 配置常量、角色实测值、源 rig 行为（不要混用）

| 类别 | 例子 | 使用规则 |
|---|---|---|
| **流程常量** | 位置阈值 0.05 / 0.1 / 2e-3 / 0.02（cm）、朝向 0.1° / 1°、阻尼 0.6、迭代预算 | 全流程固定，换角色不变 |
| **配置数量** | `N_body`、`N_map`、`N_copy`、`N_biped`、`N_collision`、`N_total` | 每轮由 profile 与结构参数算出（见操作清单 §0） |
| **每角色几何** | 段长、肩宽、髋宽、髋轴、关节坐标、手指位置 | 全部来自本轮 `gRest` |
| **每源 rig 行为** | 环名、链节点、求解器、长度轴、控制器槽、权重、合法附件偏移、伸缩函数、是否反驱 Biped | 从源实测，写入 rig 语义表 |
| **每轮派生数量** | 临时改名、SV 集、保留节点、约束目标、Expose、boxMode 数量 | 从清单算，一律不写死 |
| **需重新求解的参数** | 脊柱 `percent`、极向点平面、手柄偏移、伸缩阈值 | 每轮重扫，不复制其他角色的结果 |

判断方法：一个数字如果不随角色改变而改变，属于流程常量；如果它来自测量，必须在记录里带来源与日期。

## 4. 配置差异与分支（通用化的核心）

### 4.1 差异矩阵

| 差异 | 影响 | 处理 |
|---|---|---|
| 脊柱段数不同（如 3 vs 4/5） | Biped 结构与源控制器按源段数；目标骨可能对不齐 | 结构照源 rig 赋值；映射表写明加权或"部分骨未驱动"；差分验收只统计能映射的骨并记录余量 |
| 手指数量/节数不同 | 手指环与手指链数量不同 | 映射按组名与节号；缺失组标为未驱动；新增组不受源控制 |
| 无 twist 骨 | 源 ForeTwist 结构无处落地 | 驱动层不建 twist 点；源的 twist 约束删掉或在语义表标为"不适用" |
| 无导出根（root） | `BIPRoot` 无目标可指 | 指定一个替代根（通常 pelvis），在记录里写明；驱动点例外随之调整 |
| 目标多/少一节颈或头 | Biped 颈节数固定 | 结构照源；多余目标骨由最近的上游骨约束或标为未驱动 |
| 脚趾节数不同（toeLinks） | 脚掌环数量不同 | 结构照源；脚掌环按数量映射 |
| 源有 tail/ponytail | 结构参数非零 | 结构照源赋值；目标无对应骨则相关控制器保留但不驱动 |
| 髋宽/腿长/身高差异大 | 拟合难度上升 | 拟合阶段处理（先髋宽、再长度、再朝向），不改变流程 |
| 骨轴不相容 | 逐骨吸附会丢失偏移 | 走 §4.2 转换分支，止于映射验证 |

### 4.2 转换分支（骨轴不相容时）

1. 用肩肘腕、髋膝踝构造共同弯曲平面的 Biped 目标；原导出骨与原始静止矩阵**保持不变**。
2. 另存每骨冻结的世界旋转偏移：

```
O = R_target_rest * inverse(R_Biped_rest)
R_expected_pose = O * R_Biped_pose
```

3. 建 `BIPMAP_*` 参考点（只作测量、不驱动原骨），逐点读回，用冻结的 `O` 验证静止、四肢弯曲、根平移与转向。每个姿势重新算 `O` 会掩盖跟随错误。
4. **到此为止**：最终控制器输出的偏移接入尚未验证，不进入普通双树复制。

### 4.3 通用性检查清单（换角色时必须逐项过）

- [ ] 所有数量（`N_*`）由本轮清单算出，脚本里没有残留的上一轮常量
- [ ] 环/链/极向点由试动确认，没有按编号或图层名推断
- [ ] 试动量按 §5 比例算，不是复制其他角色
- [ ] 髋宽轴实测，不是假设
- [ ] 段长轴实测（`p1+p2` 的分量），不是假设 +X 或 p2.y
- [ ] 极向点先量 `h` 再判断静止是否退化
- [ ] 验收同时记录绝对值与**同姿势源基线**
- [ ] 未覆盖项与失败数值写入记录

## 5. 验收尺度与判定

### 5.1 阈值（cm / 度）

| 项 | 阈值 |
|---|---|
| Biped 拟合位置 / 朝向 | ≤0.05 / ≤0.1° |
| 迁移后骨位置 / 朝向 | ≤0.1 / ≤1° |
| 链起/末端 | <2e-3 |
| 链中关节 | <0.02 |
| 非求解器节点直接复位 | ≤1e-4 |
| 保存重开（非求解器节点） | 差 0（或 ≤1e-6） |

单位先换算：阈值以 cm 表达，场景单位不是 cm 时按系统单位换算后使用。

### 5.2 试动量按比例取（写进适配记录后执行）

| 测试 | 取法 | 样例（肢长 80.7） |
|---|---|---|
| 肢体弯姿势 | 两段总长的 30% | 25 |
| 越界伸展 | 两段总长的 25% | 20 |
| 根平移 | 骨盆高度的 10% | 10 |
| 根转向 | 15° | 15° |
| 环位移 | 5，或总长的 6% | 5 |

要求：弯姿势必须真的产生可测的肘/膝弯曲（记录实际弯曲角，样例腿 38.3°、臂 59.0°）。

### 5.3 判定三分法（本轮新增）

| 判定 | 条件 |
|---|---|
| **通过** | 达到绝对阈值 |
| **与源等价** | 未达绝对阈值，但不劣于源在同姿势的实测值，且差值可解释；必须在记录中写明源值 |
| **失败** | 劣于源，或无法解释差值 |

不允许用"固有残差""可接受"一句话豁免；也不能因为源本身不达标就把目标的不达标记为通过。

### 5.4 读取与记录要求

- 写入后 `completeRedraw()`；判定前退出 Figure Mode，同一次调用内连读两次。
- 角差用规范化旋转计算；接近零时用四元数向量部分与标量部分的 `atan2` 形式，避免 `acos(w)` 舍入为 0。MAXScript 三角函数用**度**。
- 锁骨用几何方向复核，不要求两个自由度实现任意完整旋转。
- 逐骨比较姿势前后的误差，不能只比全局最大值。
- 节点比对必须用**引用快照**（同名节点不能用名字比对）。

## 7. 通用性维护规则

1. 任何写进文档的数量必须标明"样例"或"公式来源"，否则视为缺陷。
2. 新增一个角色时，先比较它的 profile 与上一轮的差异，再决定是否需要改脚本；不能直接复制上一轮的脚本常量。
3. 每轮结束把"与上一轮的差异点"写进 `adaptation.md` 的结论段，供下一位读者判断适用范围。
4. 历史个案（[Stan 记录](stan-biped-controller-migration-task.md)、[references/](references/)）只作追溯，不承担规范职责。
