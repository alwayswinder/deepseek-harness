# 身体控制器迁移指南（源 rig 控制环 → 目标角色）

> **一句话**：把源角色 A 的控制环（起/末端环、肘膝环、辅助 IK 链、极向点）搬到目标角色 B 身上，"静止对准"只是**必要不充分**条件；
> 必须用**差分指标**（摆姿势后再测）验收，否则会得到"静止全对、一动就炸"的结果。
> 本指南基于 Seven → Stan（新建 Biped）实战，2026-10-16 定稿；Biped 本身怎么拟合见 [biped-rebuild-guide.md](biped-rebuild-guide.md)，本案例流水账见 [stan-biped-controller-migration-task.md](stan-biped-controller-migration-task.md) §10。
> **2026-10-16 修订（第二轮复现后）**：修正了 ① 步骤 3「只改 `c1.value.x`」→ 按「方向 × 目标骨长」写 `p1`（腿/臂的长度分量位置不同）；② 步骤 5 复制**位置 + 旋转两棵树**（旧文"位置侧不用改"会做出"动控制器不驱动角色"的半成品）；③ 新增**步骤 5.5 静止偏移对齐**（含 `percent` 收尾顺序）；④ 步骤 7 复位必须按**世界位置**校验；⑤ `*_twist` 与手臂 `LookAt` 改指加适用条件（照旧文做会**手/前臂蒙皮扭转**）。逐条证据见 [../work/WFTest_guide-findings.md](../work/WFTest_guide-findings.md)，一次跑通顺序见 [quick-runbook.md](quick-runbook.md)。

## 0. 适用与最终架构

适用：A 是自带完整原生控制环的成品 rig（Biped + 环 + 辅助 IK 链 + 极向点 + 蒙皮），B 是需要"用 A 的控制器来摆姿势、最终导出自己的骨架"的角色（B 的骨架可以是新建 Biped，也可以是纯 Dummy）。

```
摆姿势入口（两条都成立）
   ├─ 动 Biped 骨 ──┐
   └─ 动控制环 ─────┤
                    ▼
            源 rig 控制环（环 → 辅助 IK 链 → 肘膝环）
                    ▼
            目标 UE 骨（Dummy，蒙皮对象）  ← 旋转：逐骨复制源结构；位置：环的位置
                    ▼
                 Skin → 角色网格
```

关键点：

- **B 的 UE 骨是蒙皮对象**，导出命名不能改；改名的永远是 A 侧（加 `SV_` 前缀）。
- 动 A 的环**不会**反驱 A 的 Biped（实测 0.000），所以环是"**偏移/微调 + 可视化**"层；摆姿势靠 Biped。
- 环的位置来自 Biped 骨（挂父子或约束），所以"动 Biped → 环 → UE 骨"和"动环 → UE 骨"两条路径都通。
- **位置侧**：UE 骨 = 环的世界位置（单目标 `Position_Constraint`，偏移 0）。
- **旋转侧**：UE 骨的旋转必须**逐骨照抄 A 的结构**（见 §2 步骤 5），不能自己另搭。

## 1. 为什么"静止全对、一动就炸"——四条放大机制

实测现象（Seven → Stan，腿）：静止时膝/肘环与 Biped 关节差 `2.56 / 2.56 / 4.64 / 4.64` 单位，被静态补偿掩盖；
抬脚 +10 时小腿骨位置差 **2.76**、大腿朝向差 **29.2°**、小腿朝向差 **29.7°**。四条机制叠加。

### 1.1 近全伸展的径向放大（段长错一点，膝偏一大截）

两条腿在静止时接近全伸展（膝关节非常靠近"髋—踝"轴），此时中关节到轴的垂距 `h` 对段长差 `δ` 极其敏感：

```
h ≈ sqrt(L · δ)          L = 上段骨长，δ = 段长冗余量（L1+L2-d）
dh/dδ ≈ 0.5 · sqrt(L/δ)
```

- 本案例 A 的链段长 `36.61 / 43.96`，B 的骨长 `35.30 / 45.39`：**上段差 1.31、下段差 1.43**。
  单看总长只差 `0.12`，但"分配比例"错了 ⇒ 用三角形面积公式算，中关节离轴高度从 B 的 `2.26` 变成 A 的 `0.67` ⇒ **膝部径向偏 2.5 单位**。
- 同样是这条链，若总长差 `0.077`，膝径向能从 `2.16` 顶到 `2.78`（配方原案例实测）。
- 结论：**段长必须按 B 的骨长重算，且要拟合到"实测解算长度"**（§2 步骤 3）。

### 1.2 静态补偿活在旋转坐标系里（静止准、一动还全错）

上一轮迁移为了让静止"好看"，把 `2.56 / 4.64` 的误差写进了膝/肘环的**局部补偿偏移**（`零位置 XYZ`）：

- 静止：偏移正好抵消误差 ⇒ 环落在 Biped 关节上（实测 `ringErr=4.5e-3`，看着完全正确）。
- 运动：补偿是**关节局部坐标系里的固定向量**，会跟着关节一起转；而它要抵消的那个误差（链中关节相对目标关节的偏差）**大小和方向都随弯曲变化** ⇒ 抵消失效，误差原样回来（静止 `0.0045 → 抬脚+10 变 2.76`）。

⇒ **不要用静态偏移吸收残差**。任何"为了让静止对上"而加的固定偏移，都会在运动时变成同量级的错误。
正解是把段长/结构改对，让静止误差**结构性地**为 0（本案例修完 `2.56→0.0001`）。

### 1.3 等权多目标是"取平均"，两个信号一分开就错一半

若 UE 骨的旋转被写成两个 `Orientation_Constraint` 目标、权重各 100（例如"跟 Biped 的驱动点"+"跟环"），
结果是两个朝向的**球面平均**：

| 状态 | 两目标夹角 | 混合后相对 Biped 的误差 |
|---|---|---|
| 静止 | 大腿 3.52° / 小腿 6.73° | 1.76° / 3.36°（**绑定姿势已经错了**） |
| 抬脚 +10 | 大腿 **59.17°** / 小腿 **29.70°** | **29.59° / 14.85°** |

两个目标在静止时"看起来一致"，其实是"都偏一点"；一旦肢体运动，一个跟着 Biped 骨、一个跟着环/瞄准线，**立刻分道扬镳**，平均出来的就是一半的错。
⇒ 旋转必须**照抄源 rig 的逐骨结构**（`rotation_list`：`[1] Euler_XYZ` 基值 + `[2]` 单个 `LookAt`/`Orientation`，权重 50），不要自己叠第二个目标。

> 追加陷阱：`obj.pos.controller = Constraint()` 与 `appendTarget` 在**列表控制器里是追加不是替换**，
> 反复"修正"会越叠越多目标 ⇒ 实测出现过 2.5 倍响应与 45° 扭转。批量脚本要么先 `deleteTarget`（倒序）清空，要么整棵 `copy`。

### 1.4 `LookAt` 的滚转来自"上方向节点"（`pickUpNode`）

`LookAt` 只能定"瞄准"，绕瞄准轴的**滚转**由 `pickUpNode` 决定。若它仍指向**源骨架的骨**（本案例 `SV_bip001 R/L ForeTwist[1]`、`SV_bip001 Pelvis/Spine/Spine1`）：

- 静止：该骨是源角色的静止位置，恰好"看着对"；
- 运动：上方向节点是世界里静止的 ⇒ 滚转不跟 ⇒ 实测前臂差 **16.7°**（源 rig 同结构 23.0°）。

⇒ `pickUpNode` 必须改指**目标自己的同名骨**。本案例改完 + 瞄准目标改指目标关节环后，前臂滚转 `16.7° → 0.39°`。

### 1.5 方法论：所有"静止门槛"都看不见以上四条

上一轮用的门槛是"静止位置 ≤0.05、静止朝向 ≤5°"——**全是静态测量**。
而 1.1–1.4 的每一种错误都被"设计成"在静止时恰好为 0（补偿偏移、双目标平均、静止的上方向节点）。
⇒ 门槛必须加一条**差分项**：摆一个标准姿势（本案例：抬脚 +25Z、抬手 +25Z、根骨 +10Z），
再测"UE 骨 vs Biped 骨"的差，要求**不随姿势增长**（配方里的"刚性漂移"指标）。

### 步骤 3 —— 让辅助 IK 链的**静止几何**落在 B 的骨关节上（**静止**时做）

链关节是 Point，`pos.controller` 是 `position_list`：`[1] bezier_position`（**唯一稳定可写的杠杆**）、`[2] Position_XYZ`（偏移槽，腿的伸缩线挂在它的 X 上，实测腿 `+0.0385513`、臂 `0`）。

**有效局部向量 = `p1 + p2`**（实测恒等式误差 1e-6），而**长度分量两套 rig 放的位置不同**：腿在 `p1.x`（实测 `p1=[35.21,0,0]`、`p2=[0.0385,1.85,-0.22]`），臂在 `p2.y`（实测 `p1=[5.40,0,0]`、`p2=[0,-19.03,0.55]`）。
⇒ 旧文「只改 `c1.value.x`」**只对腿成立**，对臂会改掉方向而不是长度。

```maxscript
-- 正确写法：按「方向 × 目标骨长」构造有效向量，只写 p1（并扣掉 p2）
local invP = inverse j1.transform
local wantLocal = t2 * invP                              -- 目标（B 的中段骨静止位）在父级局部坐标里的点
local dir = normalize (wantLocal - [0,0,0])
local c1 = (getSubAnim j2.pos.controller 1).controller    -- ⚠ 必须 getSubAnim；j2.pos.controller[1] 是 SubAnim 包装，参与向量运算会报 undefined→Point3
local cz = (getSubAnim j2.pos.controller 2).controller
c1.value = (dir * L1) - cz.value

-- 中点关节用「父级局部坐标系不动点」迭代更稳（求解器会回拉，20 次内收敛到 0.005~0.025）
for iter = 1 to 40 do (
  if ((length (t2 - j2.transform.pos)) < 0.01) do exit
  local invP = inverse j1.transform
  c1.value = c1.value + ((t2 * invP) - (j2.transform.pos * invP))
  redrawViews()
)
```

**末端关节由求解器接管，不要写它**：直接写冻结值会发散（实测臂末端段长被撑到 `39.25`，目标 `20.67`）；末端只保证段长（把现有有效向量归一化后乘 `L2`），位置交给下面的环。
**也不要写 `j.rotation` 或 `move j`**：会触发 IK 重解并改坏段长（实测 `|j1-j2|` 由 `35.3003` 变 `37.9`）。

**环必须落在链关节上（源 rig 语义），不是落在骨上**：实测源数据里 14 个肢体环本来就与链关节重合（偏移 ~1e-5），**不要**把它们"移到 B 的关节"。

```maxscript
in coordsys world ( move <环> (<对应链关节>.transform.pos - <环>.transform.pos) )
```
- 只有**腕/踝（末端）环**要额外落到 B 的骨关节：末端骨的「位置」由环 1:1 决定，而末端关节由求解器管，二者解耦，动控制器才能带动末端骨。
- ⚠ 把**膝/肘环**挪到骨上会被拉到髋—踝轴附近，`LookAt` 的上方向节点退化 ⇒ `calf` 朝向实测**翻 179.4°**。

门槛（2026-10-16 复现实测）：`|链中点关节 − B 中段骨| < 0.02`（腿 0.009 / 臂 0.005~0.024）、段长与 B 骨长逐位一致（`35.3003/45.3889`、`19.7845/20.6696`）。
> 旧文记的「膝/肘环补偿偏移 `2.56 / 4.64` 需归零」在本次复现里**不适用**：源数据里环本来就落在链关节上（偏移 `1.6e-05`），不需要补偿偏移，乱改反而让骨离位。

### 步骤 4 —— 极向点在**弯姿势**对齐

静止时肢体近全伸展 ⇒ **平面退化**，极向点怎么转都看不出效果（本案例大腿静止离轴 2.26 单位，方向被"伸展"掩盖）。
但段长在静止时最敏感（§1.1），**两者不能在同一轮里做**：

```maxscript
-- 4.1 先把肢体弯起来（末端骨 +25Z）
biped.setTransform <末端骨> #pos (<原位> + [0,0,25]) false
redrawViews(); redrawViews()
-- 4.2 极向点绕"起—末端轴"转到目标中关节所在平面（保持离轴距离）
local S = <起关节>.transform.pos ; local H = <末端环>.transform.pos
local k = normalize (H - S)
local dt = (<B 中段骨>.transform.pos - S) - (dot (<B 中段骨>.transform.pos - S) k) * k
local P = <极向点>.transform.pos
local along = dot (P - S) k
local perpDist = length ((P - S) - along * k)
in coordsys world ( move <极向点> ((S + along*k + normalize(dt)*perpDist) - P) )
redrawViews()
-- 4.3 复位
biped.setTransform <末端骨> #pos <原位> false
```

> 2026-10-16 复现修正：源数据里环本来就落在链关节上（偏移 `1.6e-05`），**不需要**"补偿偏移归零"；强行把 `[2]` 归零反而会让环离位、骨偏位。只有当你的源数据里确实存在"靠补偿凑对"的偏移时才做这一步。

门槛：弯姿势下 `|中关节 − B 中段骨|` 与静止同量级。本案例腿 `0.053→0.0004`、臂 `0.226/0.959→0.020/0.020`。

> 2026-10-16 复现补充（**本步可以放到步骤 5.5 之后做**）：链按步骤 3 对齐、环落在链关节上之后，**弯姿势本来就跟得住**（实测抬脚 +25Z 时 `|UE calf − Biped calf| = 0.0003`），再挪极向点几乎没有变化；而**静止**时移动极向点 ±40 只让链中关节动 `0.118`（平面退化）。
> 建议顺序：步骤 3 → 5 → 5.5 → 回到本步只做**弯位复核**，只有弯位明显不合才调极向点。

### 步骤 5 —— 逐骨复制源 rig 的**位置 + 旋转**两棵控制器树（**核心一步**）

```maxscript
for o in objects where ((substring o.name 1 7) == "BIPDRV_") do (
  local bn = substring o.name 8 60               -- BIPDRV_ 之后即骨名
  if (bn != "Root") do (                          -- ⚠ Root 例外：它的位置+方向约束指向 BIPDRV_Root（重建指南步骤 5），覆盖它会让角色根不再跟随 Biped
    local src = getNodeByName ("SV_" + bn)       -- 源 rig 的同名 UE 骨
    local dst = getNodeByName bn                 -- 本角色同名骨（蒙皮对象）
    if (src != undefined and dst != undefined) do (
      dst.pos.controller      = copy src.pos.controller        -- ⚠ 位置侧**必须**一起复制
      dst.rotation.controller = copy src.rotation.controller
    )
  )
)
```

源结构（本案例 55 根骨实测，全部是 `rotation_list`）：

| 槽位 | 内容 | 说明 |
|---|---|---|
| `[1]` | `Euler_XYZ` | 基值（静止滚转/扭转微调） |
| `[2]` | `LookAt_Constraint` 或 `Orientation_Constraint` | 权重 **50**；`LookAt` 用于**上臂/前臂/大腿/小腿/脊柱/`*_twist`**，`Orientation` 用于手/脚/脚掌/手指 |

**位置侧同样要复制**：全新复现里目标骨在合并后仍是自由 `Position_XYZ`，没有任何环节把「骨 = 环的位置」建立起来。只复制旋转 ⇒ "动 Biped 会跟、**动控制器不跟**"的半成品（正是流水账 §10.14 记录的那个 bug）。复制完必做三处**重指**：

| 位置 | 源 rig 指向 | 改成 |
|---|---|---|
| `LookAt.pickUpNode` | `SV_bip001 R/L ForeTwist[1]`、`SV_bip001 Pelvis/Spine/Spine1` | 目标同名骨 `bip001 …` |
| `LookAt` 目标 | 上臂→`Circle021/023`、前臂→`Circle022/024`（源的中点环） | **先量再决定**：链已按步骤 3 对齐时中点环本来就落在线段上 ⇒ **保持源目标**；只有实测明显离线（案例偏 9.9/11.4）才改指 上臂→**肘环**、前臂→**腕环** |
| `*_twist` 骨（`lowerarm_twist_01_l/r`） | **源结构原样复制**：位置 = `Position_Constraint → Circle022/024`（臂中点环）；旋转 = `rotation_list`（`[1] Euler` 基值 + `[2] LookAt → 腕环`） | ⚠ **不要**改成裸 `Orientation_Constraint → BIPDRV_lowerarm_*`（那是给 v2 驱动层中间态写的）：那样 twist 只跟静态 Biped，动控制器时前臂扭转骨卡住 ⇒ **手/前臂蒙皮扭转**（2026-10-16 现场反馈、已定位修好） |

> ⚠ 2026-10-16 复现修正：这条"改指关节环"的建议**只对「中点环离线」的场景成立**。链按步骤 3 对齐后中点环本来就落在线段上，改指反而偏离源行为（源的目标就是中点环）。判据：量 `|中点环 − 线段|`，接近 0 就不要改。
> 案例里改指后前臂 `12.35°/10.20° → 0.390°/0.390°`；twist 按源结构复制后 `0.04°/0.00°`。

### 步骤 5.5 —— **静止偏移对齐**（复制完必做；旧版指南缺这一步）

复制完结构后骨会被拉向"源几何"，实测 **44/52 根偏 >0.2（最大 6.82 `clavicle_l`）**。做法：把「每个约束目标 ← 驱动它的骨的平均误差」迭代回写（阻尼 0.6，1–2 轮收敛）。

```maxscript
-- 每轮：tgtDelta[目标] = 平均(rest_i − bone_i)，然后 in coordsys world ( move 目标 (0.6 * delta) )
-- rest_i 用步骤 1 落盘的原始静止（不要用骨当前值，那会自反馈）
```

- ⚠ **跳过**：`Path_Constraint` 驱动的点，以及**肢体 IK 环**（起/膝/肘/腕/踝/脚掌环）——它们决定链的解算，挪了会把链拖走（实测挪踝环会让整条腿偏 10+）。
- ⚠ **手指环**在共享手柄上会振荡（实测一轮 `24.3 → 0.098 → 2.19`）：改用**逐骨验证式贪心**（每步只接受让该骨误差下降的位移），或直接跳过已对齐的手指环。
- ⚠ **`Path_Constraint.percent`（脊柱）必须放在最后一遍**：实测 `Point001` 最优 **49.97**、`Point002` 最优 **99.9968**（指南案例写的是 58.0769→50.0）。先做 percent 再迭代手柄会被层级带偏（`spine_02` 回弹到 1.41）；反过来则 `spine_02` 0.0038。
- 门槛：52 根骨相对驱动点 **位置 ≤0.1、朝向 ≤1°**（2026-10-16 复现：0.052 / 1.013°，其中 `calf_r` 的 1.013° 属固有残差）。

### 步骤 6 —— 控制层根、辅助点比例、写死的数值、残留引用

- **控制层根**（`BIPRoot` 之类）的位置+方向约束必须指向**目标自己的 UE 根**（`Root`），不能留在源 rig 的静态根（`SV_Root` @ 原点）：
  否则角色一平移/旋转，极向点不跟 ⇒ 膝平面全错。**改完复核步骤 4 / 5.5**（极向点或静止对齐若有变化再调）。
- **脊柱辅助点**常挂在一条样条上（`Path_Constraint`），`percent` 是**源角色的比例**：扫描方法与**顺序要求（必须在手柄迭代之后）**见步骤 5.5。案例原值 `58.0769` → `50.0`（`spine_02` `1.55785 → 0.00168`）；2026-10-16 复现实测最优是 `Point001 = 49.97`、`Point002 = 99.9968`。
- **参数线 / 表达式里写死的数值**：源 rig 的伸缩（stretch）与 midpoint follow 常把"源角色的骨长、两段总长的一半、距离阈值"写进 wire / expression。
  换角色后这些数全错，而且**静止看不出来**（在接近全伸展时才生效）。做法：
  1. 在**源 rig** 里逐条抄下 wire/expression（`getWiredParams`；或遍历控制器树找 `Float_Wire` / `float_limit` / `*_Wire`）；
  2. 在目标里按**目标骨长**重写（阈值 = 该肢两段总长的一半）；
  3. 复测"越界伸展"行为（把末端环拉到超过 `L1+L2` 的位置，看是"停在最大长度"还是"两段平分超出量"——两种规则的观感完全不同）。
  > 本案例的 wire 是**常量偏移**（`+0.0385513`，挂在链关节"零位置 XYZ"的 X 上），已被步骤 3 的长度迭代吸收；但若源 rig 的 wire 是**按骨长计算**的，必须重写。
- **清掉所有仍指向源骨架的引用**：`LookAt.pickUpNode`、`ExposeTm.localReferenceNode`、约束目标等。
  用 `refs.dependents <SV_对象>` 反查最快（本案例清掉 7 处 `pickUpNode` + `BIPRoot` + 2 个 `ExposeTransform`）。**交付前这项必须为空**（否则将来删源 rig 遗留层时会断线）。
- ⚠ **参数线（wire/expression）也会引用源对象，而且约束级扫描查不出来**（2026-10-16 复现踩到）：上一步只清"约束目标 + `pickUpNode` + ExposeTm 节点"，实测保留层仍残留
  `Point001 → SV_spine_02`、`Point002 → SV_spine_01`、`Line001 → SV_spine_01/02`、**`Circle013 → SV_calf_r / SV_thigh_r`**（膝环上挂的伸缩线读的是**源骨长**）。
  查法：对**每个保留层对象**做 `refs.dependents <对象>` 再筛出名字带 `SV_` 的（反向查，无归属歧义）；不要只从 `SV_` 正向查（参数块的属主难以解析）。
  修法：把 wire 的源改指目标同名对象，或按**目标骨长**重写式子（阈值 = 该肢两段总长的一半），改完复测"越界伸展"。

### 步骤 7 —— 差分验收（**必须做**）

对 55 根骨，逐状态测"UE 骨 vs Biped 骨"的位置差与朝向差：

1. 静止；
2. 抬右脚 `+25Z`（深屈膝）；
3. 抬右手 `+25Z`、抬左手 `+25Z`（屈肘）；
4. 根骨 `+10Z`；
5. **每次复测后必须精确复位（≤1e-4），且要按"世界位置"校验**：`biped.setTransform <骨> #pos <原位> false` 之后 `biped.getTransform <骨> #pos` 会读回"已复位"（1e-5），而**求值后的世界位置仍偏 25.0**（实测），Biped 被留在弯姿势。
   ```maxscript
   for k = 1 to 12 do (
     biped.setTransform b #pos p0 false ; redrawViews() ; redrawViews()
     if ((length (b.transform.pos - p0)) < 1e-3) do exit
     biped.setTransform b #pos (biped.getTransform b #pos + (p0 - b.transform.pos)) false
   )
   ```

本案例（`Stan01_BIPbuild_ctrl_fixed_v8_20261016.max`）：

| 状态 | 最大位置差 | 最大朝向差 | 超门槛（r>1° 或 d>0.1） |
|---|---|---|---|
| 静止 | 0.041（`lowerarm_l`） | 0.76°（`Root`） | **0** |
| 右脚 +25Z | 0.056（`calf_r`） | 0.76° | **0** |
| 右手 +25Z | 0.234（`lowerarm_r`） | 0.77° | 2（<0.7°） |
| 根骨 +10Z | 0.020 | 0.76° | **0** |

修前对照：抬脚 +10 → 大腿朝向 29.2°、小腿朝向 29.7°、小腿位置 2.76。

## 4. 陷阱速查

| 症状 | 原因 | 修法 |
|---|---|---|
| **静止对、一抬脚就炸** | 链段长还是源角色的（§1.1）+ 静态补偿（§1.2） | 步骤 3 + 4 |
| 静止就差 2–7°，一动差 15–30° | 旋转被写成多目标等权混合（§1.3） | 步骤 5（`copy` 源结构），不要自己叠目标 |
| 手臂一弯差 16–23° | `LookAt.pickUpNode` 指向源骨架的骨（§1.4） | 改指目标同名骨 |
| 越"修"差得越多（2.5 倍响应、45° 扭转） | `obj.pos.controller = Constraint()` / `appendTarget` 在列表里是**追加** | 先 `deleteTarget`（倒序）或整棵 `copy` |
| 骨长怎么调都不守恒 | 段长 = `p1 + p2`（伸缩线在 `p2.x`；**腿的长度在 `p1.x`、臂在 `p2.y`**） | 只写 `p1`，按"方向 × 目标骨长"构造（步骤 3） |
| 极向点转了没反应 | 静止时平面退化（近全伸展） | 在**弯姿势**对齐（步骤 4），但段长仍在静止拟合 |
| 对角骨被拉坏 | 用绝对坐标设链关节位置（= 改骨长） | 只写"冻结位置/零位置"的**值**，或对普通 Point 用 `move` |
| 动角色根后膝平面全错 | 控制层根挂在源 rig 的静态根上 | 步骤 6；改完复核步骤 4 |
| 约束目标都改指了、删源层后仍有零件跟着源走 | **参数线（wire / expression）**也引用源对象，约束级扫描查不出来 | 对每个保留层对象做 `refs.dependents <对象>` 反向筛 `SV_`（步骤 6 末条） |
| 脊柱某节静止偏 1–2 单位 | 样条 `percent` 是源角色的比例 | 扫描 percent（步骤 6） |
| 写 `obj.pos = ...` 不生效也不报错 | 控制器是"冻结位置"/"零位置 XYZ" | 一律 `move` / `rotate`，改完立刻回读自检 |
| 读到旧值 | Biped 惰性求值 | `redrawViews()` 后**二次读值** |
| 遍历控制器只找到一小部分引用 | `ctrl[j]` 得到的是 `SubAnim` 包装，遇列表控制器就断 | 用 `getSubAnim ctrl j`，再取 `.controller` |
| 误判"赋值方向是反的" | 移动脚本中途报错没复位，残留偏移被当成语义问题 | 移动脚本用 `try/catch` 且**在 catch 里也复位**；或先 Hold/Fetch |
| Biped 骨取 `.center` 得到的是骨中部 | Biped 骨的 `.center` 不是 pivot | Biped 骨用 `.transform.pos`（且它没有 `.pos`） |
| 三角函数结果不对 | MAXScript 的 `sin/cos/acos` 是**角度制** | 按度用 |
| 复制完结构后骨大面积偏位（44/52 >0.2） | 缺"静止偏移对齐"这一步 | 见步骤 5.5（手柄迭代 + percent 收尾） |
| **手/前臂蒙皮扭转** | twist 骨被改成只跟 `BIPDRV`（不跟环） | 按源结构复制 twist：位置→臂中点环、旋转→`Euler`+`LookAt → 腕环` |
| 动控制器时 Biped 不动 | **源 rig 设计**（环不反驱 Biped；源窗口实测同为 0.0） | 不是缺陷；要"环反驱 Biped"须另加约束层 |
| 写链关节 `.rotation`/`move` 后段长变了 | IK 会重解并回写 | 只写 `p1`（冻结位置），按"方向 × 长度"构造；末端关节交给环 |
| 复位"读回已复位"但姿势没回去 | `biped.getTransform #pos` 假阳性 | 按世界位置校验（步骤 7 第 5 条） |
| `Unable to convert: undefined to type: Point3` | 下标取列表控制器槽（`SubAnim` 包装） | `(getSubAnim c j).controller` |

## 5. API / 参数速查

| 用途 | 写法 | 备注 |
|---|---|---|
| 读链段长基值 | `(getSubAnim <Point>.pos.controller 1).controller.value` | 冻结位置；`[2]` 是"零位置 XYZ"（其 X 上常挂伸缩线）。⚠ 下标写法 `.pos.controller[1].value` 拿到的是 `SubAnim` 包装，参与向量运算会报错 |
| 改链段长 | 见步骤 3：只写 `p1`，按「方向 × 目标骨长」构造（`c1.value = (dir*L1) - cz.value`），或用父级局部不动点迭代收敛 | 旧写法"只改 `.x`"只对腿成立；臂的长度在 `p2.y` |
| 整棵复制控制器 | `dst.rotation.controller = copy src.rotation.controller` | 实测含 `rotation_list` 各槽、约束、目标、权重、`pickUpNode` |
| 追加/删除约束目标 | `c.appendTarget <node> <w>` / `c.deleteTarget i`（倒序） | 追加捕获的是**单位偏移**，不保留当前朝向 |
| 约束权重 | `(getSubAnim c j).value` | 可直接写（用于临时置 0 做诊断） |
| `LookAt` 上方向 | `c.pickUpNode`（可写）、`c.target_axis`、`c.upnode_axis` | 必须指目标自己的骨 |
| 样条参数 | `Path_Constraint.percent` | 0–100，脊柱辅助点用它定位 |
| 列表控制器 | `getSubAnim c j` → `.controller` | 遍历别用 `c[j]` |
| Biped 设/读变换 | `biped.setTransform <骨> #pos\|#rotation\|#scale <值> false`；`biped.getTransform` | 骨节点没有 `.pos`；读值受惰性求值影响 |
| 视觉复核 | `agent_viewport action=open` → `set_viewport source=agent frame_names=…` → `capture_viewport source=agent` | 不动用户的视口 |
