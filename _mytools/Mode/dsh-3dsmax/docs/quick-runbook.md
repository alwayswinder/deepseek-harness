# 参考 rig → 新角色操作清单（路线 1）

本文规定 Seven 兼容身体骨配置的执行顺序。源 A 是本轮参考 rig（只读取证、不覆盖文件），目标 B 是本轮新角色的工作副本。先填写[新角色适配记录](character-adaptation-guide.md)，确认拓扑、骨轴分支与 Skin 状态，再从阶段 0 开始。Stan/Chiya 是验证案例，不是固定输入；不得用历史完成副本充当本轮结构或静止数值真值。

算法见 [Biped 重建指南](biped-rebuild-guide.md)与[控制器迁移指南](controller-migration-guide.md)。每阶段另存里程碑，失败停止依赖步骤；`Hold/Fetch` 会连合并一起回退。本文位置阈值以 cm 表达，按系统单位换算；试动量按适配记录确定，历史 +25/+10/+5 不是通用位移。

## 0. 开工准备

静态模型没有骨架时，先按[身体骨架搭建指南](static-body-skeleton-guide.zh.md)准备 55 节点测试输入。无 Skin 的结果可以测试骨架拟合与控制器跟随，不能视为本清单的蒙皮或变形验收通过。

| 项 | 做法与判据 |
|---|---|
| 两窗口 | 按完整文件路径确认本轮源 A 与目标 B；记录实例标识，避免写错窗口 |
| 目标干净 | 建 Biped 前：当前配置的 55 身体骨 + 网格、无旧 Biped/IK；按名称和父子表核对，位置/旋转为自由 `Position_XYZ` / `Euler_XYZ` |
| 蒙皮名单 | 逐网格读取 Skin 名单并取并集，与本角色绑定设计核对；无 Skin 记录为不适用；54 仅为 Stan 案例 |
| 静止真值 | 保存 55 骨名字与世界变换到外部文件 `work/gRest_<角色>.txt`，并另存 preBiped 快照；会话全局变量不能代替落盘数据 |
| 适配分类 | 骨轴相容走直接迁移；需要旋转转换时按阶段 2 停止条件执行；不同拓扑先完成映射与配置适配 |
| 显示态 | 见 [README 窗口与显示态](README.zh.md#窗口与显示态每轮开工前先切好)，放通控制器层的父层 |

建成 Biped 后 Nub 也属于 Dummy，必须按开工保存的骨名表识别 55 骨。

## 1. 建 Biped

按重建指南 §2 步骤 2–3，先查找图层、缺失时创建，再逐骨 `addNode`。`createNew` 的三个参数不决定最终结构，结构属性要逐项赋值并读回。

门槛（当前配置，根名按本轮记录）：Biped 清单 71 对象；spine 3 / neck 1 / leg 3 / fingers 5×3 / toes 1×1 / forearmTwist 2；在 Figure Mode 内装载本轮从源导出的 figure，在体型调整前逐项比较同名骨 `#scale` 并记录浮点差；不能要求后续体型拟合仍保持源 scale。

## 2. 拟合

按重建指南 §2 步骤 4，在 Figure Mode 内以落盘静止真值拟合：整体定位、骨盆不动点修正，再做长度 → 朝向 → 位置迭代。不能用已被控制器拉偏的 UE 骨当前值作为目标。

每次写入或缩放后 `completeRedraw()`；判定前退出 Figure Mode，强制求值并在同一次调用内连续读两次。锁骨用几何方向交叉验证，不以其完整世界旋转替代可实现的两个自由度。

门槛：位置 ≤0.05、朝向 ≤0.1°、四条肢长与目标静止骨长一致。

先单独拟合髋宽，再检查整链骨轴。出现上下段反复互相拉偏时停止逐骨迭代。转换分支按重建指南建立整链目标和冻结旋转偏移，验证 52 个 BIPMAP 参考点后停在此处：当前尚无完成验证的最终控制器输出接入，不能继续阶段 3–10 的同轴迁移流程，也不能把转换后的朝向合格记为原始骨轴直接相等。

## 3. 建测量驱动层

仅同轴分支：按重建指南 §2 步骤 5 建 `BIPDRV_*` ×55。普通驱动点不挂 Biped 父子，用位置/方向约束跟随；`BIPDRV_Root` 先摆静止，再以 `relative=true` 跟随 `bip001`，UE Root 独立约束到它。两根 twist 测量点挂在普通前臂驱动点下。

门槛：普通对应骨的驱动误差 ≤0.05 / ≤0.1°，姿态变化后不增长；Root 按保留的静止偏移验收；建立时 55 UE 骨位移为 0（容差 ≤1e-3）。

## 4. 合并并隔离名字

按控制器指南 §2 步骤 1–2：目标临时前缀覆盖本轮碰撞清单（身体骨、Biped、已有辅助点等）；合并后先给源同名节点加 `SV_`，再还原目标名。

门槛：源/目标 Biped 数量分别与清单一致，临时前缀残留为 0、无重名、所有映射节点都能唯一解析。当前配置每侧 Biped 为 71；临时改名集、SV 集与合并总数从本轮清单计算，不固定为 126 或 1003。

## 5. 复制控制器并完成引用重指

**本步必须在链几何拟合之前。** 按控制器指南 §2 步骤 5、6，复制 54 骨的位置和旋转两棵树（含两根 twist）；Root 保留独立驱动约束。52 根普通对应骨是常规位置/朝向验收集。

重指约束目标、`LookAt.pickUpNode`、ExposeTm 节点及控制根 `BIPRoot → Root`，核对 wire/script 绑定。twist 保留源的臂中点环位置约束和 `Euler + LookAt → 腕环`，不能换成裸 `Orientation → BIPDRV`。

替换 Link Constraint 前先量源节点相对原 Link 目标骨的局部关系。源六个 Expose 与对应骨重合时用 `relative=false` 吸附，极向点恢复源父局部矩阵；其他节点的合法偏移按实测保留，不能统一套用 true/false。具体规则见控制器指南步骤 6。

从所有保留节点用 **`refs.dependsOn` 正向检查**，先 `isValidNode` 再读 `.name`；范围含 UE 骨、驱动点、目标 Biped、环、IK 与辅助/Expose 节点。再检查各控制器显式字段与绑定。`refs.dependents <保留节点>` 中出现源骨，表示源骨依赖该节点，不能据此断言保留节点引用源骨。

门槛：约束与绑定不再指向源骨架；不得只凭一次浅层扫描宣称所有引用已清净。

## 6. 先摆全部环，再拟合链静止几何

按控制器指南 §2 步骤 3，以对应 BIPDRV 坐标统一摆环和拟合链关节点，目标骨长从落盘原始静止计算。起环与腕/踝末端环先落位；膝/肘环保留源到链关节的局部关系，不能混用原始静止点与拟合后的 BIPDRV 点，再靠环偏移掩盖差异。

链有效局部向量为 `p1+p2`。静止拟合只写第一槽，扣除第二槽当前值；先确认各链求解器与局部长度轴，再选控制器指南步骤 3 的方法。任意局部方向加中点迭代不保证 IKLimb 末端正确；Seven → Stan 的正 X 轴适配也须逐链验证，不能硬套其他 rig。末端位置交给求解器，不要对链关节 `move` 或写 `.rotation`。

门槛：相对对应 BIPDRV 点的起/末端误差 <2e-3、中关节误差 <0.02、两段长度与落盘静止骨长一致。**第二槽伸缩输出不是常量**，必须按控制器指南步骤 6 验证弯曲和越界行为。

## 7. 静止偏移对齐与收尾

按控制器指南 §2 步骤 5.5 迭代手柄偏移。按本轮语义表跳过起环、末端环和脊柱 Path 点；指南内的 Circle/Point 编号仅是 Seven 对照示例。膝/肘环须保留源到链关节的局部关系，并经姿势复测确认无补偿误差才可调整；普通辅助点下的肩环、脚掌环优先保留源局部关系，调整普通父辅助点位置。共享手指环振荡时采用逐步验证，只接受改善结果的移动。

对齐后按已确认轴向和落盘静止骨长再次校准链段，最后扫描脊柱 `percent`。扫描值按当前场景实测，不能硬填案例的 49.97/99.9968。扫描分批调用，避免 MCP 超时。

门槛：52 普通对应骨位置 ≤0.1、朝向 ≤1°。

## 8. 弯姿势、极向点与直接复位

按控制器指南 §2 步骤 4、7，按本轮预先记录的位移分别弯曲双脚、双手，并测试根平移和转向（历史示例为手脚 +25Z、根 +10Z、转向 15°）。在弯姿势校准极向点平面，同时复查静止；不能为了弯姿势牺牲静止门槛。

每次试动前保存所有受影响节点的世界变换；试动后直接复位，`completeRedraw()` 后比较全体受影响 Biped、驱动点与 UE 骨，不能只看被移动的末端或一条 API 读数。

门槛：姿势位置 ≤0.1、朝向 ≤1°，误差不随姿势增长；直接复位位置残差 ≤1e-4。失败应记录并重载里程碑隔离下一组；**重载恢复不算直接复位通过**。

## 9. 行为与越界验收

- 双腕、双踝、双肩环分别按记录位移试动：对应 UE 骨等量同向移动；Biped 是否移动按源行为判定，随后校验复位。
- Biped 根按记录量平移和转向：pelvis、head、双手、双脚保持预期跟随关系；测实际变化并校验复位。
- 四肢分别将末端环拉至各自两段总长加记录的超出量，与原始源 rig 在可比相对伸展程度同测：记录两段增量、链末端到环的误差及复位。表达式文本正确或段长正确都不能单独证明末端行为一致。

## 10. 显示与保存重开

按重建指南步骤 6、控制器指南步骤 8 设置显示，`boxMode` 按源同职责节点清单对齐，不固定盒显示数量。保存前记录按名字索引的节点位置/旋转，另存后重开，重新解析所有节点与控制器，再逐节点比较同一批变换。

门槛：保存重开数值一致，并仍满足静止门槛。仅“重开后仍低于 0.1 / 1°”不能替代保存前后的一致性检查。源遗留层先隐藏，删除需另行确认保留节点的引用与行为。

## 验证状态与恢复

已有案例的通过范围和失败数值集中在[新角色适配指南](character-adaptation-guide.md#6-已有证据与边界)。Stan 两轮严格整体验收均未通过；Chiya 骨架搭建和映射参考层已分项验证，完整控制器迁移未覆盖。不得将部分改善、无 Skin 的骨架测试或文件名中的 final 计为完整通过。大衣翻面仍需单独检查蒙皮与穿模。

恢复时重载本轮里程碑，丢弃缓存的节点/控制器包装器，按名字重取；MAXScript 原生访问异常的原因尚未确认。全局变量不承担持久化。标识符不区分大小写；MCP 输出需拼成字符串返回，不能依赖 `print`。Figure Mode 跨调用持续，必须显式设置与恢复。

里程碑顺序：preBiped → biped → fitted → driver → merged → ctrl_copied → chains → aligned → acceptance_base → validated_base → final。文件名不代表验收通过；每阶段以检查结果为准。
