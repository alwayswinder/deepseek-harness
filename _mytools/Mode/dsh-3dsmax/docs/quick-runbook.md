## 1. 建 Biped（10 分钟）

- 做法：重建指南 §2 步骤 2–3（**按指南内联的做法**：不需要 `setCurrent()`；`createNew` 的 3 个参数不决定结构，真正生效的是紧随的 8 个结构属性；建完逐骨 `layer.addNode` 移层）。
- 门槛：`bip001*` **71** 个；结构读回 `3/1/3/5×3/1×1/foreTwist2`；装参考 figure 后 6 根抽样骨 `#scale` 与源**逐位一致**。
- 本次实测：71 对象；`Pelvis=[25.5303,31.977,16.4298]`、`L UpperArm=[18.3378,37.7742,48.775]`。

## 2. 拟合（20 分钟）

- 做法：重建指南 §2 步骤 4（3 轮不动点：长度 → 朝向 → 位置）。**目标值一律取第 0 步落盘的真值**，不要在骨被约束后再拟合（自反馈）。
- 门槛：位置 ≤0.05、朝向 ≤0.1°、四条肢长与 B 一致。
- 本次实测：**0.0399 / 0.056°**（`foot_l` / `thumb_02_l`；方向指标 ≤`0.028°`）、四条肢长精确。
- ⚠ **读数协议（不做这一步会误判成"拟合失败"）**：写入循环内每次写完用 **`completeRedraw()`**（`redrawViews()` 在同一调用内不足，会让不动点假收敛）；**判定前**先 `figureMode = false` + `completeRedraw()`，在**同一次调用内**读值并连读两次。实测同一场景：调用内读 = 假阳性 `0.0398`、新调用不刷新 = 假阴性 `6.96 / 10.68°`、强制求值 = 真值 `0.0399 / 0.056°`。
- ⚠ 锁骨只有 **2 个自由度**（朝向），判定用**方向**而非完整世界旋转；`quat as string` 打印顺序是 `(x y z w)`，别用打印文本算分量。

## 3. 驱动层 `BIPDRV_*` ×55（10 分钟）

- 做法：重建指南 §2 步骤 5。**`Root` 用 `relative=true` 约束跟随 `bip001`（不要挂父子，会带 0.762° 偏置）**；两个 twist 驱动点挂到 `BIPDRV_lowerarm_*` 下。
- 门槛：驱动点 vs 骨 ≤0.05/≤0.1°，**刚性**（抬脚/抬手/根动后误差不增长），**且建完后 55 根 UE 骨位移 = 0**。
- 本次实测：静止 8.5e-06、复位 ≤5.4e-05、位移 **0.0**。

## 4. 合并（10 分钟）

- 做法：控制器指南 §2 步骤 1–2（**命名三步配方已内联在该节**），**前缀必须 126 个**（55 Dummy + 71 Biped）。
- 门槛：`bip001*`=71、`SV_bip001*`=71、`SV_`=126、临时前缀残留 0、无同名冲突。
- 本次实测：**1003 对象** ✓。

## 5. 链静止几何（30 分钟，本次最花时间的一步）

- 做法：控制器指南 §2 步骤 3（**已重写**）。要点：
  1. 有效局部向量 = `p1 + p2`；**腿的长度在 `p1.x`、臂的在 `p2.y`**，只写 `p1`。
  2. 中点关节写"方向 × 目标骨长"或做**父级局部不动点迭代**；**末端关节不要写**（求解器接管，写了会发散）。
  3. **环落在链关节上**（源语义）；只有腕/踝环额外落到 B 的骨关节。
- 门槛：`|中点关节 − B 中段骨| < 0.02`；段长 = B 骨长。
- 本次实测：腿 0.009、臂 0.005~0.024；段长 `35.3003/45.3889`、`19.7845/20.6696` 精确。
- **极向点（指南步骤 4）放到这一步之后做**：链对齐、环落位后弯姿势本来就跟得住（实测抬脚 +25Z 时腿 `|UE calf − Biped calf| = 0.0003`）；**静止**时移动极向点 ±40 只让链中关节动 `0.118`（平面退化）⇒ 不要指望用极向点修静止误差。
- ⚠ 别做的事：`move`/写 `.rotation` 链关节（IK 重解会改坏段长，实测 35.3003→37.9）；把膝/肘环挪到骨上（`calf` 朝向翻 179.4°）。

## 6. 复制结构 + 引用重指（20 分钟）

- 做法：控制器指南 §2 步骤 5（**位置 + 旋转两棵树都要复制**）+ 三处重指。
- 门槛：52 根骨拿到 `position_list`+`rotation_list`；约束目标/pickUpNode 指向 `SV_` 的条数 **0**。
- 本次实测：目标 61、`pickUpNode` 10、失败 0；`Link_Constraint` 12 个改位置+方向（Link 无写接口）。
- ⚠ twist 骨（`lowerarm_twist_01_l/r`）**按源结构原样复制**（位置→臂中点环、旋转→`Euler`+`LookAt → 腕环`）——**现场反馈确认过**：按旧指南改成裸 `Orientation → BIPDRV_*` 会出现手/前臂蒙皮扭转。

## 7. 静止偏移对齐（20 分钟，旧版指南缺这步）

- 做法：控制器指南 §2 步骤 5.5。手柄迭代（阻尼 0.6）+ **最后**做脊柱 `percent` 扫描。
- 门槛：52 根骨 **位置 ≤0.1、朝向 ≤1°**。
- 本次实测：**0.052 / 1.013°**（`Point001`=49.97、`Point002`=99.9968）。
- ⚠ 三个陷阱：跳过 IK 环与 `Path_Constraint` 目标；手指环会振荡（改贪心或跳过）；percent 必须最后（先做会被迭代带偏 1.41）。
- ⚠ MCP 超时：手柄迭代 + 400 次评估的 percent 扫描会超时 ⇒ 扫描窗口收窄到 ±5、步长 0.1；分段调用。

## 8. 差分验收（15 分钟）

- 做法：控制器指南 §2 步骤 7；**复位按世界位置校验**（`biped.getTransform #pos` 是假阳性）。
- 门槛：位置 ≤0.1、朝向 ≤1°，且**误差不随姿势增长**；复位 ≤1e-4。
- 本次实测：静止 0.052 / 1.013°；右脚+25Z 0.127 / 0.935°；右手+25Z 0.052；左手+25Z 0.070；根+10Z 0.052。

## 9. 行为验收（5 分钟）

- 门槛：动末端环 +5 ⇒ 目标骨 **5.000**、复位 0；动 Biped 根 +10 ⇒ `pelvis`/`head`/`foot` **10.000**；动环时 **Biped 不动**（源设计，别当 bug）。
- 本次实测：全部通过；twist 骨随环 3.96 单位 / 28.7°（源 5.45 / 20.07）。

## 10. 显示与交付（10 分钟）

- 做法：重建指南 §2 步骤 6 + 控制器指南 §2 步骤 8。
- 门槛：`boxMode` **56/71**；只显示「网格 + 控制器（+ Biped）」；**另存 → 重开 → 复测数值一致**。
- 本次实测：56/71 ✓；重开 0.0518 / 1.013° 与保存前一致。

### C.1 顺序：两处「照上面走会失败」

| # | 上面的写法 | 实测修正 |
|---|---|---|
| 1 | §5「链静止几何」排在 §6「引用重指」**之前** | **必须反过来**。链起点关节被约束到起环，起环跟着 Biped 骨；重指前它们还跟着 Seven 的 Biped ⇒ 重指前臂链 `startErr=5.09`，**重指后 `9.5e-07`** |
| 2 | 没写环与链的先后 | **先摆全部环，再解链**。先解链后摆末端环会给链关节重解 ⇒ 臂链 `midErr` 从 `0.0015` 弹到 **`6.39`** |

### C.2 规则：「跳过肢体 IK 环」一刀切是错的

3. §7 的陷阱写"跳过 IK 环"，**过宽**。实测膝/肘环是**链中关节的子级**（`Circle014→Point026`、`Circle020→Point032`、`Circle017→Point045`），挪它只改 UE 骨、不动链 ⇒ **应当照常对齐**；只有**起环与末端环**必须跳过（末端环驱动链的终点，把它算进对齐会让左腿中关节漂 `0.45`）。
   - 实益：把 `calf_l` 的 `0.469` 收进门槛（最终静止 **0.0398 / 0.996°**，0/52 超标）。
   - 正确跳过清单：`Circle009/011/015/018`（起）+ `Circle010/012/016/019`（末端）+ `Point001/002`（`Path_Constraint`）。

### C.3 真值：一切目标取**驱动点/落盘静止**，绝不取骨当前值

4. **同样的自反馈坑两次**：① 把环摆到骨的**当前位置**（骨已被复制来的控制器拉偏）⇒ `upperarm_l` 锁死 `4.95`；改用 `BIPDRV_*` 后 → **`0.0492`**。② 链长按 **UE 骨当前间距**归一化 ⇒ 弯姿势下取到 `35.2634`（真值 `35.3003`）；改用 `BIPDRV_*` 间距后四条链恢复 `35.3003/45.3889`、`19.7845/20.6696`。

### C.4 机制：**弯曲姿势本身就会写短链段长**

5. 上面陷阱表只写了"写 `.rotation` 会改坏段长"。实测**不写 rotation、只是把肢体弯起来**，段长也会被求解器回写：`35.3003→35.2618`、`45.3889→45.3504`（**各短 `0.0385`**）。修法：按**驱动点**的骨长重归一化 `p1`，并且**要放在对齐之后**（对齐会再次扰动链）。

### C.5 上面没写的三个必要动作

6. **整体定位要补「骨盆不动点」**：§2 只有一句"根骨放到 B 两侧大腿中点"，实测这样放**骨盆差 `1.98`**（Biped 骨盆轴心不在根上）。对 `rootNode #pos` 以骨盆为目标做不动点（2 步收敛）⇒ **`0.0`**。（第一轮的 `_fitted` 里骨盆是 `1.18e-05`，说明当时做了但没写下来。）
7. **读值协议**：写入循环内**每次写完调 `completeRedraw()`**；`redrawViews()` 在同一调用内**不足**（不动点会假收敛）。控制台判定前先 `figureMode = false` + `completeRedraw()`，**在同一次调用内**读值。实测同一场景三种读法：调用内 = 假阳性 `0.0398`、新调用不刷新 = 假阴性 `6.96 / 10.68°`、强制求值 = 真值 `0.0399 / 0.056°`。不用它时唯一可靠纪律：**一个阶段一次 MCP 调用**。
8. **滚转（roll）没别的杠杆**：`rotation_list[1]` 的 `Euler_XYZ` 基值被 `LookAt` **完全覆盖**（±20° 三轴扫描**零效果**）；`LookAt.pickUpNode` 与骨重合时退化（膝环与 `calf` 相距 `3.8e-06`），其影响幅度只有 **±1.5°**。⇒ 滚转只能靠极向点/链平面。

### C.6 极向点：是"弯姿势**对齐**"，不是"弯位复核"

9. 上面 §5 末尾把极向点的作用弱化了。实测它是**修手臂 `4.83` 漂移的唯一手段**：在`抬手 +25Z` 姿势下把极向点绕"起—末端轴"转到目标中关节平面，**一次旋转把肘环误差 `4.8296 → 0.0701`**（后续再迭代反而发散，`α=1.0` 一步最佳）。
   - 应用对象：`Point159/158`（肘）、`Point039/038`（膝）。
10. **腿的极向点在「静止 ↔ 屈腿」是取舍，不是误差**：静止时膝几乎落在髋—踝轴上（平面退化）。以「两状态最差误差」搜索实测：单取屈腿最优 ⇒ `bent 0.055 / rest 0.012`，但 `calf_r` 静止滚转变 `1.99°`、左腿静止中关节漂 `0.415`；单取静止最优（**本次交付态**）⇒ 两态静止门槛全过、屈腿留 **`0.516` / `2.793°`**。**手臂没有这个取舍**（静止不退化），所以手臂从 `4.83` 压到 `0.235` 是真收益。

### C.7 计数与扫描口径（会让判据失效）

11. **`classof o == Dummy` 在建成 Biped 后不再是「55 根 UE 骨」的判据**：13 个 `*Nub` 也是 `Dummy` ⇒ 数到 **68**。§0 的自检清单在"已建 Biped"的场景里失效，改用名字表筛。
12. **`refs.dependents` 反向扫（步骤 6 末条）有两个坑**：① 会撞上**非 Node 依赖**（`ParamBlock2`、`rotation_list`、各 `*_Constraint`）直接报 `Unknown property: "name"` ⇒ 必须加类判据；② 全场景扫会淹没在**源 Seven 自己**的 `Skin`/控制器里（实测 803 条里绝大多数是它自己的）⇒ 有效口径是**只扫我们这层**（55 UE 骨 + 55 `BIPDRV_`，实测 `SV_` 引用 = **0**）。

### C.8 MCP / MAXScript 工具坑（会浪费整轮）

| 症状 | 原因 / 修法 |
|---|---|
| `Unable to convert: [Point3] to type: <node>` | **MAXScript 标识符大小写不敏感**：用 `H` 存 Point3 会覆盖手骨变量 `h`，报错指不到真正原因 ⇒ 变量名全局唯一，不靠大小写区分 |
| `Syntax error: at +, expected <factor>` | 字符串不得用行首 `+` 续行；`(x) as string` 的优先级低于 `+`，会吞掉整串 ⇒ 拆成多条 `s += ...` |
| 脚本跑了但看不到输出 | `print` 在 MCP 桥下**不回传** ⇒ 把结果**拼成一个字符串返回** |
| 场景被留在半途状态 | 试动脚本必须"记录原值 → 测 → 复位 → **校验复位残差**"；写错目标值（如把 `[0,0,0]` 当原位）会把场景搞脏，只能从里程碑重载 |
| `figureMode` 的行为 | 实测**跨 MCP 调用持久**（一次调用里置 `true`，下一次不设置读到的仍是 `true`）——不要按"会自己变回 false"来设计 |
