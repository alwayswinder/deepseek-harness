# 从静态网格搭建 55 节点身体骨架

[English](static-body-skeleton-guide.md) | 中文

本流程把未绑定的人形角色准备成骨架拟合和控制器迁移实验的输入。它按实测关节位置与世界坐标轴创建 55 个兼容 Seven 的 **Dummy 节点**。不添加 Skin、Biped、IK、面部骨或动画控制器；移动骨架不会使静态网格变形。

创建节点、命名、建立父子关系和保存矩阵可以重复执行。关节中心、肢体滚转方向和静止姿态需要人工解剖检查。附带的 [Chiya 参数文件](../tools/body55/profiles/chiya.json)记录了一个实测模型；其他角色需要独立参数，不能按身高缩放后直接照搬坐标。

## 文件与前提

| 文件 | 职责 |
|---|---|
| [generate.py](../tools/body55/generate.py) | 验证实测参数并生成可执行 MAXScript；仅依赖 Python 标准库 |
| [build.ms](../tools/body55/build.ms) | 搭建模板；先生成脚本再运行 |
| [chiya.json](../tools/body55/profiles/chiya.json) | Chiya 关节位置、坐标轴、层级及静态网格检查值 |

搭建器要求系统单位为 **1 厘米**，场景只含声明的静态网格，网格无修改器或动画，也不存在骨架节点。先把该输入保存为 `.max` 文件。执行前记录目标 Max 实例与源文件路径。输出使用已有目录中的新路径；生成器与搭建器都会拒绝已有输出文件。原生执行已在 3ds Max 2026.3 检查，其他版本尚未验证。

## 1. 测量新角色

从已保存的中立姿态开始。检查正、侧、顶视图，记录骨盆、脊柱、颈、肩、肘、腕、髋、膝、踝、脚趾及每节手指的世界关节中心。身体关节应贴合衣物下的身体，而非衣服或头发包围盒。三角面与平面的截面可辅助估计肢体中心；重叠衣物、指甲和分离网格组件需要人工判读。组件编号只适用于当前模型。

采样顶点前先确认坐标空间：Chiya 测量时，`snapshotAsMesh` 返回世界坐标。再次乘节点变换会使测量位置偏移。使用采样结果前，先与可见的世界空间标志点核对。

保留 `generate.py` 中 `skeleton_parents()` 定义的标准层级：中轴 7 个节点，每侧 24 个节点（肢体及 twist 9 个、手指 15 个），共 55 个。`lowerarm_twist_01_l/r` 挂在对应前臂下，手掌是前臂的另一个子节点。参数验证会拒绝缺失名称、重名与不同父节点。

上臂、前臂、大腿和小腿均设置局部 **+X 指向下一关节**。可重复的坐标架算法为 `X = normalize(child - joint)`，把选定的滚转参考向量投影到垂直 X 的平面得到 Y，再令 `Z = cross(X, Y)`。投影接近零时更换参考向量。所有坐标架保持正交、单位长度和右手系；镜像关节位置后重新建立坐标架，不能引入负缩放。手指、躯干、手掌和脚的坐标架需要对照 Seven 约定逐项检查。特别是 Seven 的脚轴不要求 +X 指向脚掌球关节。

完全伸直的肢体不能确定后续 IK 弯曲平面。记录肘、膝预期弯曲方向，供后续 Biped 拟合使用。Blender 骨架即使命名和层级一致，若骨长沿 +Y，也需要为本 +X 流程重建坐标轴。

## 2. 记录参数

复制 `chiya.json` 为新角色参数文件，然后替换**所有实测变换和网格记录**。位置是厘米制世界坐标；`axes` 是 Max `matrix3` 使用的三个世界空间行向量。这些值不再乘父节点变换。

| 字段 | 必需值 |
|---|---|
| `format`、`layer` | `body55-v1` 与非空的输出图层名 |
| `meshes[]` | 全部输入网格：`name`、正整数 `vertices`/`faces`、世界 `position` 与 `axes` |
| `nodes[]` | 恰好 55 条记录：标准 `name`、`parent`（Root 为 `null`）、世界 `position` 与 `axes` |

生成器拒绝非有限坐标、带缩放/错切/反射的坐标架，以及八段主要肢体轴偏离骨段方向超过 0.1° 的参数。网格数量、拓扑计数和变换用于防止选错场景，不能检测保持这些计数不变的顶点编辑。保留被测源文件版本，并目视检查结果。

## 3. 生成与预检

在本预设目录中，Chiya 示例为：

```powershell
python tools/body55/generate.py --profile tools/body55/profiles/chiya.json --source-scene E:/AI/3dMax/Save/chistatic.max --scene-copy D:/AI/work/body55-tool-validation/chiya-body55.max --script D:/AI/work/body55-tool-validation/build-chiya.ms
```

先建立输出目录，后续运行使用新路径。该命令只写脚本，不控制 Max。在目标 Max 实例打开实测静态输入，通过 MAXScript 运行生成的脚本。加载只执行预检并返回 `PREFLIGHT_OK=55; no scene or file changes`。在对应的已完成输出场景加载同一脚本时，则执行只读验证。

## 4. 搭建与验收

预检通过后，显式执行：

```maxscript
DSHBody55Run action:#build
DSHBody55Run action:#verify
DSHBody55Run action:#pose
DSHBody55Run action:#rest
```

`#build` 先保存干净工作副本，再创建节点、赋实测世界矩阵、建立父子关系、重新赋矩阵、验证、测试 Root +10Z 与直接复位，最后保存完成副本。中轴/左/右节点以黄/青/红色放入参数指定图层。重复搭建会被拒绝。`#verify`、`#rest` 只读；`#pose` 临时移动 Root 后复位，不保存文件。

验收要求 55 个唯一 Dummy 名称及规定父节点、自由 `Position_XYZ` / `Euler_XYZ`、无动画、单位缩放，世界矩阵行向量最大距离 ≤1e-4。Root +10Z 必须带动全部 55 节点等量移动，且直接复位后全部矩阵误差 ≤1e-4。默认缩放控制器可以是 `bezier_scale`，不要求 `ScaleXYZ` 类。

三视图检查关节与轴，包含手指位于手内、肘膝深度、肩髋中心及脚方向。数值与参数一致只能证明搭建符合参数，不能证明解剖位置合适。若验收要求网格不变，需与输入比较几何及材质数据；构造器仅检查拓扑计数并不足够。

通过宿主/文件工具把 `#rest` 返回字符串保存为外部 UTF-8 文本。每行是名称及 12 个按行排列的世界矩阵数字。添加约束前保留该原始静止表；会话全局变量不会跨重启保留。遵守 Safe Scene Script Execution，Max 阻止写文件时使用外部文件工具。

保存返回的静止字符串，重开完成副本，再运行 `#rest`，按名字与已存表比较全部数值。Chiya 批处理检查除验证、Root 移动/复位和重复搭建拒绝外，还确认了重开前后完整返回字符串一致。

## 恢复与下一阶段

预检失败时，先修正场景、参数或路径再搭建。构建失败则停止后续操作，不保存部分完成场景。尝试最终保存前，输出文件是干净检查点；最终保存失败时，输出必须视为未验证。重开原始静态输入，检查或保留失败输出，用新路径重新生成脚本。搭建器不会主动保存覆盖源输入。

生成场景可以测试骨架命名、层级、Biped 拟合和控制器跟随。先填写[新角色适配记录](character-adaptation-guide.md)，检查髋宽、整链骨轴和可继续的分支，再参考 [Biped 重建指南](biped-rebuild-guide.md)与[操作清单](quick-runbook.md)，并记录尚无 Skin。蒙皮名单、变形、绑定姿态质量、烘焙及引擎导出仍需分别验收；body55 搭建通过不代表迁移全流程通过。
