# 身体控制器迁移：Seven → Quinn / Stan

迁移的验收对象是动作结果，不能只看控制器形状、静止关节坐标或节点数量。先在源场景实际移动手脚、肘膝环和极向点，再选实现方式。**Quinn 与 Stan 都使用 Seven 原生隐藏驱动链**（Stan 已按本流程实测通过：4/4 肢体 + 8/8 驱动验收 PASS）。适配控制链那条路线降为历史参考，其事故教训仍值得一读；两套实现的脚本、节点映射及关节环关系不能混用。

## 通用 A→B 流程（先读这一节）

本技能适用于**任意** "源 rig A → 目标角色 B"。下列步骤与工具与具体角色无关；
算法、实测数字与完整坑表见 [通用配方](references/recipe.md)，可直接执行的脚本见 `scripts/`。

| 阶段 | 做什么 | 工具 |
|---|---|---|
| 0 | 判定两个窗口哪个是 A、哪个是 B（**按场景内容，不按文件名**） | `list_max_instances` + `scripts/01_discover_rig.ms` |
| 1 | 检查点：文件备份 + `hold` + 先定好里程碑新文件名 | `manage_scene` |
| 2 | 选实现路线（A 的原生 Rig 作隐藏驱动层 / 在 B 里搭适配链） | [recipe.md](references/recipe.md) §1 |
| 3 | 合并 A 的 Rig；**同名骨骼用三步配方**处理重名 | `scripts/02` → `merge_from_file` → `scripts/03` |
| 4 | 逐肢把 IK 段长按 **B 的静止骨长**重算并标定极向点 | `scripts/04_calibrate_limbs.ms` |
| 5 | 建静止对齐驱动点 + 位置/方向约束 | `scripts/05_build_driver_layer.ms` |
| 6 | 图层：只留 B 的网格 + A 的控制器 | `manage_layers` |
| 7 | 数值验收 + 驱动测试 + **保存重开复测** | `scripts/06_verify.ms` |

**六个最容易翻车的点**（完整清单见 recipe.md §9）：

1. 控制器多为**冻结变换**（`冻结位置`/`零位置 XYZ`）—— 写 `.transform.pos` **不报错也不生效**，会让人误判"约束断了"。一律用 `move`/`rotate`，并在赋值后立刻回读自检。
2. 约束与 IK **惰性求值** —— 脚本内改动后必须 `redrawViews()` 再读值，否则读到上一帧缓存。
3. **设定段长 ≠ 实际段长**：`x_position` 上挂着伸缩参数线。必须按**实测解算长度**迭代拟合。
4. **极向点只修角度**；剩余误差若是径向的（中关节到轴的距离），只能改段长。
5. 移动控制器要用**控制器自身**的误差，不是末端执行器的误差（两者实测差 0.03 vs 0.81）。
6. 批量脚本必须**逐项 `try/catch` + 结尾汇总**，否则一次运行时报错会把场景留在半成品状态。

> 数值门槛（按身高折算，本例身高约 150）：末端误差 < 2e-3、中关节误差 < 0.02、
> 接约束时目标骨位移 < 1e-3、**刚性漂移** < 1e-5、复位误差 = 0。

## 确认工作场景

1. 两个 Max 窗口并存时，用 `list_max_instances` 找到实例，按实际打开的场景文件确认源和目标，再用 `select_max_instance(pid)` 绑定本次调用。PID 只在当前会话有效；每次切换窗口后重新确认文件。
2. 修改前保存新的工作副本或检查点，保留原始场景和已验证原型。记录当前帧、自动关键帧状态、目标骨骼静止世界变换与缩放。比较世界位置使用 `node.transform.pos`；源骨骼受列表/约束控制时，局部 `node.pos` 可能不是世界位置。
3. 检查源控制器、IK 链、约束、参数线、ExposeTransform、Biped 节点与辅助点的依赖关系。核对目标已有的驱动与约束；如果场景状态或节点名不符，重新盘点，不按旧记录猜测。

在源场景逐肢试动：手脚目标在可达范围内和超出两段骨长时分别移动；肘膝环、极向点分别单独移动；末端旋转；如有 IK/FK 开关则实际切换。记录每次关节位置、两段长度、弯曲方向、末端朝向和着色蒙皮，随后恢复姿势。明确哪些节点是可编辑输入、哪些是 IK 求解结果、哪些只负责显示；不要凭控制器名称或属性存在推断功能。

## Quinn：迁移 Seven 原生身体链

身体原型在 `E:/AI/3dMax/Save/Quinn_SevenNative_Body_Prototype_20261015.max`（**该路径在当前 Save 目录下已不存在，疑已改名为 `QuinnTest01.max`；引用前先确认**）。先核对目标节点是否已存在 `Q7_*` 驱动与约束；已完成的 996 节点原型不能再运行 `*_extend.ms`，也不要把原型脚本直接重放到成品上。

1. **保留原生链路。** Seven 原始 IK、约束、参数线和辅助层完整保留，驱动 Quinn 的 `Q_` 骨骼；源网格和内部 Rig 隐藏。不要再并联一套 IK 到同一 Quinn 变换轨道，以免循环或双重驱动。
2. **逐肢校准 IK。** 左右臂、左右腿分别检查 `startJoint`、`endJoint`、`VHTarget`、求解器、两段 FK 基础长度和伸缩表达式。右腿用 `IKHISolver`，其余三条用 `IKLimb`，不能假设轨道或参数线完全相同。以 Quinn 静止骨长重算每段长度；原型中的伸缩阈值是两段总长的一半，表达式保留原距离变量并以 `amax 0` 限制压缩。暂停求解器后调整基础长度、起点及末端控制器，恢复求解器，再数值标定极向点，使 Seven 中间关节贴近 Quinn 静止关节。
3. **让极向点可独立操作。** 手/脚目标移动时，极向点的父层按肩—手或髋—脚中点的 Root 空间偏移跟随；极向点本身仍能单独移动。`Point158/159` 是肘极向，`Point038/039` 是膝极向；肘环、膝环只是随 IK 求值的形状。
4. **保持静止姿势。** 给 Quinn 骨骼接约束前保存世界变换。每个静止对齐驱动点先放到 Quinn 骨骼静止世界变换，再挂到对应 Seven 骨骼并恢复世界变换，以其驱动 Quinn 世界朝向。已标定的肩/肘/手、髋/膝/脚位置匹配源关节；需要保留偏移的骨骼由静止对齐驱动点带位置。多出的前臂扭转骨用两源朝向混合，腿扭转骨随相应 Seven 大腿/小腿驱动。
5. **处理层级差异。** Seven 三段脊柱映射 Quinn 五段脊柱，中间 `Q_spine_02`、`Q_spine_04` 各混合相邻两段源骨；骨盆和锁骨分别接入。双手 30 节指骨接同名 Seven 指骨，Quinn 掌骨保持原生手部层级。脚掌骨及 `Q_ik_hand_gun`、左右手脚 IK 标记骨跟随对应末端。头部与表情不在本流程内。

具体节点、脊柱权重、脚本位置和已测误差见 [Seven→Quinn 参考记录](references/seven-quinn.md)。这些数值属于当前原型；重开不同版本时重新计算静止姿势和误差。

## Stan：原生驱动层（正式路线）

Stan 走与 Quinn 相同的路线：Seven 整条 Rig 合并进 Stan 场景作隐藏驱动层，Stan 的骨由静止对齐驱动点带动。
已完成并验收的原型：`E:/AI/3dMax/Save/Stan_SevenNative_Body_Prototype_20261015.max`（932 个对象）。

实测要点，细节与算法见 [通用配方](references/recipe.md)：

- Seven 与 Stan 的骨架**逐字同名**，这是本案例的主要障碍。合并前给 Stan 的骨加临时前缀、合并后把 Seven 的骨加 `SV_` 前缀并还原 Stan 的名字：`scripts/02` → `merge_from_file` → `scripts/03`。**Stan 的导出命名必须保住原名，所以被改名的永远是 Seven 的骨。**
- 四肢 IK 段长按 Stan 静止骨长重算：臂 `18.3378/23.2822 → 19.7845/20.6696`，腿 `36.5735/43.9204 → 35.3003/45.3889`。**必须拟合到实测解算长度**（`x_position` 上挂伸缩参数线，设定值 ≠ 实际值）。
- 极向点只修平面方向；**径向**误差只能靠改段长。近全伸展的左臂最难做小（midErr 1.4e-2），是四条肢里唯一逼近门槛的。
- 55 根骨各一个 `S7_*` 驱动点 + 位置/方向约束；驱动层与 Seven 骨架分别放在 `S7_驱动`、`SV_SevenRig` 两个隐藏图层，终态只显示 `PrinceofStan`（网格）+ `控制器`。
- 验收结果：4/4 肢体 PASS、8/8 驱动 PASS、刚性漂移 ≤ 2.4e-7、复位误差 0.0；保存并重新打开后复测一致。
- Stan 缺 `upperarm_twist_01/02`（Seven 多这 4 根），按名字匹配天然跳过；Stan 的 `Root` 对应 Seven 的 `Root` 点辅助对象。
- **未验证**：完整动画范围、极端扭转、不同身材蒙皮、IK/FK 切换。头部与表情未迁移（Stan 的脸仍由自身 `head/neck_01/spine_03` 驱动）。

### 历史参考：适配控制链路线的事故教训

以下来自另一条路线（在 Stan 里重建适配控制链；据 [seven-stan.md](references/seven-stan.md) 其产物为 `Stan01_SevenBodyRig_20261015.max` —— **该文件当前不在 `Save` 目录下**，引用前先确认）。
它**不是 Stan 的正式做法**，但其中失效机制对任何路线都成立，排错时可对照：

- 先用一条肢体做可撤销试改，分别测试末端目标、肘膝环和极向点，再扩展到其余三肢。若环应直接控制关节，不能只让它带动 pole；若环只应随 IK 中点显示，也不能擅自改成关节约束。以源场景的实际操作结果为准。
- 画出“环、pole、IK 中点、骨骼”的依赖方向。把 pole 挂在环下，再让环跟随 IK 中点，会形成循环依赖。重挂父级时保留 pole 世界变换及环可手调的局部偏移。
- 检查 IK goal 与末端控制器的实际世界位置和既存偏移。末端移动后的中间关节不能用固定膝环或简单的肩—手中点替代；超出最大可达距离时，必须按源 Rig 实测的伸展规则处理，不能只依赖被夹住的辅助 IK 链。
- 旋转脚本同时检查类型、空间、乘法次序和方向。MAXScript `angleaxis` 参与 quaternion 运算前要显式 `as quat`。关节位置正确仍可能因旋转方向相反而扭坏袖子、膝部或手部连接；必须看着色蒙皮。

适配链路线的具体节点、失效机制、越界公式和脚本线索见 [Seven → Stan 故障复盘](references/seven-stan.md)（**历史参考**，非 Stan 的正式做法；其中引用的场景与 `Tmp/*.ms` 脚本可能已不存在）。该场景四肢主骨骼的旧“IK/FK”属性目前不能切换主骨骼；未实测切换功能前，不得声称 IK/FK 可用。

## 验收与交付

- **先过数值门槛再看画面**：`scripts/06_verify.ms` 会输出逐肢的末端/中关节误差、**刚性漂移**（运动前后 `|B骨−A骨|` 是否恒定）与驱动复位误差。**刚性漂移是判断"跟对了"还是"跟错了但也在动"的关键指标**，只看"动没动"不够。
- 每个驱动测试都必须**复位并确认复位误差为 0**，这样"没弄脏场景"才是可证明的。
- Quinn 网格和 `Quinn_Global_CTRL` 在 `0` 层；Seven 可操作形状在 `控制器` 层，其父图层 `不导出` 必须可见。隐藏 `辅助`/`NUB`、`FBX`、`bip`、Seven 网格和面部层，可只显示 Quinn 与身体控制器。图层隐藏不应改变 Rig 求值。Stan 的终态显示是**只显示 `PrinceofStan`（角色网格）+ `控制器`**；Seven 骨架与驱动层分别放在 `SV_SevenRig`、`S7_驱动` 两个隐藏图层。
- 每完成一条链，记录静止位置和朝向误差。临时平移、旋转手脚目标，检查末端、肘膝、随动圆环、极向点及扭转骨；单独移动极向点时，末端应保持。再测骨盆、胸、手指、脚掌、整体控制圈和 IK 标记。所有试验恢复原变换并检查没有留下关键帧。
- 对四肢分别测试末端目标的可达与越界动作、肘膝环单独移动、pole 单独移动。核对关节与期望控制器的位置关系、两段长度、弯曲方向和末端连接；从至少两个角度看着色蒙皮。静止坐标重合或某一肢体通过，不代表其余肢体 IK 正确。
- 在着色视口查看蒙皮，而不只看骨骼数值。新文件保存后重新打开，复测代表性控制器与可见性。Max 报错或崩溃后先读取实际场景，再决定从检查点恢复；不要重复执行非幂等脚本。
- 交付时列出已验证动作、场景路径及未验证范围。Quinn 原型已做右手上移并旋转 60°、左脚抬高 12 单位和代表性控制器重开复测；完整动画范围、极端扭转和不同身材的蒙皮仍未验证。Quinn 原型未实现完整 IK/FK 切换；Stan 场景旧切换属性目前不驱动四肢主骨骼。必须实际切换验证，才能宣称功能可用。
