# A → B 身体控制器迁移 · 通用配方

本文件是**目标无关**的通用流程，适用于任意 "源 rig A → 目标角色 B" 组合。
案例专属数值见 [seven-quinn.md](seven-quinn.md) 与 [seven-stan.md](seven-stan.md) —— 两份都是**历史案例记录**，
其中引用的 `E:/AI/3dMax/Save/Quinn_SevenNative_*`、`E:/AI/3dMax/Save/Stan01_SevenBodyRig_*` 与
`E:/AI/3dMax/Tmp/*.ms` 可能已不存在；只把它们的**数值与失效机制**当参考，引用路径前先确认。

## 1. 先选实现路线

两种路线都已被验证可行，**取舍在开工前决定**，不要中途混用（两者的脚本、节点映射、关节环关系互不兼容）。

| | **路线 1：源 Rig 作原生隐藏驱动层** | **路线 2：在 B 里搭适配控制链** |
|---|---|---|
| 思路 | 把 A 的整条 Rig 合并进 B；A 的骨通过静止对齐驱动点带动 B 的骨 | 不搬 A 的 Rig，在 B 里重建环/IK/follow，环直接控制 B 的关节 |
| 已落地 | **本仓库的正式路线**：Seven→Quinn 原型；Seven→Stan 原生链原型（`Stan_SevenNative_Body_Prototype_20261015.max`，4/4 肢体 + 8/8 驱动 PASS） | 历史参考：Seven→Stan 适配链（`Stan01_SevenBodyRig_20261015.max`，见 seven-stan.md） |
| 优点 | 控制行为与源**完全等同**；IK、极向点、参数线、伸缩规则原样保留；改动集中在约束层 | 场景干净可命名；可针对 B 的身材与层级重写 |
| 代价 | 场景对象数暴涨（实测 A 侧 818 个）；必须处理骨骼重名、图层合并、A 的网格/面部层隐藏 | 需逐条重建 follow、越界伸展、旋转数学，事故率高（循环依赖、转向反、末端偏移） |
| 选它的时机 | 要求"和源一模一样"、A 是可信成品、后续还要吃 A 的更新 | B 需要长期维护、要自有命名与层级、不需要与源逐帧一致 |

> **本仓库的既定选择**：Quinn 与 Stan **都走路线 1**（源 Rig 作原生隐藏驱动层）。
> 路线 2 只作为历史参考保留 —— 它的排错记录（循环依赖、`angleaxis` 转向、越界伸展、既存 goal 偏移）
> 对任何路线都有参考价值，但**不要**把两套实现的节点映射或关节环关系混用。

> **共同点（两条路线都必须做）**：逐肢把 IK 段长按 **B 的静止骨长**重算；用**数值门槛**验收；把边界写进交付报告。

## 2. 判定哪个窗口是 A、哪个是 B

PID 会因 Max 重启而变，**永远按场景内容判定**。

```powershell
$py = '<repo>\.venv\Scripts\python.exe'; $m = '<repo>\scripts\mcpcall.py'
& $py $m list_max_instances '{}'
& $py $m --pid <pid> execute_maxscript @args_discover.json   # scripts/01_discover_rig.ms
```

| 特征 | A（源 rig） | B（目标） |
|---|---|---|
| `IK_Chain_Object` | ≥1 | 0 |
| 圆 / 样条控制器 | 几十个 | 0 |
| `ExposeTransform` | 有 | 无 |
| 骨架节点 | Dummy / Bone / Biped 混合 | 纯 Dummy 一层 |
| 蒙皮 | 角色本体（最终隐藏） | 角色本体（最终显示） |

两个都是 A 或都是 B → **停下来问用户**。

## 4. 合并与重名（路线 1）

### 4.1 永远给 A 的骨架加前缀

即使 A/B 不同名也要加（建议 `SV_`）。任何后续脚本都需要随时区分"A 的骨"与"B 的骨"。

### 4.2 同名时用三步配方，别用 `duplicate_action="rename"`

后者产出 `pelvis001` 这类不可靠映射。

```
① B 的骨架临时加前缀 S_（腾出名字）
② merge_from_file(file_path=A.max, select_merged=false, duplicate_action="rename")
③ A 的同名骨加 SV_ → 再把 B 的名字还原
```

已固化为脚本：`scripts/02_prefix_target_skeleton.ms`（**合并前**跑，带"已迁移就中止"的保护）与
`scripts/03_prefix_source_skeleton.ms`（**合并后**跑，含末尾校验）。
**B 的导出命名必须保住原名，所以改名的永远是 A 的骨。**

### 4.3 合并的副作用

- **同名图层被合并**（`NUB` 撞 `NUB` → `NUB.001`；两边骨架混进同一层）
- **A 的隐藏状态一起带入**（实测带进 636 个隐藏对象）
- **取消隐藏父层会级联**：为显示 `控制器` 打开父层，会连带放出 `bip` 与面部控制器

## 5. 逐肢 IK 校准

工具：`scripts/04_calibrate_limbs.ms`。

### 5.1 配对：链 ↔ 肢体

取 A 每条 IK 链的**起点关节世界坐标**，在 B 的骨骼里找**最近那根骨**即所属肢体。

> 实测：`Point044 @(-13.84,5.13,133.15)` → B 的 `upperarm_r @(-13.90,2.46,129.87)`，距离 3.28；
> 次近 `clavicle_r` 距离 9.8。判别清晰。

每肢需要：起点/中间/末端关节名、起点/末端控制器名、极向点名、B 的上段/中段/末端骨名。

### 5.2 误差判据：**先分径向与角度**

- **径向** = 中关节到"起点—末端轴"的垂距 → 由**段长**决定，**转极点无效**
- **角度** = 在轴周围的方向 → 由**极向点**决定

```
径向不对 → 改段长；径向对了 → 转极点。
```

> 实测教训：一开始想用极点去修全部误差，对另外三条肢迭代 12 次**误差纹丝不动**
> （0.753539 → 0.753539），因为剩余误差全是径向的。

### 5.3 段长必须拟合到**实测值**

段长存在 `IKControl` 的 FK 子控制器里，而 `x_position` 上通常挂**伸缩参数线**，会再加偏移：

```
<中/末端关节>.transform.controller[4].controller[1].controller[1].controller.value
```

流程：先设冻结基值为 B 骨长 → **再按实测解算长度迭代修正**（约 5 轮）。

> 实测：设 `35.3003/45.3889`，实测 `35.3388/45.4275`（各 +0.0386）。
> 因链静止时在 **99.9% 伸展**，这 0.077 的总偏差把膝盖径向从 2.16 顶到 **2.78**，midErr 直接 0.62。
> 拟合到实测后降到 **1.2e-4**。

### 5.4 极向点只定平面

径向正确后，把极向点沿"绕轴旋转"移到**目标中关节所在平面**（Rodrigues 旋转）。一次不够，脚本用
"拟合段长 ↔ 归位极点"**交替迭代**到收敛。

### 5.5 移动的是**控制器自身**的误差

```
✅ move <末端控制器> (B末端骨位置 - <末端控制器>.世界位置)
❌ move <末端控制器> (B末端骨位置 - <链末端关节>.世界位置)
```

> 实测：末端只差 `0.0316`，控制器却差 `0.813`。用后者去修，整条左臂永远解成"直臂"（midErr 卡在 0.78）；
> 修对之后 0.783 → 0.0140。

## 6. 静止对齐驱动层（路线 1）

工具：`scripts/05_build_driver_layer.ms`。对 B 的**每一根骨**：

1. 记下当前**静止世界变换**
2. 在该处建驱动点 `<DRV>_<骨名>`（如 `S7_pelvis`）
3. 把驱动点**挂到 A 的对应骨**，然后**恢复世界变换**（此后刚性跟随 A）
4. 给 B 的骨加**位置约束 + 方向约束**，目标为该驱动点

效果：B 的静止姿势分毫不动；运动由 A 刚性带动；**B 的骨长在运动中保持不变**。

> 数学说明：约束在创建时捕获静止偏移 `C = A骨_rest⁻¹ · B骨_rest`。
> 子骨相对父骨的变换化简为 `B父_rest⁻¹ · [绕关节的旋转] · B子_rest`，
> 即"对 B 的静止局部变换做刚体旋转" —— 长度守恒。这也是为什么"位置+方向"双约束**不会**拉伸 B。

## 7. 图层与显示

终态默认：**只显示 B 的网格 + A 的控制器**。

- 显示：`控制器`（父层 `不导出` 必须可见）、B 的角色网格层
- 隐藏：A 的网格层、A/B 骨架层、`bip`、`辅助`/`NUB`、全部面部/表情层

图层隐藏**不影响** Rig 求值与蒙皮。

## 8. 验收门槛

工具：`scripts/06_verify.ms`。

| 指标 | 含义 | 门槛 | 实测达成值 |
|---|---|---|---|
| 末端对齐误差 | 链末端 vs B 末端骨 | < 2e-3 | 4.4e-5 / 1.1e-3 / 7.9e-5 / 8.9e-4 |
| 中关节误差 | 链中点 vs B 中段骨 | < 0.02 | 5.1e-5 / 1.4e-2 / 1.2e-4 / 1.8e-3 |
| 接约束时 B 骨位移 | 证明静止姿势未被破坏 | < 1e-3 | 1.57e-5 |
| **刚性漂移** | 运动前后 `\|B骨 − A骨\|` 是否恒定 | < 1e-5 | 2.4e-7 |
| 驱动复位误差 | 试验后能否精确复位 | 0 | 0.0 |

门槛按**角色身高**折算更合理：末端 < 身高 × 1e-5、中关节 < 身高 × 1.5e-4。
本案例角色身高约 150，故取 2e-3 / 0.02。**近全伸展的肢体（本例左臂）最难做小** ——
它的中关节径向对段长极度敏感（见 §5.3），是四条肢里唯一逼近门槛的。

**刚性漂移是最关键的一项**：只看"动没动"无法区分"跟对了"和"跟错了但也在动"。

驱动测试至少覆盖：双手、双脚、脚掌、脊柱、骨盆、手指、肩/髋。
最后 `Save As` → **重新打开** → 重测（重开后句柄全变，一切按名字重新解析）。

## 9. 硬坑清单

1. **控制器多为冻结变换**（`冻结位置` / `零位置 XYZ`）。写 `c.transform.pos = ...` **不报错、不生效** ——
   会让人得出"约束断了"的错误结论。**一律 `move` / `rotate`，并在赋值后立刻回读自检。**
2. **约束与 IK 惰性求值**：脚本内改动后必须 `redrawViews()` 再读值，否则读到上一帧缓存。
3. **段长实际值 = 冻结基值 + 伸缩 wire 偏移**，永远按实测迭代。
4. **极点只修角度**，径向问题去改段长。
5. **移动控制器用控制器自身的误差**。
6. **批量修改脚本必须逐项 `try/catch` + 结尾汇总**，否则一次运行时报错会让场景停在半成品状态
   （实测发生过两次：一条肢体已改、其余未改）。
7. MAXScript 陷阱：
   - 行尾不要留二元运算符（`+` 换行 → `Syntax error: at +, expected <factor>`）
   - 不要用内置名做函数名（`refine` → `Cannot assign to read-only variable`）
   - `substring s 1 0` 返回 `""`；`getNodeByName ""` 返回 `undefined`；再取属性会**中断整段脚本**
   - Biped 对象没有 `.pos` / `.rotation`，只能用 `.transform.controller`
   - `LayerProperties` 没有 `getNodes()`；用 `layer.getNumNodes()`
   - `snapshotAsMesh` 返回的 TriMesh 没有 `.min` / `.max`
   - 列表控制器：`ctrl[i]` 得到 `SubAnim`，控制器要再取 `.controller`
8. `merge_from_file` 会合并同名图层并带入源场景隐藏状态。
9. 宿主 shell：PowerShell 的 `$pid` 是只读自动变量，函数参数别叫 `pid`。
