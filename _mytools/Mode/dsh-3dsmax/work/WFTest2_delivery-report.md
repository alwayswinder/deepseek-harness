## 4. 已知残留（用户 2026-10-16 决定接受）

| 项 | 实测 | 性质 |
|---|---|---|
| 右腿屈 25Z：`calf_r` 位置 0.516 | 门槛 0.1 | **静止↔屈腿的几何取舍**（见下） |
| 左腿屈 25Z：`calf_l` 朝向 2.793° | 门槛 1° | 同上 |
| 抬手/根动位置 0.140–0.293 | 门槛 0.1 | 与指南案例同量级（其记 抬手 0.052–0.234） |
| `calf_l` 静止滚转 0.996° | 门槛 1° | 刚好达标；与指南自记的 `calf_r` 1.013° 同级 |

**取舍的实测依据**：腿的极向点在两个状态下最优位置不同 —— 静止时膝几乎落在髋—踝轴上（平面退化），屈腿时平面才良定义。以「两状态最差误差」为目标搜索实测：
- 单取屈腿最优 → `bent 0.055 / rest 0.012`，但 `calf_r` 静止滚转变差（1.99°）、左腿静止中关节漂到 0.415；
- 单取静止最优（**当前交付态**）→ 两态静止门槛全过，屈腿留 0.516 / 2.79°。
手臂没有这个取舍（静止不退化），所以手臂从 4.83 压到 0.235 是**真收益**，不是同类问题。

## 5. 本轮新增的可复用结论（建议回填指南）

1. **链必须先把引用重指再摆静止几何**：链起点被约束到起环、起环跟着 Biped 骨；重指前它们还跟着 Seven 的 Biped（实测重指前臂链 `startErr=5.09`，重指后 `9.5e-07`）。Runbook 把「链静止几何」排在「引用重指」之前。
2. **必须先摆环、再解链**：摆末端环会给链关节重新解算 —— 实测先解链后摆环会把臂链 `midErr` 从 0.0015 弹到 6.39。
3. **静止偏移对齐的"跳过 IK 环"要分起/末端环与膝/肘环**：膝/肘环是链中关节的**子级**，挪它只改 UE 骨不动链；起环与末端环驱动链的起止，必须跳过（把末端环算进对齐会让链中关节漂 0.45）。
4. **一切"真值"必须取落盘静止（`BIPDRV_*`/`gRest`），不能取骨当前值**。我踩了两次：环按骨当前位置摆（`upperarm_l` 锁死 4.95）、链长按 UE 骨当前间距归一化（弯姿势下 35.2634 而非 35.3003）。
5. **弯姿势会把链段长写短**（实测 35.3003 → 35.2618、45.3889 → 45.3504，各短 0.0385）—— 指南陷阱表只写了"写 `.rotation` 会改坏段长"，**弯曲姿势本身就会**。修法：按**驱动点**的骨长重归一化。
6. **滚转只能靠极向点/平面**：`rotation_list[1]` 的 `Euler_XYZ` 基值被 `LookAt` 完全覆盖（±20° 三轴扫描无任何效果）；`LookAt.pickUpNode` 与骨重合时退化（膝环与 `calf` 相距 3.8e-06），其影响幅度只有 ±1.5°。
7. **MAXScript 标识符大小写不敏感**：用 `H` 存 Point3 会覆盖手骨变量 `h`，报错却是 `Unable to convert: [Point3] to type: <node>`。
8. **`completeRedraw()` 是读值协议的关键**：每次写入后调一次，同一次调用内的读值即精确跟随；不用它时正确纪律是「一个阶段一次 MCP 调用」。
9. `refs.dependents` 反向扫会被**非 Node 依赖**（`ParamBlock2`、各 `*_Constraint`、`rotation_list`）打断，且会淹没在源 Seven 自己的 Skin/控制器里 —— 有效口径是**只扫我们这层**。
