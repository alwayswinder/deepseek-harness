- 换 `in coordsys world (rotate <锁骨> <quat>)` 行为**不一致**：
  - 单骨 + 单次调用：`dirErr 86.31° → 0.868°`，基点保持 `posErr 3e-6` ✅

| 假设 | 实测结论 |

| `biped.getTransform #pos` 是假阳性（文档陷阱表有这条） | **不成立**：API 读回与 `.transform.pos` 世界几何完全一致（max 同为 67.7911） |

### 2.5 Biped API 深挖结果（第二轮，全部实测）

#### 2.5.1 锁骨朝向由一对「锁骨值」驱动，且**没有 setter**

```maxscript
biped.getClavicleVals <锁骨节点>      -->  [a, b]      （实测初值 [0, 33.4931]）
```
- 写 `biped.setTransform <锁骨> #rotation <quat>` 会**改变这两个值**（实测写目标世界旋转后变成 `[-3.19542, -60.5197]`）⇒ 锁骨只有 **2 个自由度**（正好等于"一个方向"）。
- `biped` 结构里**没有** `setClavicleVals`；控制器 96 个属性里没有含 `clav` 的项；锁骨节点/基础对象/Biped_SubAnim 里也都没有对应槽位。
- 锁骨的世界旋转读回、`.transform.row1`、`biped.getTransform #rotation` 三者**完全自洽**（`as matrix3`.row1 与 row1 夹角 0.0°）——所以问题不在读数，在**写入被 Biped 重新求解**。

#### 2.5.2 用「不动点 + 数值雅可比」可以把锁骨方向**解到 0.00°**

文档的 `q ← (target × inverse(current)) × q` 之所以不收敛，是因为它假设"写世界旋转 = 世界旋转按同量旋转"；锁骨上这个映射被 Biped 替换了。改为**测雅可比**即可：

```
在当前请求 q0 处，绕世界轴 e1/e2 各转 2° 测方向响应 → 2×2 雅可比 J
求解 J·Δu = (目标方向 − 当前方向)  →  q0 ← (quat Δu1 e1) * ((quat Δu2 e2) * q0)
带回溯（步长减半）避免过冲
```
- 实测：干净状态下 5 步收敛 `22.7° → 54.6° → 7.9° → 0.048° → 0.0°` ✅
- **会在边界构型上奇异**（`det ≈ 0`，方向局部不可动）：此时需要**随机重启**（先随机采样若干请求四元数取最优，再牛顿收敛）。加了随机重启后左右锁骨都到 **0.0° / 0.0198°** ✅

#### 2.5.3 读值滞后可以彻底消除：**每次写入后 `completeRedraw()`**

- 实测 `写 q1 → completeRedraw → 读` / `写 q2 → completeRedraw → 读` / `写 q1 → completeRedraw → 读` 得 `a1 == a3`、`a1 != a2` ⇒ **加了 `completeRedraw()` 后，同一次调用内的读值精确跟随写入**。
- `redrawViews()` **不够**（实测同一次调用内多次读值反复出现同一个数 `115.971`）。
- ⚠ 尤其 **`#pos` 写入之后**：不 `completeRedraw()` 时，紧随的读值仍返回**旧值**（实测写 `#pos` 后读 `dir=0.0`，下一次调用实测 `dir=26.16`）。

#### 2.5.4 骨与骨之间会互相重解（耦合）

- 实测：写完锁骨的朝向（`dirErr=0.0`）后，**只写一次 `bip001 L UpperArm` 的 `#rotation`**，锁骨方向立刻变成 `26.15°`。
- 因此"一次调用里顺序解 52 根骨"会互相打架：实测顺序求解后锁骨停在 `55.6° / 59.4°`；加了 `completeRedraw()` 后能到 `0.0° / 0.0°`，但**位置阶段与朝向阶段互相破坏**（最后一次实测 `maxPos=191`，`ball_l`）。
- 结论：需要**全局松弛**（位置轮 ↔ 朝向轮交替 + 每轮后测残差），且锁骨必须**最后**解。

#### 2.5.5 当前最好的一次结果（比文档配方好得多）

#### 2.5.7 交替松弛实测：仍然不收敛（本轮最后一个负面结果）

按 §2.5.3–2.5.4 的结论写出「长度 → 朝向（直接写 + 雅可比牛顿）→ 位置」并加 `completeRedraw()` 的多种排序，逐轮实测（都是**全部 52 根** `maxPos` / `maxDirErr`）：

## 3. 其它可回填文档的实测结论

1. **`classof o == Dummy` 建成 Biped 后不再是「55 根 UE 骨」的判据**（Nub 也是 Dummy，会数到 68）。
2. **读值滞后有确定的解法**：每次写入后调一次 `completeRedraw()`，同一次调用内的读值即精确跟随写入（见 §2.5.3）。文档写的"`redrawViews()` + 二次读值"**不足以**在单次脚本内收敛；若不用 `completeRedraw()`，正确纪律是**一个阶段一次 MCP 调用**。
3. **安全模式确实拦 MAXScript 写文件**：`createFile` 返回 `Blocked by safe mode: command contains a restricted function` —— 与文档一致，所以真值只能走 MCP 输出 + 外部写盘。
4. `E:\AI\3dMax\Save\` 是有效场景目录；`saveMaxFile` 返回 `true`，`doesFileExist` 复核通过。
5. **MAXScript 的 `quat` 打印顺序是 `(x y z w)`**，而 `.w/.x/.y/.z` 取值器是常规 wxyz。实测 `quat 90 [0,0,1]` 打印 `(quat 0 0 0.707107 0.707107)`、`.w=0.707107`、`.z=0.707107`。**不要拿 `quat as string` 的输出顺序算分量**。
6. **文档的"朝向残差"指标本身有隐患**：`2·acos(|qt·qb|)` 用 `bone.transform.rotation` 是**世界旋转**（已验证 `as matrix3`.row1 == 骨指向），但早期若用 `matrix3 row1 row2 row3 → rotationpart` 构造比较四元数，MAXScript 会转置 ⇒ 得到的角度毫无意义（我踩过，`upperarm_l` 真值 116.8° 被算成 3.79°）。建议在指南里补一句"用分量点积、别自己拼矩阵"。

## 6. §5 的复核与更正（2026-10-16 18:3x，逐条实测）

### 6.4 `#pos` / `#rotation` 写入**立刻可读**，不是"读到刚写入的 figure 值"

- 写 `#pos`：写完**不刷新**立即读 ⇒ `posErr = 1.78814e-07`（写入已生效），且**方向不变**（`7.35159°`）；`completeRedraw()` 后再读仍相同。
- 写 `#rotation`：写完**不刷新**立即读 ⇒ `clavDir 7.35159° → 86.7288°`（写入已生效），`completeRedraw()` 后仍为 `86.7288°`。

⇒ "调用内读到的是刚写入的 figure 值、循环假收敛"这条**没有复现**。文档的不动点在单次调用内**确实会因为读数与求解器耦合而不可靠**（§2.5.3/2.5.4 记录的那些自相矛盾的数字），但那是**"写一根骨会让别的骨重解"**造成的**真实状态变化**（实测：只写一次 `bip001 L UpperArm` 的 `#rotation`，锁骨方向就从 `0.0°` 变成 `26.15°`），不是读值假象。

### 6.5 §2 的结论更正（**这一条最重要**）

- **"锁骨写不进去"是错的。** 锁骨写得进去：先把 `#pos` 摆到目标（基点精确到 `1.79e-07`，**不动方向**），再用 `in coordsys world (rotate <锁骨> <quat ang ax>)` 迭代 ⇒ `dirErr 7.35° → 0.0°`；落盘 `_fitted` 里锁骨 `dirErr = 0.02798°`、`clavVals = [-2.96976, 25.9935]`，与第一轮的 `[-3.00001, 25.9999]` 同一支。
- **我 §2.2 的 `maxPos=67.79 / maxDir=173°` 不是"配方失败"，而是我自己写入序列中途的快照。** 因为写一根骨会重解相邻骨，逐轮 `125 → 22 → 17 → …` 那些数字都是**真实但未收敛的中间态**；我把中间态当成了配方的结论 —— 这是本轮的方法论错误。
- **可用的读值纪律（我验证过的）**：① 判定拟合结果时**测落盘文件**（确定性、可复现）；② 在会话中做逐轮迭代时，别把单次中间态的读数当结论，要用**纯几何指标**（由子骨位置算方向夹角、位移）并跨调用复测；③ 涉及 `#pos` 的批次里，写入后用 `completeRedraw()` 再读（§2.5.3 的记录仍然成立）。
