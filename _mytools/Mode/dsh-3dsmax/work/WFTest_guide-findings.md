## 2. A 类：阻断级（照字面执行会错）

1. **控制器指南 §2 步骤 5 只复制旋转，并写「位置侧不用改」** —— 复现中目标 UE 骨在合并后仍是自由 `Position_XYZ`，没有任何环节把它们连到迁移来的环上。照字面做会复现「动控制器→角色不动」，也过不了指南 §3 自己的验收项「环驱动 1:1（动末端环 +5）目标骨 = 5.000」。
   **重建指南 §0 却写着「UE 骨位置 = 环的位置 由控制器指南 §2 步骤 5 建立」——两份指南自相矛盾。** 真正的步骤只出现在流水账 §10.14（「逐个复制到同名 UE 骨、替换驱动层约束」）。
   实测：补上「复制 `position_list`+`rotation_list`」后，动环 +5 ⇒ `hand_r` = 5.000、复位 0。

2. **驱动层 `Root` 例外不成立**：把 `BIPDRV_Root` 挂到 `bip001` 下会继承 **0.762° 旋转偏置**，且**用世界变换赋值无法纠正**（新建 Point 一挂上去立刻偏 0.762°；`t.transform = 单位矩阵`、`t.rotation = 单位四元数` 读回都不变）。
   后果：违反同一步门槛「建驱动点前后 B 骨位移 ≤1e-3」——实测 `head` 1.974、`pelvis` 1.208（正是案例里那句「漂移量 1.2–2.0」），整条骨架绕 Root 旋转 0.76°。
   可用替代：**不挂父子，改用 `relative = true` 约束**（先把驱动点摆到原始静止、再 `appendTarget`）→ 实测位移 **0.0**；指南那句「不要给这些约束开 `relative = true`」在这里是过宽的（有基准时它正确且必要）。顺带说明：指南「Biped 根 scale=[1,1,1]」也不准，实测节点 scale 为 `1`、而 `biped.getTransform #scale` 是 `0.410745`（装 figure 后）。

3. **`biped.getTransform <骨> #pos` 不能用来校验复位**：+25Z 测试后 API 读回「已复位（1e-5）」，但**求值后的世界位置仍偏 25.0**（膝偏 29.4），Biped 被留在弯姿势。
   差分验收必须「先记世界位置、复位后比对世界位置 ≤1e-3」；指南只写了「惰性求值，二次读值」，不足以覆盖这个假阳性。

## 3. B 类：指南缺失、复现时必须补的步骤

4. **复制结构后的「静止偏移对齐」没有条目**：复制完 52 根骨里 **44 根偏 >0.2（最大 6.82 `clavicle_l`）**。流水账 §10.14 只有一句「以驱动点为准多轮迭代（共享手柄取平均）」。
   实测可用做法：把「每个约束目标 ← 驱动它的骨的平均误差」迭代回写（阻尼 0.6），1–2 轮收敛。

5. **`Path_Constraint.percent` 必须在手柄迭代之后收尾**：`Point001/002` 的 percent 最优值（实测 **49.97 / 99.9968**，指南案例写的是 58.0769→50.0）会被后续手柄迭代经层级带偏（`spine_02` 回弹到 1.41）。顺序错了就永远差 1–2 单位。

6. **膝/肘/脚掌环同样是被约束的目标，必须一起对齐**：指南步骤 3 只写「把**起/末端环**移到 B 的关节」，实测 `calf_*` 由膝环驱动、`ball_*` 由脚掌环驱动；漏掉它们，`calf`/`ball` 偏 1.1–5.8。

7. **辅助 IK 链的「静止几何」需要单独重拟，指南的段长迭代修不掉它**：链关节的冻结向量**纯沿局部 X**（y,z≈1e-6），关节静止位置的方向由**关节自身旋转**决定，而那是源角色的数据。
   指南步骤 3 的迭代只改 `c1.value.x`，**从原理上修不掉侧向误差**——实测腿 0.62、臂 4.07。修法：按「父级局部坐标系里的方向 × 目标骨长」重写冻结向量（`eff = p1 + p2`，实测该恒等式误差 1e-6），臂的中点关节可用**局部坐标系不动点迭代**收敛到 0.005。

8. **`gRest`（55 骨原始静止）只在会话全局里**：指南没说怎么持久化；重开场景即失效，而 Max 安全模式禁止 MAXScript 写文件（`createFile` 被拦）。建议加一条「落盘到工作区文件」的步骤。

9. **原 `scripts/02_prefix_target_skeleton.ms` 只给 `Dummy`(55) 加前缀**，漏了新建 Biped 的 71 根 `bip001*`；实测重名集是 **126**（流水账记的也是 126）。照脚本跑会让源的 Biped 被 Max 自动改名（`bip001001…`），`SV_` 命名约定随之失效。
   > 处置（2026-10-16）：55 Dummy + 71 Biped 的命名三步配方已内联进控制器指南 §2 步骤 2；整个技能目录已移除（原件留档在 `E:\AI\3dMax\3dsmax-mcp-master\.agents\skills\`）。

## 4. C 类：表述/数字与实测不符

10. `LayerManager.getLayerFromName "<层>".setCurrent()` 在 Max 2026 **不存在**（指南 §5 API 表写着）→ 建 Biped 只能建完再 `layer.addNode` 逐骨移层。
11. `biped.createNew 3 1 [0,0,0]` 的 3 个参数**不决定结构**：实测默认 `spineLinks=4`，而真正生效的是紧跟的 8 个结构属性。
12. 指南「Skin 骨骼名单与这 55 个名字逐一对上（数量也要对）」：实测 `PrinceofStan_Body`=54、`Face`=3、`Eye`=1、`Hair`=1，**`Root` 不参与蒙皮**；应写成「并集 = 54（Root 除外）」。
13. 指南「`refs.dependents <骨>` 只看到 `Skin`」不可直接判读：实测依赖类还有 `DummyClass`（子骨）与 `Editable_mesh`（蒙皮网格）。可执行判据：依赖类 ⊆ {Skin, DummyClass, Editable_mesh} 且无约束控制器。
14. `manage_layers list` 报的是图层**自身**勾选位，MAXScript `Layer.isHidden` 报的是**合并后**状态（父层隐藏会连带）。指南陷阱表只提了后者，容易把「父层隐藏」误判成「该层可见」。
15. 数字不一致：指南 §3 写腿长 `45.3890`、§7.1 写 `45.3889`；案例写「最大位置误差 0.04（`thigh_r`）」，本次复现最大值在 `thigh_l`。
16. 极向点：指南说门槛「|中关节 − B 中段骨| < 0.02」，实测静止时链中关节离 Biped 膝 **0.0799**（臂 4.07 更离谱，见 B-7）。
17. `01_discover_rig.ms` 的「是否已迁移」检测查的是 `S7_*`（路线 2 的命名），对 `SV_*` 路线查不到。
18. 环的「补偿偏移归零」（步骤 4）本次不需要：源数据里膝环本来就落在链关节上（偏移 1.6e-05）。**反而**指南步骤 3「把环移到 B 的关节」若照做（把环挪到骨上）会让膝环贴近髋—踝轴，`LookAt` 上方向节点退化，`calf` 朝向实测翻 **179.4°**。

## 5. D 类：Max/MAXScript 工具细节（指南未覆盖的坑）

19. **列表控制器取值必须走 `getSubAnim c j` → `.controller`**：`pos.controller[2]` 拿到的是 `SubAnim` 包装，`.value` 是 `undefined`，直接参与向量运算会报 `Unable to convert: undefined to type: Point3`（指南 API 表提了遍历，但没提「下标取值参与算术会炸」）。
20. `fn rp ...` 这类短函数名会与内置冲突（同名时整段脚本报 `undefined` 类型错误）；用全长名（如 `restPosOf`）即可。
21. 一旦对链关节写 `.rotation`，IK/求解器会重解并**改坏段长**（实测 `|j1−j2|` 从 35.3003 变 37.9）；`move` 对链关节只部分生效（有伸缩线 `p2.x = 0.0385…` 与 IK 回写）。**唯一稳定杠杆是写 `p1`（冻结位置）**，且必须按「方向 × 长度」构造而不是直接写目标坐标（直接写会因求解器接管而发散，臂的末端段长一度被撑到 39.25）。

## 6b. 追加：用户现场反馈后定位（2026-10-16 16:1x，`_delivered_v2`）

**反馈 1「移动控制器后 Biped 不跟着动」——不是迁移缺陷，是源 rig 的设计。**
在**源窗口**同操作实测：动 `Circle016/010/013/015/093` 各 +5Z ⇒ 源 UE 骨全部 5.0、源 `bip001*`（Biped）**0.0**。迁移后的 Stan 窗口数值完全相同。指南 §0 也写明「动 A 的环不会反驱 A 的 Biped（实测 0.000），环是偏移/微调 + 可视化层，摆姿势靠 Biped」。
若确实要「环反驱 Biped」，那是源 rig 没有的**新增能力**（需另加一层约束，并承担与 IK 循环依赖的风险），不属于本次迁移范围。

**反馈 2「手部扭曲、IK 效果不对」——真凶是照抄指南 §7.3 的 twist 建议。**
- 源 rig 的 `lowerarm_twist_01_l/r`：旋转 = `rotation_list`（`[1] Euler_XYZ` 基值 + `[2] LookAt → 腕环`），**位置 = `position_list`（`[2] Position_Constraint → Circle022/024` 臂中点环）**。
- 我按指南 §7.3「单目标 `Orientation_Constraint` → `BIPDRV_lowerarm_*`」实现 ⇒ twist 骨**只跟静态的 Biped 驱动点**；正确姿势是「动环」时 Biped 不动 ⇒ 前臂扭转骨卡住 ⇒ 蒙皮扭转 ✗（而且源 twist 是位置+旋转双通道，我只做了旋转）。
- 修正：按源结构复制 twist 的**位置 + 旋转**两棵控制器树，并把中点环 `Circle022/024` 摆到 B 的 twist 骨静止位；另把**手臂 `LookAt` 目标还原为源的中点环**（`Circle021/022/023/024`）——指南 §7.3 建议改指「肘环/腕环」，那是为「源中点环偏 9.9/11.4」的中间态写的；在链已对齐的终态里，源中点环本来就落在前臂中段，改指反而偏离源行为。
- 修正后实测（动腕环 +5Z）：左右**对称**跟随 —— twist 骨位移 **3.96**、自转 **28.7°**（源 5.45 / 20.07，差异来自两套骨架比例不同），静止对齐不受影响（0.0518 / 1.013°）。

⇒ 指南新增问题 22：**§7.3 的 twist 与 LookAt 改指建议缺适用条件**。它们是为「v2 驱动层中间态」写的；在路线 1 的最终态套用会让「扭转骨跟随环」这一源行为失效（表现为手/前臂蒙皮扭转）。

## 7. 建议的指南修订（最小改动）

1. 控制器指南 §2 步骤 5 改成「复制**位置 + 旋转**两棵控制器树」，并删掉「位置侧不用改」；重建指南 §0 的表述同步。
2. 驱动层 Root 例外改为「改用 `relative=true` 约束（先摆静止再 appendTarget）」，并把「Biped 根 scale = [1,1,1]」改为实测值。
3. 新增一节「**静止偏移对齐**」：手柄迭代 + `Path_Constraint.percent` 收尾，明确顺序不可颠倒。
4. 新增一节「**辅助链静止几何重拟**」：`eff = p1 + p2`、只写 `p1`、按「方向 × 目标骨长」构造、臂/腿用不同分量约定（腿在 `p1.x`、臂在 `p2.y`）。

6. 差分验收补一句：「复位必须校验**世界位置**，`biped.getTransform #pos` 会给出假阳性」。
7. `02_prefix_target_skeleton.ms` 补上 Biped（126 个对象）；`01_discover_rig.ms` 的迁移痕迹检测补 `SV_`。
