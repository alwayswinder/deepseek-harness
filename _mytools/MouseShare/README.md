# MouseShare —— 一套键鼠控制两台 Windows 电脑

**反向连接**版软 KVM：被控端主动拨入主机端，所以两台即使不在同一网段、隔着一层 NAT（例如笔记本在另一台路由器后面）也能用。

## 为什么不用 PowerToys 的「无界鼠标」

MWB 的连接方向是「对端连到有键鼠的那台」之外还要求主机端能解析并连上对端；本机实测拓扑是主机 `192.168.1.3`、对端 `192.168.0.104`（在 TP-Link 后面做 NAT），**主机端没有到那个网段的路由**（`tracert 192.168.0.104` 直接跑到上级网络），只有对端能出网连到主机。这里把方向反过来：主机端监听，被控端拨入。

## 文件

| 文件 | 说明 |
| --- | --- |
| `src/Native.cs` | Win32 互操作：低级键鼠钩子、`SendInput`、光标与屏幕信息 |
| `src/Host.cs` | 主机端：监听、全局钩子、热键切换、吞掉本地输入并转发 |
| `src/Agent.cs` | 被控端：拨入、断线重连、收到事件用 `SendInput` 注入 |
| `src/Program.cs` | 入口、用法、注入链路自检 |
| `build.bat` | 用系统自带 `csc.exe` 编译到 `bin\MouseShare.exe`，不需要 .NET SDK |
| `run-host.bat` / `run-agent.bat` | 双击即用；`run-agent.bat` 的主机地址取自第一个参数，留空则提示输入 |
| `bin/MouseShare.exe` | 已编译好的程序，**跟着仓库走**：另一台 `git pull` 就能直接拿到，不必自己编译。改过源码后跑 `build.bat` 重新生成并一并提交 |

## 编译

```bat
build.bat
```

系统自带 .NET Framework 编译器（`%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`），无第三方依赖。

## 部署与使用

1. 在另一台电脑上 `git pull` 拿到 `bin\MouseShare.exe`（它已入库），或直接拷贝整个目录。那台能不能被访问不重要，只要它**能出网到主机**即可。
2. **先在被控端**运行：`run-agent.bat`（提示输入主机地址），或 `MouseShare.exe agent --server <主机IP>:15180`
3. **再在主机端**运行：`run-host.bat`，或 `MouseShare.exe host`
4. 主机端窗口显示「被控端已连接」后，按 **Ctrl+Alt+F12** 切到远程；再按一次切回本地。

参数：

| 端 | 参数 | 说明 |
| --- | --- | --- |
| host | `--port <端口>` | 监听端口，默认 15180 |
| host | `--hotkey ctrl+alt+f12` | 切换热键，支持 ctrl/alt/shift/win + 字母/数字/F1–F24 |
| host | `--remote` | 被控端一连上就直接进远程模式 |
| host | `--trace` | 打印每个鼠标事件的原始坐标与推算位移（排查映射问题用） |
| host | `--accept-injected` | 连注入的鼠标事件也转发；**仅自测用**，正常使用不要开 |
| agent | `--server <IP>[:端口]` | 主机地址，默认 `127.0.0.1:15180` |
| agent | `--dry-run` | 只打印收到的事件、不注入，排查用 |
| 两端 | `selftest` | 注入 1 像素鼠标移动 + F24 按键，验证注入链路 |

开机自启：把 `run-agent.bat` 的快捷方式放进 `shell:startup`。

## 协议

每行一条，ASCII，空格分隔：

```
M <dwFlags> <dx> <dy> <mouseData>    鼠标：直接对应 SendInput 的 MOUSEINPUT 字段
K <wVk> <wScan> <dwFlags>            键盘：直接对应 KEYBDINPUT 字段
P                                    心跳，对方回一条 P
```

鼠标移动用 `MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` 的归一化 0..65535 坐标，**按屏幕比例**映射，所以两台分辨率/DPI 不同也能落在对应相对位置。

### 为什么鼠标位置要「累积」而不是直接用事件坐标

主机端在远程模式下会吞掉鼠标事件，**本机光标因此不再移动**，钩子上报的 `pt` 只是「锚点 + 这一次事件的位移」。所以直接拿 `pt` 当绝对坐标会得到一个永远停在原地的值（表现为远端光标只能在很小范围内抖）。

现在的做法是维护一个虚拟光标：

- 进入远程模式时记录锚点（当时的光标位置），虚拟光标 = 锚点；
- 每个鼠标事件把 `pt − 锚点` 累加到虚拟光标上，再把虚拟光标按比例发出去；
- 之后立刻 `SetCursorPos` 把物理光标按回锚点，保证下一个事件的位移仍然相对锚点；
- 自己 `SetCursorPos` 产生的事件带 `LLMHF_INJECTED` 标志，默认被忽略，因此不会自我放大。

## 已知限制

- **没有认证**：主机端监听 `0.0.0.0:<端口>`，任何能连上这个端口的机器都会被接受，连上后就能向主机端反向注入键鼠。只适合在可信局域网里用；需要的话可以自行加共享密钥（协议里加一条握手）。
- 同一时间只服务一个被控端；后来的连接会顶掉先前的（先连的那台会被切换成本地模式）。
- 注入不了「以管理员身份运行」的窗口（Windows 的 UIPI 完整性级别限制）。需要时用管理员身份运行被控端。
- 被控端锁屏界面 / UAC 安全桌面上注入无效（除非被控端以服务身份运行）。
- 鼠标是**按比例映射**，不是 1:1 位移；对端若是多显示器，落点按它整个虚拟桌面的比例算。
- 远程模式下**本机光标会停在进入时的位置不动**（这是设计：事件被吞掉并不断按回锚点）。
- 链路中断（Wi-Fi 掉线、被控端退出）时，主机端最多 12 秒内自动退回本地；正常的 TCP 断开通常 1 秒内就发现。
- 主机端进程退出或被强杀会同时卸载钩子；即便当时在远程模式，本地键鼠也会立刻恢复。
- 只做键鼠，不做剪贴板、文件传输、屏幕画面传输。

## 排错

| 现象 | 检查 |
| --- | --- |
| 被控端一直「3 秒后重连」 | 在被控端 `ping <主机IP>`；主机端 `host` 是否在跑、端口是否被占用 |
| 主机端一直「等待被控端连接」 | 主机端防火墙/安全软件是否拦入站。本机实测 Windows 防火墙三个配置文件都是 `OFF`（装着实测运行中的深信服 aTrust），但不能按此推断别的机器 |
| 按热键没反应 | 热键被其它软件占用，换 `--hotkey ctrl+alt+f9`；必须在主机端窗口还开着时按 |
| 切过去后本机键鼠不动 | 这是预期的（已被接管）。再按一次热键返回；若主机端显示「连接断开」，说明链路掉了 |
| 远端光标只在很小范围抖动 | 已修复（见上面「为什么鼠标位置要累积」）。对端若还在跑旧版不会有影响，**要更新的是主机端**；用 `--trace` 看是否在累积 |
| 远程端出现粘滞按键 | 切回本地时会自动补发所有按下键的抬起；仍异常就再切一次 |

## 实测记录

2026-10-04（主机端 Windows 11 家庭版 26200，回环 + `--dry-run` 被控端）：

- `selftest`：`INPUT` 结构 40 字节，鼠标+键盘 `SendInput` 返回 4/4。
- 注入 F24 → 被控端收到 `vk=0x87 flags=0x00` / `0x02`（按下/抬起）。
- 注入 Ctrl+Alt+F12 → 主机端日志 `>>> 远程模式`；再注入一次 → `<<< 本地模式（热键切回）`。
- 杀掉被控端 → 0.9 秒内主机端 `<<< 本地模式（连接断开）`。

2026-10-05（真实两台机器，用户实测反馈 + 回环复现）：

- 用户实测：连上后远端光标「只能在很小范围内晃动」→ 定位为吞掉事件后 `pt` 不再变化，绝对映射失效（旧实现）。
- 改为累积虚拟光标后回环复测：静默 500ms 基线 0 事件，注入 3 次位移产生**恰好 3 条**事件（回锚没有自我放大），注入后本机光标仍停在 `640,400`。
- **注意**：主机端在远程模式下会接管本机鼠标，本地测试时用户的手动移动也会混进结果——这次就踩到过（`--accept-injected` 的自测尤其明显）。

**尚未实测**：被控端把事件真正注入到它自己的桌面（回环用的是 `--dry-run`）；真实两台机器上修复后的手感。
