# @local/dsh-appearance-plus

[English](README.md) | 中文

## Summary

该配置层在插件页增加五套颜色主题、背景图片编辑器和空闲锁屏。偏好作为组合包当前 profile 配置中的热更新字段保存；选取的本地图片只保留在对应浏览器或 Desktop 配置中。组合包只改变显示效果，不改动对话或模型请求。

<a id="use-this-package"></a>
## 使用本包

组合包启用后，打开**插件 → 外观增强**。可选择默认、护眼绿、暖纸、海蓝、柔紫或深夜。每项选择都会立即应用并自动保存。

**背景图片。** 可以粘贴 HTTP(S) 图片地址，也可以选择本地图片。页面会立即预览文件，把它转换为容量受限的 WebP 图片，并拒绝超过 20 MB 的本地输入。图片亮度、界面遮罩、模糊和铺放方式也会自动保存；滑块和图片地址使用短暂延迟，把连续修改合并后写入。图片到达屏幕的强度是「图片亮度 ×（1 − 界面遮罩）」，界面遮罩决定最终还能看到多少。默认 0.62 让壁纸清晰可见而界面依然易读；滑块下限 0.15 让侧栏、消息区、输入框、设置行和代码块一起变透，嵌套表面叠加后壁纸仍能透出大半。下拉菜单和提示浮在图片之上，另按不低于 0.82 的底色绘制，保证文字可读。

**锁屏壁纸。** 第二张独立图片，自己一套铺放方式。勾选**空闲时启用**后，只要没有任务在运行、并且一段时间内没有点击、滚动、按键或鼠标移动（默认 20 秒），客户端就进入锁屏：这张图片在 2.4 秒内盖住整个页面，对话和侧栏一并遮住。之后任何一次点击、滚动、按键或鼠标移动都会在 0.22 秒内交还界面；锁屏不透明时，用于解除的那一次点击会被它吃掉，不会落到它遮住的控件上。任务运行期间不进入锁屏，设置页也始终不解锁屏，保证控件随时可点。在桌面端，锁屏还会在这张图片加载完成、完全盖住窗口之后，把窗口自带的标题栏——那条底色以及最小化、最大化、关闭三个符号——一并清掉：壳正是用页面上这两个颜色重画这块区域的，插件把它们置空即可。窗口本身不会被缩放、移动或切到全屏，界面回来时标题栏同时恢复。

Web 端在终端安装：

```text
dsh plugin --profile web add file:<repo>/_mytools/Plugins/appearance-plus
```

Desktop 拥有自己的配置（`$DSH_HOME/profiles/desktop`），并拒绝 `dsh plugin --profile desktop`；因此要在应用的**插件 → 添加插件**对话框中填入本目录的绝对路径，每台机器安装一次。裸绝对路径和 `file:` 形式都可以：插件必须能从自身目录解析 `@deepseek-ai/schemastery`，而 `build.bat`、`build-desktop.bat`、`start-dsh.bat` 和 `start-desktop.bat` 都会在运行前把 `_mytools/Plugins/node_modules/@deepseek-ai/schemastery` 链接到 vendor 中的副本。缺少该链接时 Host 无法导入插件，会把组合包报告为启用失败。

首次安装后重启 Desktop 或重新加载 Web 应用，使浏览器包进入客户端图。

<a id="understand-the-implementation"></a>
## 了解实现

<details>
<summary>实现细节——点击展开</summary>

[`index.js`](index.js) 把组合包的 Config 标为可热更新；组合包已有自定义页面，因此关闭自动生成的表单页。[`client.js`](client.js) 通过 `ctx.configForms` 读取该表单，经具名的 `ctx.theme` token 覆盖层应用配色，把两张已保存的图片投影到自有样式表，并通过 `plugins.item` 提供配置页。覆盖层以可持久保存的内置浅色或深色偏好为基础，因此配置同步不会替换已选配色。[`cordis.patch.yml`](cordis.patch.yml) 挂载 Host 行。

两张图片由两份自有样式表承担。一份声明 `#root` 之后的背景层，以及压在所有东西之上的锁屏层（高于每一个 portal 出来的菜单、弹窗和提示），锁屏过渡只依赖其中唯一一个用 `@property` 注册的淡化系数；另一份把每个表面 token 从当前主题重新推导成基于已保存遮罩 alpha 的 `color-mix(...)`——因此所选配色不会被一张写死的颜色表替换，而是穿过背景图片保留下来。空闲计时器是一个本地 500 毫秒轮询加上 pointer、wheel、key 三类监听器；「有任务在运行」读的是 `ctx.sessions.list` 中任意一行的 `running` 标记，走可选注入，因此没有会话服务的 profile 只是永远不会进入锁屏。鼠标移动只有在指针真的移动过时才算操作，因为缩放或移动窗口会让引擎在原位置补发一次移动事件。桌面端标题栏的清除也由同一份样式表承担：控制器在锁屏盖住窗口后再过一个淡入时长打上属性、离开时摘掉；锁屏层只在这张图被浏览器解码完成之后才算盖住窗口，于是「标题栏颜色被清空」与「屏幕上真有锁屏」是同一个状态。通知壳重读这两个颜色靠的是一个插件自己的属性——壳只在 body 的 style 属性变化时重读，而主题写在 body 上的配色 token 不能被碰。定义这些 token 的样式表还没到位时，颜色会按短间隔重试读取；基础表面由根元素自己绘制，因此应用没有画背景的区域同样受遮罩控制，不会直接露出原图。

两个图片槽各自持有自己的本地存储键与持久标记：选择的本地图片以压缩 Data URL 形式存储在当前浏览器配置中，当前 profile 配置只携带标记，从不包含图片字节。只有存放过该图片、之后又丢失的来源才会清除这个标记；其他来源只会提示本设备没有这张图，并保持共享偏好不变，因为 profile 配置是共享的，而本地存储按来源隔离。

</details>

<a id="model-experience"></a>
## 模型体验

无。组合包只改变浏览器显示，不增加模型可见输入、提示词内容、工具或会话事件。

## 已知限制与延后工作

本地图片不会在 Desktop、Web 或其他浏览器配置之间同步；每张图都需要在每个界面分别选择，没有副本的界面会在页面上说明。锁屏过渡依赖 `@property`，表面透明依赖 `color-mix`；不支持它们的引擎会直接切换状态而没有过渡。清掉桌面端标题栏后，那条底色和三个符号都看不见了，但它们的点击区域还在：壁纸右上角点击仍然会最小化、最大化或关闭窗口，鼠标移上去也会出现系统自带的悬停高亮。标题栏的颜色取自页面的标签色，因此两者是同一个状态：锁屏图缺失或始终加载不出来时不画锁屏，标题栏颜色保持不变，界面照常可读。标题栏被清空期间，界面自己的主标签色同样是透明的，只是被画在上面的锁屏挡住了才看不见。背景透明度作用于使用主题 token 的界面，而嵌入式终端、文档预览和远程网页可以保留自己的不透明背景——锁屏画在界面之上，因此这些内容同样会被遮住。
