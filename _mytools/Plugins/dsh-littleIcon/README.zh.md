# @local/dsh-little-icon

[English](README.md) | 中文

## Summary

桌宠是**独立于 DSH 窗口的进程**（PowerShell + WPF），不是画在窗口里的浮层：它有自己的无边框、透明、置顶小窗，所以 DSH 最小化或被收起后它依然留在桌面上。宿主半边（`index.js`）采样 agent 状态写进状态文件，桌宠读它切换表情动画；点击桌宠用 user32 的 `ShowWindow` 把 DSH 主窗口收起或恢复，右键菜单提供同样的动作、归位与退出。右键菜单里由页面执行的部分：**对话**在 DSH 内嵌浏览器里开 chat.deepseek.com，**Git 改动**在右侧栏开仓库视图——左边是当前会话工作目录里未提交的改动，右边是提交历史（先显示最近十条，滑到底继续往下读，还能按作者筛选），并提供一次明确的快进拉取，**打开工作目录**把同一个工作目录交给宿主，在 Windows 资源管理器里打开，**设置**把**插件**页翻到本插件自己的那张卡片上（大小、虚化、打盹这些控件就在那里），**小游戏**子菜单里的**玻璃鱼缸**打开的是另一个插件（3D 玻璃鱼缸）的全屏 WebGL 浮层；**听歌**子菜单每次展开都按宿主发布的曲库重建——一行灰色状态、**开始**／**暂停**与**换歌**／**上一首**、缺文件时的**补全缺失歌曲（N 首）**、**打开音乐文件夹**与**设置**，音频由桌宠进程自己播，所以 DSH 收起后照样响。**截图**是桌宠自己的活、不经过页面：在压暗的遮罩上拖一块区域，PNG 落进 `$DSH_HOME/little-icon/shots/`，**图片本身**进剪贴板。插件自身不增加模型可见输入；只有点击**提交并推送**时才发送普通用户消息。

## 使用本包

**桌面端安装。** Desktop 拥有自己的配置（`$DSH_HOME/profiles/desktop`），并且拒绝 `dsh plugin --profile desktop`；在应用的**插件 → 添加插件**对话框里填本目录的绝对路径即可，每台机器装一次。装好后必须重启 Desktop：宿主半边（`index.js`）不参与客户端热更新，只有重启才会加载它。

**网页版安装**（可选；此时桌宠只悬浮，不控制任何窗口）。`build/start-dsh.bat` 的 `DSH_LOCAL_PLUGINS` 里已经列了本插件，每次启动会幂等地把本目录以 `file:` 装进 web profile，`sync-plugins.bat` 随之刷新 `index.js`、`pet/` 与 `assets/`。要手动装：

```text
dsh plugin --profile web add file:<repo>/_mytools/Plugins/dsh-littleIcon
```

**调节大小与虚化。** 打开**插件**页，点标题为**桌宠**的卡片：设置卡片画在这张卡片的详情页上（在描述与「包含的组件」之间），不用再点进 `little-icon` 那一行。顶部是常用项：

- **常用网站**：一行一个网站，左边是**备注**（菜单上显示的名字，留空就用网址的域名），右边是**网址**（不写 `https://` 也行）；行尾的**删除**去掉一条，下面的**添加一个网站**补一条。右键菜单的「常用网站」按这个顺序列出，地址不是 http/https（比如 `file://`）或带了用户名密码时，那一行下面会说明它打不开、菜单里不会出现；
- **音量**：0–100 的滑块（`musicVolume`，默认 70），决定桌宠播放的音量；这一项跟着设置文件走，两台机器共用；
- **音乐目录**：音频文件下载到哪个文件夹（`musicDir`），右边是**浏览**按钮；留空就是插件自己的 `$DSH_HOME/little-icon/music/`；
- **听歌**：链接列表、**补全缺失（N 首）**按钮，以及**正在播放**那一行与播放/暂停/上一首/下一首（见下面「听歌」）；
- **大小**：96–320 像素的滑块，改完桌宠当帧就变；
- **闲置时虚化**：开关，关掉就是始终不透明；
- **虚化程度**：开启虚化时可用，15%–100%；
- **切到别的应用就收起 DSH**：默认开启；下面那条滑块是「到后台多久才收起」，默认 0（一切到后台立刻收），关掉开关时变灰；
- 另外还有启用开关、始终置顶、点击行为、表情节奏，以及折叠在**更多**里的空闲节奏、开心时长和状态采样间隔。

控件即时写回 profile 配置（`$DSH_HOME/profiles/<profile>/cordis.patch.yml` 里那一行 `little-icon`），不需要重启：宿主半改配置会重新发布状态文件，桌宠一秒内套用。把**启用桌宠**关掉再打开也能立刻结束/重新拉起桌宠进程。**改完一秒半后宿主还会把这一行抄进仓库的 [../../settings/pet-settings.yml](../../settings/pet-settings.yml)**——只有 desktop profile 会自动保存，提交与推送仍由你决定；同一条通路也带走 **Desktop 的快捷键**：那个文档归主进程管（`$DSH_HOME\desktop\electron-user-data\keybindings.json`），宿主看不到它的编辑事件，所以直接盯着那个文件，应用一改就抄进 [../../settings/keybindings.json](../../settings/keybindings.json)。另一台机器 `git pull` 后启动时，`build\start-desktop.bat`（或桌宠菜单里的重启）把这两份文件合并回那台机器，所以两台电脑不必各设一遍。反过来，本机改过的值会保留到对应文件下次更新；要强制退回文件里的值，跑 `node _mytools\settings\sync-settings.mjs apply --force`（机制细节见工作副本的 `_mytools/README.md` 里「设置跟着 git 走」一节）。这张卡片由插件的浏览器半边（`client.js`）提供，所以重启后不会再出现第二份自动生成的表单。

**交互。** 桌宠默认贴在主屏右下角，闲置时按上面的设置半透明，鼠标移上去变清晰。按住左键拖动会移动位置（松开即记住，下次启动还原，并夹在当前虚拟屏幕内）。**单击**（没有拖动的那一次按下）执行配置里的 `clickAction`：`toggle`（默认）只在 DSH **已经是最前面那个窗口**时把它收起；DSH 只是被别的应用盖住时，单击是**把它提到最前**而不是收起；DSH 已收起或最小化时单击则恢复并置顶。`minimize` 只最小化；`none` 什么也不做。**右键点桌宠**弹出的菜单提供「对话」「常用网站」「Git 改动」「打开工作目录」「小游戏」「听歌」「截图」「特殊功能」「设置」，桌面端另有「系统」子菜单，里面是「更新 DSH」「重启 DSH」「退出 DSH」。除了你点它，桌宠还会在 DSH 被晾到后台的时候自己动手：见下面「切到别的应用就收起」。

**右键菜单。** **右键点桌宠**弹出插件唯一的菜单（桌宠不再有自己的托盘图标：DSH 主进程已经常驻一个，这个挂件不该再占一个）。菜单是白色圆角卡片，使用细线图标、柔和阴影与克制的悬停底色，并在「系统」子菜单前放一条分隔线；系统仍负责把菜单留在工作区内，点到外面或按 Escape 就会关闭。前四项由页面执行，接着是桌宠自己按快门，会自己起东西的能力收在**特殊功能**子菜单里，**设置**收在分隔线之上的最后一格。菜单里**没有任何窗口类条目**：收起/恢复 DSH 靠单击桌宠（以及 DSH 自己的托盘图标），桌宠的位置只靠拖动改变。第一项是**对话**：它先把 DSH 放回屏幕并置顶（收起、最小化、或只是被别的窗口盖住都算），再打开 <https://chat.deepseek.com>。**打开位置跟着设置里的「网页链接默认打开方式」**（设置 → 通用，正是 DSH 处理对话里 chat 链接用的那一项）：选**应用内侧边栏**时开在 DSH 自己的**右侧 Browser 标签**里，选**默认浏览器**时交给系统浏览器。第二项是**常用网站**：它是个子菜单，自己什么都不开，展开后逐条列出设置里配置的网站（见上面「调节大小与虚化」里的**常用网站**与下面的 `sites` 字段）——备注是条目的名字，鼠标停上去显示网址。点任意一条都像**对话**那样先把 DSH 放回屏幕，再按**同一个偏好**打开那个地址；**列表为空时**子菜单里写一句「还没有常用网站，先去设置里添加」，最下面一格**管理常用网站**就是**设置**那条命令，把插件页翻到本插件那张卡片。列表由宿主随状态文件发布、桌宠每次展开时重建，所以在卡片里改完不用重启任何一边。地址只支持 http/https（不写协议的补 `https://`），带用户名密码的、以及 `file:`／`javascript:` 一类都会被宿主挡在菜单之外。**登录状态**在偏好把这两项送进应用内标签时，跟着那个 Browser 分区按**工作区**保留：在那里登录一次之后，重启 DSH 与重新 build 都不用再登（见「已知限制」里的说明）；选**默认浏览器**时，登录状态归那个浏览器自己的 profile 管。第三项是 **Git 改动**：同样先把 DSH 放回屏幕，然后在右侧栏打开插件自己的 **Git 页**（见下），左边是当前会话工作目录里**未提交的改动**（含新增、未跟踪的文件），右边是**提交历史**（先显示最近十条，滑到底接着往下读，还能按作者筛选），双击任意一行看它背后的详情（左栏是那个文件的 diff，右栏是那次提交涉及的文件）。先放回窗口是必须的：标签页开在一个看不见的窗口里等于没开。第四项是**打开工作目录**：它把当前会话的工作目录交给宿主，由宿主用 `explorer.exe` 打开——页面知道是哪个目录却没有进程，宿主有进程却不知道是哪个，所以两边各出一半（见下面「打开工作目录」）。它**不**先把 DSH 放回屏幕：要看的是那个文件夹，资源管理器自己会到前台。第五项是**截图**，这一项完全由桌宠自己完成、不写任何命令；最后一项是**设置**，也是唯一一项关于插件本身、而不是关于当前会话的：它像**对话**那样先把窗口放回来，然后让**插件**页翻到本插件那张卡片——就是插件列表里那张卡片，大小、虚化、打盹、截图存放位置、点击行为都在上面。那一页属于插件管理器，所以这是**跨插件导航**，走的是那一页提供的服务（`ctx.pluginNavigation.openBundle`），不是本插件自己的路由；桌宠只负责点名，剩下的是页面的事。**小游戏**同样收在一层子菜单里：它自己什么都不开，展开后是这一层的第一款——**玻璃鱼缸**，把另一个插件（3D 玻璃鱼缸）的全屏 WebGL 浮层打开。它也先把 DSH 放回屏幕（浮层开在看不见的窗口里等于没开），然后把 `aquarium` 交给页面；页面取的是那个插件提供的服务（`ctx.get('aquarium3d')`），没装那个插件时只记一条警告，不会开出一块空白。以后再加小游戏只往这个子菜单里加一行，不动菜单的形状。**听歌**是第三个子菜单，也是唯一由桌宠自己执行的一项：它排在**小游戏**与**截图**之间，条目每次展开都按宿主发布的曲库重建，点击后在自己的进程里干活、不经过页面，所以 DSH 收起后歌照样放。展开后第一行是灰色状态：**正在播放：<歌名>**、**已暂停：<歌名>**、还没开始时的**待播放：<歌名>**、放不出来时的**播放失败：<原因>**、一首都没下好时的**还没有下载好的歌曲**，以及一首都没下好但还有链接等着时的**<N> 首还没下载**；接着是**开始**／**暂停**（按当前状态显示其中一个）、**换歌**（下一首）与**上一首**；补全进行中时这一组只剩一行灰色的**正在补全：<done>/<total>**；再往下是缺文件时的**补全缺失歌曲（<N> 首）**，一个都不缺时是灰掉的**歌曲都已下载**；然后是**打开音乐文件夹**，交给宿主用资源管理器打开；最后是**设置**，和主菜单里那条**设置**是同一条命令——先把 DSH 放回屏幕，再把插件页翻到本插件那张卡片。**特殊功能**排在截图与**设置**之间，和**小游戏**一样自己不打开任何东西：会自己起东西的功能都收在这一层，以后再加一项也不必动菜单的形状。里面第一项是**多机协同**，这个子菜单每次展开都按宿主的状态整段重建——一行灰色状态：**未启动**、**主机端 · 等待另一台电脑**、**主机端 · 已连接**（连上后带上往返毫秒数，主机端处于远程模式时再缀上**远程模式**）、**被控端 · 已连接**、或**被控端 · 重连中**；一行灰色主机端地址，一行灰色切换热键；一条分隔线；然后是**启动并连接**或**停止**（当前在跑就显示后者）；最后是**设置**，把插件页翻到本插件那张卡片。分隔线下面是**系统**子菜单，展开后依次是三项：**更新 DSH**（构建当前工作副本，成功后自动重启，见下）、**重启 DSH**（先确认，然后结束 DSH 并把它照原样再拉起来，见下）与**退出 DSH**——它会先弹一个确认框（退出会打断正在跑的任务），确认后**直接结束 DSH 的 Electron 主进程**。这条以前是给主窗口发 `WM_CLOSE`（和点标题栏的 X 同一条路），但桌面端现在把「关闭窗口」改成了**隐藏到托盘**——点 X 也只是收起来——那条路于是不通了。主进程一退，宿主子进程会收到 IPC 断开并**走它自己的优雅收尾**（会话落盘、agent 停止），这次收尾会卸载插件，插件的清理再把桌宠一起关掉；另有定时器兜底（发现宿主没了就自行退出）。菜单项由桌宠进程画，动作由页面执行，两边通过宿主转交；页面那边没有 Browser 标签可用（比如网页版默认关掉了它）时，**对话**与**常用网站**会按上面的偏好回落到系统浏览器，并记一条警告说明回落原因，不会报错——**Git 改动**不依赖任何自带标签页，只要有右侧栏就能开。**桌宠自己不在菜单里退出**：它的生死只由设置里的「启用桌宠」控制，否则菜单里的退出会绕过那个开关。

**Git 页。** 菜单里的 **Git 改动**在右侧栏开一页，分成左右两栏，各自滚动；侧边栏窄到放不下两栏时改成上下两格，两格平分高度，也各自滚动：

- **左栏「未提交的改动」**：`git status --porcelain` 的全部条目——已暂存、未暂存、以及**未跟踪的新文件**（`-uall`，所以新目录里的文件会逐个列出，不会被折叠成目录名）。每行是状态词（新增 / 修改 / 删除 / 重命名 / 复制 / 冲突 / 类型变更）、路径，已进索引的那几行还带一个「已暂存」标记；
- **右栏「最近提交」**：这个仓库的提交历史，每条三行——**提交信息**（换行显示完整标题，不再被截断）、**短哈希**、作者 · 本地时间。开头是最近 `10` 条，滑到列表底部就自动接着读下一批 `10` 条（列表末尾那行也可以直接点，读的是同一页），一直读到仓库的开头为止；读取中、失败、以及这个仓库读不了，都会在那一行就地说明，失败时那一行变成**重试**。
- **右栏标题下的「按作者筛选」**：下拉里是这个历史里出现过的每个作者，连同各自的提交数（同名不同邮箱的两个身份在悬停时用完整地址区分）。选中之后整栏只剩这个作者的提交，同样是一批 `10` 条往下读；选回**全部作者**就回到全部历史。换了仓库、或者新读到的历史里没有这个作者时，筛选自动落回**全部作者**。

**双击任意一行**，两栏整块让给那一行背后的东西（顶部一律是**返回**按钮，回到原来的两栏）：

- **左栏的一行**（一个未提交的文件）给的是**这一个文件的 diff**：状态词与完整路径在标题行，正文 `+` 绿、`-` 红、`@@` 蓝、文件头与 `index` 一类灰，不换行、可以横向滚动。超过 20 万字符的 diff 只发开头一段，并在正文第一行说明它被截断了；已跟踪文件的改动按它在索引与工作区各占哪一侧分别比较（两侧都有改动就上下各一段），未跟踪的新文件则与空文件相比，所以刚加进来的文件也有 diff 可看——不拿 `HEAD` 当比较对象，第一次提交都还没做的仓库照样能看。
- **右栏的一行**（一次提交）给的是**这次提交涉及的文件**：标题行是提交信息、文件个数、短哈希，下面每个文件一行——状态词（新增 / 修改 / 删除 / 重命名 / 复制 / 类型变更）加路径，重命名把原来的路径用「← 原路径」标在同一行（是一次移动而不是删一个加一个）。合并提交按**第一父提交**比，所以看到的是这次合并带进来的东西，而不是空列表；空提交（没有改任何文件）就写一句说明。

打开详情期间：**刷新**重读的是当前这个详情（不会把你弹回列表），换一个会话或换工作目录则回到列表。行悬停会高亮，鼠标停在行上会提示这一行的双击能做什么。

顶部一行是仓库根目录、当前分支、**刷新**、**拉取**和**提交并推送**。**最近提交**旁的状态标签会联系当前分支配置的上游，显示**已是最新**、有多少提交待拉取、历史是否已经分叉，或无法判断是否最新的原因。打开页面和点**刷新**都会重新检查；检查只更新这个分支的远端跟踪引用，不移动本地分支、暂存区或工作树。**拉取**执行 `git pull --ff-only`，成功后用最新仓库状态替换列表。detached HEAD、当前分支没有上游时会直接拒绝；认证失败、超时或历史已经分叉时保留原列表并显示原因。页面不会暂存、提交、推送、撤销或自动创建合并提交，双击任意一行也只是让宿主再读一次它背后的 diff 或文件列表。仓库由**当前会话的工作目录**决定，不是某个配置项——在哪个项目里对话，就看哪个项目的改动；所以从子目录开的会话照样显示整个仓库。工作目录不是 Git 仓库、目录已经不在、机器上没有 `git`，各自显示一句说明，此时操作按钮置灰；空仓库（还没有第一次提交）是正常状态，两栏都显示「（还）没有」。

**「提交并推送」按钮。** 它做的不是 Git 操作，而是**替你说话**：把「审查本地改动，没有问题就提交并推送吧」作为一条**真正的用户消息**发进当前对话——和你在输入框里手打这句话再回车走的是同一条宿主通道（`ctx.conversation.send`，排队的一轮）。按钮上仍写「提交并推送」这个短标签，发出去的是整句话（`COMMIT_AND_PUSH_PROMPT`）。所以这条消息会出现在对话里、进会话记录、模型看得见；agent 正在跑就排到下一轮，空闲时立刻开始这一轮，然后它先审查本地改动，只在没有发现问题时才用自己惯常的工具去 `git add/commit/push`，提交信息按仓库的约定写。按钮点完就地变成「已发送」（本轮正在跑时是「已排队」），发不出去时就在下面显示原因（这个会话当前没有输入通道，或者宿主拒绝了这次发送）。**没有二次确认**：点一下就等于你要求了这次审查，以及审查通过后的提交与推送。

**打开工作目录。** 菜单里**打开工作目录**这一项把当前会话的工作目录交给宿主，由宿主起一个 `explorer.exe` 打开那个文件夹，和你在地址栏里粘一条路径回车得到的是同一个窗口。它和 Git 页看的是**同一个目录**（页面从 `sessions` 列表里取**主视图持有的那个会话**的 `cwd`，就是 DSH 会话标题栏那个「在工作区中打开」用的同一个来源），区别只在最后一步由谁做：页面没有进程，宿主没有「当前会话」这个概念，所以页面在 `POST /api/little-icon/open?cwd=…` 上点名目录，宿主去开。这一项**不会**先把 DSH 放回屏幕——你要看的是那个文件夹，资源管理器自己会到前台。

失败时说话的是**桌宠**：宿主把「上一回没打开」连同时间戳写进状态文件（`notice: { at, reason }`，`reason` 是 `no-cwd`／`no-dir`／`failed`），桌宠读到比自己显示过的更新的一条，就弹一句说明——目录已经不在、这个会话还没有工作目录、或者没能打开。之所以绕这一圈，是因为**点下去的是桌宠**：宿主那一路的失败写在日志里没人看，而「点了没反应」会被当成菜单坏了。时间戳让同一个失败只弹一次——`at` 不变就不重复，而它一直躺在状态文件里也无妨，内容不变就不会多写盘。**宿主不替你验证目录以外的东西**：是不是 Git 仓库无所谓，能打开就打开。

**截图。** 菜单里**截图**是唯一一件完全用不到 DSH 的事：区域是拖在桌面上的、不在任何窗口里，所以由桌宠把每块屏幕压暗、自己画选区、自己按快门。那块遮罩是桌宠自己的置顶窗口，盖住整个**虚拟屏幕**（所以选区可以横跨显示器），而窗口的 region 把选区挖掉——那个洞是**实况**，看到的正是文件里会有的东西，不是示意图；洞的四周有边框，上方写着像素尺寸。松开左键就把这个矩形存成 `shot-<时间戳>.png`（名字里带毫秒，同一秒里的两次截图不会互相覆盖），放在**截图存放位置**这项设置指定的文件夹里——设置留空时就是插件自己的 `$DSH_HOME/little-icon/shots/`，也就是默认值——并把**图片本身**放进剪贴板；没拖动的那一次点击、右键、以及 Escape 三条路都什么都不写、也什么都不说。剪贴板上只有图片这一种格式：认图片的目标（别的聊天窗口、文档、以及 DSH 自己的输入框——它的粘贴入口会把图片直接收成草稿附件）拿到图片，只认文本的目标什么也拿不到，而不是拿到一个还得自己去打开的路径——文件落在哪儿由桌宠上方那句提示来说。图片是**压进剪贴板**而不是留个引用，所以桌宠退出后照样能粘。成功后桌宠会在自己上方把落点说一句、几秒后消失；真的存不下来时，用和「没打开文件夹」同一种说明框把原因讲出来。遮罩用 **WinForms** 画而不是桌宠自己的 WPF，是因为 WinForms 的坐标始终是物理像素——也就是 `Screen` 和 `CopyFromScreen` 用的单位；WPF 的设备无关单位在非 100% 缩放下会和快门对不上，这正是桌宠自己的窗口位置靠「一直待在 WPF 单位里」绕开的那个坑。截到的东西就是选区里当时显示的东西，选区盖住桌宠时桌宠也在图里。

**听歌。** 音频由**桌宠自己的进程**用 WPF 的 `MediaPlayer` 播放本地文件，不是页面里的 `<audio>`：桌宠窗口在 DSH 收起后依然留在桌面上，音乐因此也留着。宿主下载的是 B站 的 `30280` 流（约 192 kbps 的 AAC，容器是 m4a），边下边写、不做转码。**链接是配置、文件不是**：地址存在 `musicLinks` 字段里，由和其它设置同一套机制抄进仓库的 [../../settings/pet-settings.yml](../../settings/pet-settings.yml)，所以**仓库里只有链接、没有音频**；文件下载到 `musicDir`（默认 `$DSH_HOME/little-icon/music/`，`~` 与相对路径按用户目录解析），`$DSH_HOME/little-icon/music-index.json` 记下 id→文件名。把目录指到仓库里不会被照用：这一项被忽略、改用默认目录，卡片会说明原因，发布进 `music.json` 的曲库也带一条 `inside-checkout` 警告。卡片上的**听歌**那一块是干活的一头：一条链接一行——有文件就显示标题 + **已下载** + 删除，没有文件就显示链接本身 + **未下载**（上次失败显示**下载失败**）+ 删除；粘贴框 + **添加**会写进 `musicLinks` 并立刻下载（重复链接直接提示「这条链接已经在列表里了」，标题重复由宿主按视频 id 判重，所以同一个视频的两条地址不会都进去）；还有**补全缺失（N 首）**与 `共 N 首可用`，本机有文件但没有对应链接的会单列一段（多半是删链接后留下的文件），可以在那一段里删文件。再下面是**正在播放：<歌名>** 与播放/暂停/上一首/下一首四个按钮，它们把命令写进 `music.json`，由桌宠去执行。删除正在播放的文件会被拒绝并提示「文件正在被桌宠播放，先换一首再删」；改音乐目录**不会**搬走已下载的文件，要去新目录重新补全。**换机一键补全**：另一台机器 `git pull` 后链接随 `pet-settings.yml` 合进 profile 配置、文件不在本机，于是菜单里出现**补全缺失歌曲（N 首）**、设置卡里出现**补全缺失（N 首）**；点一次就顺序下载全部缺失（每次之间停 400ms），失败的链接会被报告（`video`／`audio`／`network`／`unrecognized`／`no-audio`／`write`），不打断其余下载，再次点击只重试仍然缺失的；下载完成后桌宠上方弹一句**补全完成：新增 N 首，失败 M 首**。**重启能接着放**：桌宠按 `music-player.json` 恢复上次那首歌与播放位置，上次在放就继续放；页面上的命令带时间戳，重启不会重放。**菜单里也能改**：桌宠的**听歌**子菜单里有**音量（N%）**（父项写着当前音量，子菜单第一行是**滑条 + 右侧数字**：拖动立刻变响，松手后才写进配置，所以拖一次只写一次设置；下面是 0/25/50/75/100 五个预设，点它们就是移动同一条滑条）与**添加 B站链接…**（弹出一个小输入框，默认填剪贴板里的那一条）。**这两项都是配置，所以由页面执行**，和卡片写的是同一套：设置服务拒绝任何发生在 HMR 事务里的写入，而宿主定时器就跑在「加载它的那次事务」的上下文里，所以这两条命令走的是菜单里其它「会改东西的条目」同一条流。宿主仍然先判它能判的（链接认不出视频、视频已在列表里）再转发，并下载页面加进来的那一条。**一条链接就是一个集合。** 带 `?p=N` 的链接只算那一 P；不带 P 的视频链接代表这个视频里的全部内容——分P 视频的每一 P，或它所属合集的每一集——所以粘一条地址就能一次加进一百首歌。**加入不等于下载**：集合先写进 `musicLinks`，真正开始下载的是**补全缺失（N 首）**，因为一百个文件的下载应该是一次决定，而不是粘贴的副作用。**长列表仍然好看**：同一个视频的各个 P 折叠成它所属的那一组——一行写着视频标题、`N 首 · 已下载 M 首`，一个展开/收起按钮，以及一个**整组删除**按钮（连本机文件一起删），不必点一百次；单首仍然就是一行。

**多机协同。** 「**特殊功能**」子菜单里的**多机协同**让两台电脑共用一套键鼠：由插件拉起自带的 `bin/MouseShare.exe`（由 `_mytools/MouseShare/build.bat` 编译后同步过来），让它当本机的主机端或被控端；这个子进程随 DSH 退出而结束，不会留下监听端口和全局键鼠钩子。**哪台当哪一端不用配置**：两台共用同一份设置，网卡地址与地址里的 IP 相同的那台就是主机端、按地址里的端口监听，另一台是被控端、主动连过来。所以连接方向是**被控端连主机端**，每 3 秒重试一次——两边谁先点「多机协同」都行，两台不在同一网段、隔着 NAT 也能用。三项设置就在卡片上**截图存放位置**下面：**主机端地址**（默认 `192.168.1.3:15180`，主机 IP 变了只改这一处）、**切换热键**（默认 `ctrl+alt+f12`），以及**DSH 启动时自动启用**（默认打开，DSH 一起来就按这个地址把链路拉起来，不必再点菜单——而**从菜单里停掉**的链路不会被别的设置写入重新拉起，要等下次 DSH 启动，和「启用桌宠」同一个规则）。热键只是备用，**鼠标平时自己就过去了**：对端在本机左侧，所以光标碰到本屏**左边缘**就交过去（远端光标从它自己的右边缘进来，看起来是一次连续移动），在对端把光标推过**右边缘**就交回来、落在本屏左边缘。屏幕最上/最下一条与「按住鼠标键」期间都不参与，所以点开始菜单、扫过角落、把窗口拖到边缘都不会换机器。远程模式下本机光标会停在原地不动（事件被主机端接管）。

**配置字段。** 下面是宿主 schema 的全部字段；插件卡片负责桌宠控件，`gitPullTimeoutMs` 只在 profile 配置中修改。全部即时生效，不需要重启：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关掉会结束桌宠进程；再打开会重新拉起 |
| `size` | `160` | 窗口边长（像素），素材按 256 像素生成，缩小显示 |
| `translucent` | `true` | 指针不在桌宠上时是否虚化 |
| `idleOpacity` | `0.45` | 虚化到什么程度；悬停恒为 1。`translucent` 关掉时它被忽略 |
| `frameMs` | `600` | 每帧停留毫秒数 |
| `pollMs` | `800` | 宿主采样间隔；改小更跟手，改大更省 |
| `happyMs` | `3000` | 一轮活干完后「开心」保持多久，然后回到待机 |
| `boredEverySeconds` | `60` | 没有任务在跑时，每隔这么久插一次「无聊」 |
| `boredMs` | `5000` | 每次「无聊」持续多久 |
| `sleepAfterSeconds` | `600` | DSH 显示着时，无操作多久「打盹」 |
| `sleepWhenHiddenSeconds` | `20` | 收起 DSH 后，多久「打盹」（此时只有拖动桌宠算操作） |
| `autoHide` | `true` | DSH 在前面时永不自动收起；切到别的应用后是否自动把它收起 |
| `autoHideSeconds` | `0` | 切到别的应用后隔多久才收起；`0` 就是立刻。任务在跑也照收 |
| `topmost` | `true` | 是否始终置顶 |
| `clickAction` | `toggle` | `toggle` / `minimize` / `none` |
| `gitPullTimeoutMs` | `60000` | 检查上游与拉取的超时毫秒数，可设为 `1000`–`300000`；自定义设置卡没有这个控件，可在 profile 配置里修改 |

| `musicLinks` | `[]` | 「听歌」曲库所依据的 B站链接，按桌宠播放顺序排列。同一套机制会把这个字段抄进仓库的 `pet-settings.yml`，所以仓库里只有链接、没有音频；卡片上有对应的粘贴框与列表 |

**拉取行为。** `POST /api/little-icon/git/pull?cwd=<会话工作目录>` 会确定仓库与上游，然后在禁止凭据交互提示的环境中执行 `git pull --ff-only`。同一仓库的并发请求会共用一次正在进行的拉取，不会争抢 Git 锁。成功响应带回刷新后的改动、提交和 `HEAD` 是否移动；失败则保留页面原有状态。Git 子进程不会继承名称包含 `KEY`、`SECRET`、`TOKEN` 或 `PASSWORD` 的环境变量。

**表情与状态的对应。** 一轮任务读起来是：开始就直接 `working`（干活中，不再先惊讶）→ 需要你抉择时 `alert`（惊讶，一直举着直到你回答）→ 结束后 `happy`（开心）→ `idle`（待机）。

- **听歌表情**不是采样出来的，而是叠在采样结果之上：音频由桌宠自己播，所以「正在播」这个输入来自它——播歌时听歌表情（`music`）会顶掉待机那一族（`idle`、`bored`、`sleep`），而一轮任务自己的那几张脸（`working`、`alert`，以及结束时的 `happy` 庆祝）保持不变；暂停或停止立刻回到采样结果。
- **无聊**跟着「有没有任务在跑」走，不看鼠标：没有任务时每隔 `boredEverySeconds` 插一段 `boredMs` 的「无聊」，所以读长回复时也会偶尔看到；一旦有操作，当前这段无聊立刻结束。
- **打盹**跟着「有没有操作」走，而且分两种计时：DSH 显示着时用 `sleepAfterSeconds`，操作包括鼠标、滚轮、键盘在 DSH 页面上的动作、拖动桌宠、单击桌宠；**收起 DSH 之后**改用 `sleepWhenHiddenSeconds`（默认 20 秒），此时唯一可能的操作就是拖动桌宠，或者点桌宠把 DSH 放回来。两种情况下一有操作都立刻醒来回到待机。
- **等你抉择时举着「惊讶」**：模型给你出选项、或者等一次审批时，桌宠切到 `alert`（惊讶）并**一直举着**，直到你回答——这就是「该你了」的信号，DSH 被收起时也能从桌宠看出来。宿主旁听 `user-questions/request` 与 `approval/request` 这两条 waterfall（只观察、照常 `next()` 委派），把「在等用户回答」的 agent 记下来；这期间它不算「干活中」，也不会打盹，因为真正在等的是你。你答完它继续干活，直接回到 `working`（不再先惊讶一次）。排在同一个 agent 后面的输入同样不算忙碌，因为那也要等你先回答。
- **切到别的应用就收起**（`autoHide`，默认开）看的是**前台是谁**，不是「有没有操作」：DSH 自己在最前面时永不自动收起——读长回复、想事情都不再打断你；一旦别的应用跑到前面（你去用编辑器、浏览器），桌宠就把 DSH 收起，`autoHideSeconds`（默认 0）是切到后台之后的宽限时间，0 就是下一拍就收。**不看有没有任务在跑**：任务继续跑，窗口先收起来。只有 DSH 还显示在屏幕上时才有这一步，最小化或已经收起时不动。DSH 自己的对话框、更新提示，以及桌宠自己的窗口都算「DSH 在这边」，所以拖动桌宠不会把 DSH 收掉。要把它放回来：点桌宠（或 DSH 自己的托盘图标），放回来的同时它会重新成为前台，于是不会立刻又被收起。

桌宠把「DSH 现在在不在屏幕上」和「在不在前台」（前台是不是 DSH 自己那一侧：它的主窗口、它的对话框，或桌宠）写进 `window.json`；前者决定用哪条打盹计时，后者决定要不要自动收起，两者变化本身也算一次操作。每套表情都是四帧循环。

本机数据写在 `$DSH_HOME/little-icon/`：`state.json`（宿主写、桌宠读；除了表情、尺寸这类状态，还捎带一条 `notice`——「上一回打开工作目录没打开」及其时间戳、截图要去的绝对路径 `shotDir`（设置留空时没有这个字段），以及菜单要列出的网站 `sites`）、`position.json`（桌宠写的位置）、`window.json`（桌宠写的「DSH 在不在屏幕上、在不在前台」）、`command.json`（桌宠写的右键菜单选择，宿主读走后转交给页面）、`shots/`（菜单里**截图**存下的 PNG，一次一张、按时间命名；`shotDir` 设置把它们挪走时这里就空着）、`music.json`（宿主写、桌宠读：每首曲目的绝对路径、音量、还缺几首、补全进度，以及给桌宠的命令与提示）、`music-player.json`（桌宠写：在放什么、进度毫秒、已经套用过的命令时间戳，宿主读它给设置卡看）、`music-index.json`（本机的 id→文件名索引）、`music/`（音频文件本身）与 `quit`（宿主写的「请你退出」，桌宠读到就存好位置、按顺序关掉自己的窗口再退出，退出时把它删掉）。它们按机器独立，不随仓库同步，删掉即回到默认位置与默认状态；**设置**不在这个目录里——桌宠那一行由 [../../settings/pet-settings.yml](../../settings/pet-settings.yml) 跟着 git 走，Desktop 的快捷键文档在它的 userData 里、由 [../../settings/keybindings.json](../../settings/keybindings.json) 跟着 git 走，两份都由 `build\start-desktop.bat`（或桌宠菜单里的重启）写回每台机器。

**浏览器半边。** `client.js` 做四件事。一是把手写设置卡片注册进 `plugins.bundle.config`（插件页给「某个 bundle 自己的配置」留的位置），键是包名 `@local/dsh-little-icon`——卡片就画在插件列表里那张卡片的详情页上，比藏在 `little-icon` 行页面里少一次点击。卡片不直接读配置：`ctx.configForms.get('little-icon')` 拿到该行的表单，订阅它、把接受的 section 折进一个快照 store，再经注册的 `inject` 面（`hooks.petSettings` 钩子 + `write` 回调）交给组件；值的唯一拥有者仍是宿主 schema。滑块拖动时先本地回显、停手 250 毫秒合并成一次写入，开关与下拉立即写，而**截图存放位置**是个文本框：打字时只本地回显、离开输入框才写一次——每敲一个字符写一次 profile 就是一条路径写几十次。它旁边的**浏览**按钮用工作区面板同一个目录选择器填空（`ctx.get('uiWorkspace')?.pickDirectory()`，同样是现取而不是注入，这个构建没有选择器时就答「没有」），选择器被取消则什么都不改。宿主侧因此调用 `settings.configure({ auto: false })`，避免同一批字段出现第二份自动生成的英文表单。二是活动上报（上面那段）。三是执行桌宠的右键菜单命令：它 `new EventSource('/api/little-icon/commands')` 订阅宿主那条流，收到 `chat` 与 `site` 就去开地址，而**开在哪里读的是偏好而不是本插件的常量**：`ctx.configForms.get('ui-chat')` 的 `linkOpening`，正是 `ui-chat` 处理对话里链接时读的那个值——`sidebar` 且这个构建有 Browser 标签时走 `ctx.sidebarRight.openTab('browser', { params: { url } })`（插件在 DSH 内开站点的入口），其余一律交给 `window.open`，桌面端的主进程把它转成系统浏览器。值在**点击那一刻**才读、不做镜像，所以在 Chat 的设置页改完，下一次点菜单就生效。同一条流上的 `site` 走同一条路，只是地址来自帧里：**设置里配的那些网站**。地址在这一路上经过三个地方——桌宠写进 `command.json`、宿主读出来转发、页面开标签之前——宿主与页面各自都按「只许 http/https、不许带用户名密码」验一次（宿主验不过就不把 `url` 放进帧；页面收到没有地址的 `site` 就只记一条警告），所以菜单里绝不会出现一条点了什么都不开的条目。`sidebarRight` 与 `sidebarRightTabs` 都用 `ctx.get` 现取而不是声明注入（Web profile 可能没启用 browser 类型，没有右侧栏的构建连服务都没有），取不到时偏好仍指着应用内侧边栏，于是地址回落到系统浏览器并记一条 `console.warn` 说明原因：这张设置卡片在任何 profile 都得照常加载。同一条流上的 `open-cwd` 是另一种：它从 `sessions` 列表里取**主视图持有的那个会话**的 `cwd`（DSH 自己的「在工作区中打开」读的也是这一行），`POST` 给 `/api/little-icon/open` 之后就不再插手——开文件夹的是宿主，失败时说话的是桌宠。`settings` 是第三种：本插件自己的东西一个都不打开，因为那张卡片画在插件管理器的页面上，所以命令走的是那一页的导航服务（`ctx.pluginNavigation.openBundle`）——和右侧栏一样用 `ctx.get` 现取，因为没有插件页的构建根本没有这个服务——取不到时只记一条 `console.warn`。还有 `aquarium`：它是唯一一项打开**别的插件**界面的命令，取 `ctx.get('aquarium3d')`（3D 玻璃鱼缸插件提供的服务）调它的 `open()`——桌宠只点名，鱼缸怎么画、画在哪儿都是那个插件的事；没装那个插件时同样只记一条警告。四是 **Git 页**：`git` 命令调用 `openTab('little-icon-git')`，而这个页类型正是插件自己按右侧栏的两段式注册进去的——`ctx.sidebarRightTabs.register({ id, kind, title })` 提供「这个类型是什么」，再往 keyed 槽 `sidebar.right.pane.tab` 注册键为同一个 `id` 的组件提供页面主体。注册表本来就允许仓库外的插件注册类型，所以这一页既不依赖 Browser 标签，也不依赖任何自带查看器；整段挂在 `ctx.inject(['sidebarRightTabs', 'slots'], …)` 上，没有右侧栏的构建根本不会执行，设置卡片照常存在。组件里不读文件：`inject` 面给出三个读回调——`load(cwd, signal)` 拉仓库列表，`loadDiff(root, path, signal)` 拉一个文件的 diff，`loadCommit(root, hash, signal)` 拉一次提交的文件列表（后两个带的是仓库根而不是会话目录，因为列表给的路径是相对根的；至于跟哪一侧比、要不要按第一父提交比，都由宿主自己查、自己定），`useSessions` 提供当前会话的工作目录，`useTabInfo` 提供这次导航的 `revision`——所以再点一次菜单（同一个标签页被重新导航）就会重新拉一次，和「刷新」按钮走的是同一条路。打开某一行的详情只是组件里的一个状态：`detail` 有值时两栏被它顶掉（按 `kind` 决定画 diff 还是文件列表，标题行也各画各的），返回按钮把它置回 `undefined`，所以列表不用重新拉一遍。同一个面里的 `sendPrompt(text)` 就是**提交并推送**按钮调用的东西：它借当前会话自己的作用域拿到 `ctx.conversation.send`——也就是输入框用的那条 admission，不是另开一条私路；会话没被保留时取不到作用域，就回 `no-channel`。文案都走 `ctx.locale` 字典（中英各一份）；`tests/smoke.mjs` 会断言两边键一致、页面用到的键都存在，驱动一次开关写入与一次拖动合并，压一次「打字不写、离开才写」的路径框与「选完就写、取消不改」的选择器，断言活动上报确实注册了那四个监听器且被节流，并驱动一次 `chat` 命令（含没有 Browser 标签、没有 Sidebar 服务两种取不到的情况）、一次 `git` 命令、一次 `open-cwd`（主视图持有的会话、没有主视图会话、没有 `sessions` 服务三种）、一次 `settings`（有、没有导航服务两种）与一次注销后的 `EventSource.close()`，再拿造好的仓库状态渲染一次 Git 页，断言两栏、状态词、暂存标记、分支、四种「读不到」的说明都在，并点一次**提交并推送**验证那句话原样进了会话、以及三种发不出去的情况；还分别渲染「某个文件的 diff 已打开」「某次提交的文件已打开」两种详情，断言两栏确实被换掉、返回按钮、每行的着色与状态词、重命名的「← 原路径」、文件个数，以及空 diff、空提交、截断、读失败这几种状态。

**为什么必须是独立进程。** 桌面壳没有向插件开放任何窗口能力：`apps/desktop` 里没有 `Tray`，主窗口的 `BrowserWindow` 也没有 `transparent`/`alwaysOnTop`/`skipTaskbar`；`apps/desktop/src/ipc.ts` 的通道表里没有最小化/隐藏/恢复，`preload-app.ts` 只暴露 `dshDesktop`（浏览器视图与更新）、`dshPlatform`（仅用量/充值内嵌页）、目录选择、宿主路径与语言。渲染进程是 `sandbox: true` + `contextIsolation: true`，`window.open` 一律被拒。更关键的是插件的宿主代码跑在 `ELECTRON_RUN_AS_NODE=1` 的 Node 子进程里（`apps/desktop/src/host-process.ts` + `node-environment.ts`），那里 `require('electron')` 只能拿到二进制路径。窗口一旦隐藏，窗口内的 DOM 也不再绘制。所以「收起 DSH 后桌宠还在」只能靠插件自己起一个进程。

**打开工作目录路由。** `POST /api/little-icon/open?cwd=<会话工作目录>` 是这里唯一带副作用的接口，所以也是唯一不接受 GET 的动作：重新读一遍列表不该弹出文件夹。它先看目录本身——`cwd` 为空回 `no-cwd`，`statSync` 说不存在或不是目录回 `no-dir`——不让资源管理器自己去撞：它撞上一条不存在的路径会开成别的文件夹或弹出它自己的对话框，那读起来不像「拒绝」，像「开错了」。都过了才 `spawn('explorer.exe', [目录], { detached: true, stdio: 'ignore' })` 并 `unref()`；`spawn` 的失败在回答之后才到，所以挂了 `error` 监听记日志（没人监听的话，未捕获的 `error` 事件会带走整个宿主）。三种失败原因（`no-cwd`／`no-dir`／`failed`）除了回给页面，还连同时间戳写成 `notice: { at, reason }` 发布进状态文件——**点下去的是桌宠**，能说话的是它；`at` 让它只弹一次，而这条通知不变就不会多写盘。`tests/smoke.mjs` 用一个 `enabled: false` 的宿主实例压这条路由（不拉起真桌宠，所以谁的桌面上都不会多一个文件夹窗口或消息框）：GET 回 405、两种拒绝的原话，以及 `notice` 确实进了 `state.json`；成功那一步用在注入的启动函数上单独压 `openWorkingDirectory`。**桌宠为什么不算 inbox。** 一条等在 inbox 里的消息是「还没人处理的输入」，不是「正在跑的活」：后台任务结算时 DSH 会把 `background job … finished` 注入到 owner 的 next-step，队列投递（`quiet`，或唤醒预算用尽）下它就停在那里等一个可能永远不来的 step。照 `update-tasks.ts` 那份判据（它问的是「现在停机会不会丢东西」）去算，桌宠就会在什么都没跑的时候一直显示**工作中**——这正是要修的那条：忙碌只看「有 agent 在生成」；job 与排队输入都只写进 `work`，不驱动表情。state.json 里因此多一个 `work: {agents, jobs, queued}`，卡住时看文件就知道是谁。


**宿主半边。** `index.js` 每 `pollMs` 采样一次：用 `ctx.get('agents')` 看是否有 agent 正在生成或跑工具（**job 不驱动表情**：每次工具调用的子进程都是一条 job，子进程活得比调用久时——留在后台的开发服务器、脱离进程树的帮手——它会一直是 `running`），再减去**正在等用户回答**的 agent：宿主在 `user-questions/request` 与 `approval/request` 两条 waterfall 上用 `prepend` 挂了观察者（自己照常 `next()` 委派，返回原 promise），请求挂起期间把该 agent 从忙碌里排除、并作为 `waiting` 交给状态机（于是桌宠举着 `alert` 而不是 `working`），回答落定即恢复——这样「模型在等你选」既不会被当成「还在干活」，也不会被漏看。状态机是纯函数 `sampleState`，`tests/smoke.mjs` 直接压它；它接收「有没有活」「最近一次操作」「现在该用哪个打盹计时器」三个输入——计时器由桌宠报告的窗口可见性决定（收起后用短的那条）。另一个纯函数 `shouldTuck` 决定「该不该收起 DSH」，它只看桌宠报来的窗口事实——窗口还在不在屏幕上、前台是不是别人、DSH 是什么时候转到后台的——再加上 `autoHide`/`autoHideSeconds`：**DSH 在前台时直接返回 false**（永不自动收起），**没有「有没有任务在跑」这个输入**（所以在后台时任务照跑、窗口照收）；采样结果写进 `$DSH_HOME/little-icon/state.json` 时把它的结果作为 `tuck` 一起发布。`tuck` 是一条命令而不是状态：桌宠收好后写回的 `dshVisible:false` 让宿主下一拍就把它关掉，期间重复发出的同一个请求也因为桌宠那边幂等而无害。内容变化才写盘，另外每 4 秒补写一次心跳，桌宠据此判断宿主是否还活着。写盘是「写临时文件再改名」，而 Windows 只要这个文件被任何进程打开着就拒绝改名——桌宠自己每 200 毫秒读一次 state.json 就会撞上——所以这里重试几次；仍然写不进去就保留上一份快照、记一条告警（同一段失败最多 30 秒报一次），等下一拍再写。异常绝不冒到定时器外面：宿主拿到未捕获异常会**直接退出整个进程**（2026-09-27 那次崩溃就是这句改名抛出的 EPERM），所以采样这一拍、以及设置变更时那次发布，都包在同一层 try 里。配置里的 `translucent` 与 `idleOpacity` 在这里合并成一个 `opacity` 字段，桌宠不需要知道这个开关。桌宠由 `child_process.spawn` 拉起（`powershell.exe -NoProfile -NonInteractive -STA -ExecutionPolicy Bypass -File pet/pet.ps1`），参数里带素材目录、状态与位置文件、以及要控制的窗口进程号；`ctx.effect` 的清理函数会结束它（先写 `quit` 请它自己存好位置、正常退出，1 秒不回答才强杀），DSH 不会留下孤儿窗口。桌面壳里宿主的父进程就是 Electron 主进程，所以这个进程号直接取自 `process.ppid`；网页版没有可控制的窗口，传 0。菜单命令走另一条路：桌宠把选择写进 `command.json`，宿主每拍读一次（`at` 严格递增才算新命令，所以上一轮留下的记录不会被重放），再经 `GET /api/little-icon/commands` 这条 SSE 流推给页面；`site` 这一条还带一个 `url`，宿主读出来时先按「只许 http/https、不许带用户名密码」验一遍才放进帧里——**这个文件是文件**，谁写的都算，而菜单要列出的那份 `sites` 也是在同一次采样里发的（打不开的行在这里就被丢掉，桌宠只画它拿到的）。流过与活动上报同样的 `connection.requestRejection` 检查，只回事件流本身（`text/event-stream`，先写一帧注释让订阅立刻成立），并在客户端断开或插件销毁时从订阅集合里摘掉、`end()` 掉。页面不在线时的命令直接丢掉——执行它的是页面，没有页面就没有可执行的对象。

**Git 路由。** Git 页要的仓库事实都在磁盘上，页面既没有文件系统也没有进程，所以由宿主去问 Git：`GET /api/little-icon/git?cwd=<会话工作目录>` 回一个 JSON。先 `statSync` 确认目录还在（**不能**靠 `execFile` 的 `ENOENT` 判断：目录不在和 `git` 不在可执行路径里，Node 报的是同一个错，而这两件事对用户的意思完全不同），再 `git rev-parse --show-toplevel` 定仓库根——由目录找仓库，而不是反过来，所以从子目录开的会话照样看到整个仓库。随后并发跑四条只读命令：`branch --show-current`（游离 HEAD 时为空，页面就不显示分支）、`status --porcelain=v1 -z --untracked-files=all`、取一页 `log`（`10` 条，多要一条来判断后面还有没有，格式用 `0x1f` 分隔字段），以及 `shortlog -sne HEAD`（这个历史里出现过的每个作者与各自的提交数，筛选下拉列的就是它）。`status` 与 `log` 两条输出都按 `-z` 解析：记录之间是 NUL（提交标题里的任何标点都不会撞上分隔符），而重命名/复制把**源路径**放在下一条记录里，所以解析要手动跨一格。仓库还没有第一次提交时 `git log` 会报错，那是正常状态，回空列表而不是失败。路由只接受 GET，永远回 200 JSON：目录不在、不是仓库、没有 git、命令失败，分别是 `no-dir` / `not-a-repo` / `no-git` / `failed` 四个 `reason`，由页面翻译成人话——**机器可读的原因，不是本地化文案**，页面才知道该用哪种语言。

**Git 远端路由。** `POST /api/little-icon/git/remote?root=<仓库根>` 会解析当前分支配置的远端、远端分支和远端跟踪引用，再用 `--no-tags --no-write-fetch-head` 只把这个分支抓取到它的跟踪引用。随后通过 `rev-list --left-right --count` 比较 `HEAD` 与更新后的引用，返回 `up-to-date`、`behind` 或 `diverged`，以及两侧各自的提交数。同一仓库、同一跟踪引用的并发检查共用一个请求；同一仓库的所有抓取与拉取则串行执行，避免争抢引用锁。这个路由使用 POST，是因为抓取会更新远端跟踪引用，虽然它不会移动本地分支、暂存区或工作树。不可用状态会区分游离 HEAD、当前分支没有上游、超时和 Git 命令失败。

**Git diff 路由。** 双击一行时页面再问一次宿主：`GET /api/little-icon/git/diff?root=<仓库根>&path=<一行里的路径>`（同样是 GET-only、同样永远 200 JSON，走的还是同一段守卫与同一个 `send` 出口）。同样先确认目录、`rev-parse --show-toplevel` 定仓库，好让「目录不在 / 不是仓库 / 没有 git」在这条路上得到和列表一样的说法。然后自己查这个路径的状态（`status --porcelain=v1 -z -uall --` 加 `:(literal)` 包住的路径，免得文件名里的 `*` 被当成通配），再只跑需要的比较：索引那一侧非空就 `diff --cached`，工作区那一侧非空就 `diff`，两侧都有就两段依次拼起来；`??` 的未跟踪文件用 `diff --no-index` 跟 `NUL`（Windows）或 `/dev/null` 比，它「有差异」时的退出码是 1，那是答案不是失败（stdout 照样有内容）。**不出现 `HEAD`**：还没有第一次提交的仓库里 `HEAD` 解析不了，而 `--cached` 那时正是拿索引跟空树比。每次调用都带 `--no-color --no-ext-diff`，免得用户配置里的颜色或外部 diff 程序把转义序列、别家输出塞进页面。拼好的文本超过 20 万字符就截断并回 `truncated: true`，由页面在正文第一行说明。这个路径在两次命令之间被提交掉、或被改回原样时，状态查询会回空，于是答案是一段空 diff（`{ok:true,text:''}`），页面说「这个文件没有可显示的差异」——这是正常状态，不是错误。

**Git 提交路由。** 双击右栏一行时问的是 `GET /api/little-icon/git/commit?root=<仓库根>&hash=<那一行的完整哈希>`，同样 GET-only、同样永远 200 JSON、同样先确认目录与仓库，所以三种「读不到」的说法也一致。提交没有工作区可比，改动路径来自 `diff-tree`：先 `rev-list --parents -n 1 <hash>` 问这一提交有没有父提交——**第一次提交没有**，那就用 `--root` 拿空树当另一侧（否则 `diff-tree` 对它一个文件都不列）；**合并提交有两个以上**，就取第一父提交与它相比（`diff-tree` 只给它自己时对合并同样什么都不列），页面因此显示的是这次合并带进来的文件。哈希不存在时 `rev-list` 会失败并带回 Git 的原话（`failed`）。输出按 `-z` 解析：每条记录先是状态、再是路径，`R100`/`C075` 这类重命名与复制是**唯一带两条路径**的，源在前、目标在后，页面把目标显示成路径、源显示成同一行的「← 原路径」。空提交回空列表，页面写一句「这次提交没有改动文件」。

**Git 提交分页路由。** 列表滑到底、或者选了某个作者时，页面问的是 `GET /api/little-icon/git/commits?cwd=<会话工作目录>&skip=<已经显示了几条>&author=<作者身份>`（GET-only、永远 200 JSON，走同一段守卫）。用**目录**而不是仓库根，是因为主机要像列表那次一样重新解析仓库：工作区在两页之间换了地方时，回答的是现在这里的仓库。`skip` 不是安全整数或小于 `0` 就当作 `0`；`author` 为空表示全部作者，否则必须是列表自己给出的那个身份字符串。这条路由跑的就是同一条 `log`（同样的字段分隔、同样多要一条、同样的 `--skip` 与 `-n`），只是多了个 `-F --author=<身份>`：**`-F` 是必须的**——`--author` 默认把自己的参数当基本正则读，而 `second+tag@example.test` 这样的地址在正则里是个量词，会匹配到别的提交或者干脆匹配不到。加 `-F` 之后它按字面串匹配，所以筛选比的是列表给出的那个身份本身。读过头（`--skip` 超出历史长度）得到的是空页而不是错误，页面于是知道没有更多了。

**音乐路由。** 卡片既列不了目录也够不到 B站，而桌宠自己的菜单必须在没有页面时也能用，所以两边的事都由宿主承担：`GET /api/little-icon/music` 回答曲库视图（本机的链接、已有文件的条目、音乐目录与它的警告、音量、补全进度，以及桌宠报上来的播放状态）；`POST /api/little-icon/music/sync` 在后台把缺失的链接一次性补起来，回答这次启动了几首；`POST /api/little-icon/music/download?url=` 下载一条，答完文件已经落地；`POST /api/little-icon/music/expand?url=` 回答一条链接代表的全部链接，以及其中设置里还没有的那些——所以合集是一次粘贴，而已经有的那首仍然只是一行；`POST /api/little-icon/music/added?count=` 记录「一个集合进来了」，桌宠上方说的就是它，因为集合只加入、不下载；`POST /api/little-icon/music/remove?id=` 删记录与文件——`?ids=a,b,c` 一次删掉一整组——文件正被桌宠播放时答 `busy`；`POST /api/little-icon/music/command?action=play|pause|toggle|next|prev` 给桌宠写一条命令。几条路由和 Git 那几条一样先过同一个连接检查与方法守卫；下载与补全**不需要页面在听**：桌宠菜单经命令文件里的 `music-sync` 与 `music-open-dir` 走到同一批活，卡片上那四个播放按钮也是把命令写进 `music.json`，自己不播。

**「操作」这个信号从哪来。** 宿主只看得到 agent 和 job，「没人动过」和「没有任务在跑」是两回事——没有输入信号的话，人一直在用 DSH，桌宠照样会睡。所以浏览器半边在 `pointerdown`/`pointermove`/`wheel`/`keydown` 上打点，节流到 15 秒一次，`POST /api/little-icon/activity`（同源路由，按仓库惯例先过 `connection.requestRejection`，非 POST 回 405）；宿主再和 `position.json` 的修改时间取最大值——拖动桌宠同样算操作。收起 DSH 之后页面收不到任何输入（这正是想要的），所以改由桌宠每秒把自己看到的窗口状态写进 `window.json`（在不在屏幕上、前台是不是 DSH 这一侧），宿主据此在两种打盹计时器之间切换、以及决定要不要自动收起；「显示/收起/切到前台」这些变化本身也算一次操作（所以收起之后短的那条打盹计时立刻开始走）。于是打盹只在真的一段时间没人碰过任何东西之后才出现，而任务开始本身也算操作。

**桌宠进程。** `pet/pet.ps1` 是 WPF 无边框透明置顶窗口（`WindowStyle=None` + `AllowsTransparency` + `Topmost` + `ShowActivated=false`，不抢焦点）。脚本开头先把进程声明为 DPI 感知（`SetProcessDpiAwarenessContext` 逐级回退）：PowerShell 没有 DPI 清单，非感知进程里的分层窗口会被系统按虚拟化尺寸渲染再拉伸，桌宠会画成 2×2 平铺且比设定尺寸大。随后用 `WindowInteropHelper.EnsureHandle()` 拿到句柄补上 `WS_EX_TOOLWINDOW`——WPF 的 `ShowInTaskbar=false` 并不会真的加上这个样式，否则任务栏和 Alt+Tab 里会多一项。定时器每 200 毫秒按状态文件的修改时间决定是否重读，套用表情、尺寸、不透明度、点击行为与置顶；帧动画按 `frameMs` 轮播，帧数由脚本自己数素材文件（多数表情 4 帧、`干活中` 6 帧）。拖动用 `DragMove()`。激活桌宠窗口的那次按下会被 WPF 报告两次（一次随激活、一次是普通鼠标消息），而前一次还起不了拖动，所以按下只做记录，松开时才判定是点击还是拖动：否则第一次点击会刚把 DSH 收起又立刻放回来，只想拖桌宠时也会把 DSH 收起。窗口位置存在 `position.json`，启动时读回并夹进屏幕范围。右键菜单（`New-PetMenu`）是插件唯一的菜单，由 WinForms 的 `ContextMenuStrip` 画：**对话**与**常用网站**在最前，接着是 **Git 改动**，它们先调 `Show-DshWindow` 把 DSH 恢复并置顶（收起/最小化时 `SW_RESTORE`，只是被盖住时 `SetForegroundWindow`），再把 `{"command":"chat","at":…}` / `{"command":"site","url":…,"at":…}` / `{"command":"git","at":…}` 写进 `command.json` 交给宿主转交；再下一项**打开工作目录**只往同一个文件里写 `{"command":"open-cwd","at":…}`——它不抬窗口，要看的是那个文件夹；下一项**截图**是本进程自己的活、一个字都不写；菜单最后由**设置**收尾，它像**对话**一样先把窗口抬起来，再写 `{"command":"settings","at":…}`，由页面把插件页翻到本插件那张卡片上。宿主那一路没打开时，桌宠读到状态文件里的 `notice` 会弹一句说明（`Get-OpenFailureText` 把宿主的原因（`no-cwd`／`no-dir`／其余）翻成 labels.json 里的话，同一个 `at` 只弹一次）。**常用网站**是唯一一个内容来自配置的菜单项：它在 `DropDownOpening` 时由 `Update-SiteMenu` 拿状态文件里那份 `sites` 整段重建（`Add-SiteMenuItem` 每条一次调用，并给处理器挂 `.GetNewClosure()`——PowerShell 的脚本块**在运行时**按当时的作用域查变量、不是按创建时，所以「循环里共用一份处理器」和「处理器直接引用函数参数」两条路都会在点击那一刻拿到空值，命令于是带着空地址发出去（`tests/smoke.mjs` 会真的 `PerformClick()` 一次来压这条）），所以卡片里改完不用重启桌宠；列表为空时放一条灰掉的说明，末尾固定是**管理常用网站**（发的就是 `settings` 那条命令）。网页版没有可控制系统窗口，分隔线下的**系统**子菜单（**更新 DSH**／**重启 DSH**／**退出 DSH**）根本不建，而收起/显示与归位这两项在两边都已经不在菜单里了。它每秒上报的「前台」指的是**前面是不是 DSH 这一侧**：DSH 自己进程里的窗口（含对话框、更新提示）与桌宠自己的窗口都算，只有第三方应用跑到前面才算「不在前台」——所以拖动桌宠不会被当成你跑去用别的应用。标签都从 `pet/labels.json` 按 UTF-8 读，读不到用脚本内的英文兜底，脚本本身保持纯 ASCII。

**重启 DSH。** **系统**子菜单里**退出 DSH** 上面那一项是**重启 DSH**（同样先确认，因为重启会打断正在跑的任务），做的是「结束 DSH，再把它照原样拉起来」。这一步必须在桌宠之外完成：结束 DSH 会卸载插件，插件的清理会把桌宠一起关掉，所以先由一个**脱离的等待进程**（隐藏窗口的 `powershell.exe -EncodedCommand`）守着——它等 DSH 进程真的退出，再等 4 秒让宿主的收尾（会话落盘、agent 停止）走完，然后自己开始。等待进程要重放的是「DSH 是怎么被启动的」：这只有那个进程自己知道，于是从 WMI（`Win32_Process.CommandLine`）读它自己的命令行，原样交给 `cmd /c` 执行；命令行不经过任何拼接，而是放在环境变量 `DSH_RELAUNCH_CMD` 里让 cmd 自己展开，因此路径里的空格、引号和非 ASCII 都不会被哪一层重新解析坏。工作目录取命令行里**最后那个存在的目录**——启动脚本正是用它当工作目录（`start-dsh-service.vbs` 的 `CurrentDirectory`），对这个启动器就是 `apps\desktop`。**这条重放路径不经过 `build\start-desktop.bat`**，所以那次启动前本该做的桌宠设置合并（见上面「使用本包」）由桌宠自己补跑：重放命令行之前先执行一次 `_mytools\settings\sync-pet-settings.mjs apply`，仓库同样按 `apps\desktop` 这个锚点定位；找不到 `node` 或合并失败都只写一条日志，不会拦住重启。**还有一条环境上的坑**：桌宠跑在宿主里、宿主跑在 Node 模式的 Electron 里，所以整条进程树都带着 `ELECTRON_RUN_AS_NODE=1`；带着它启动的 Electron 会当普通 Node 进程跑，加载 app 的第一行 import 就崩——等待进程在启动前把它删掉（只在那一层删，桌宠自己仍然用它）。读不到命令行（WMI 不可用）时**不动 DSH**，只弹一句说明：宁可什么都不做，也不能把它关掉却没有回头路。准备阶段的任何失败同样弹框说明「DSH 没有被动过」——包括设不了那个环境变量：Windows PowerShell 里 `$env[$name]` 不能按算出来的名字赋值（报「Cannot index into a null array」），而它发生在**结束 DSH 之前**，所以当初的表现就是「点了菜单没反应」；现在改用 .NET 赋值，也让这类失败在框里说话。

**更新 DSH。** 仅桌面端显示的**更新 DSH**会构建当前工作副本，不会 fetch 或 pull 代码。确认后，桌宠从正在运行的 `apps/desktop` 目录定位 `_mytools/build/build-desktop.bat`，并带 `--detached --restart` 启动。脱离的控制台会实时显示每行构建输出并同步写入日志；成功时自动关闭，失败时保留最终输出和日志路径，按 Enter 后关闭。脱离构建把结果写进 `$DSH_HOME/build`，会在清理前关闭这个工作副本的 Electron，且只在桌面端全部构建与准备步骤成功后运行 `start-desktop.bat`。若预检或依赖检查先失败，DSH 保持运行，桌宠会恢复菜单并显示失败步骤与日志路径；关闭 DSH 之后才失败则保持关闭，避免启动不完整产物。若当前启动命令无法定位这个工作副本，或构建启动器没有成功拉起，DSH 保持运行，桌宠直接提示失败。

**几何单位。** 位置与夹取一律用 WPF 自己的 `SystemParameters.WorkArea` / `VirtualScreen*`，它们和 `Window.Left/Top` 同为设备无关单位；WinForms 的 `Screen`/`SystemInformation` 给的是物理像素，在 150% 缩放之类的情况下混用会把桌宠推到屏幕外（右下角被乘 1.5 倍）。`tests/smoke.mjs --pet` 会用 DPI 感知的探针量出窗口矩形，断言它确实落在屏幕内。

**窗口控制。** 目标窗口先取 `Process.MainWindowHandle`（这正是主窗口，不会被无标题的辅助窗口误判，所以优先信它），拿不到时枚举该进程的顶层窗口并跳过 `IME`/`CandidateWindow`/`MSCTFIME UI` 一类输入法辅助窗口；句柄找到后缓存，因为 `SW_HIDE` 之后 `MainWindowHandle` 会变成 0。收起用 `SW_HIDE`（从屏幕和任务栏一起消失，回来的入口是桌宠和 DSH 主进程自己的托盘图标），恢复则**按窗口当时的状态选命令**：最小化的用 `SW_RESTORE`，只是被收起的用 `SW_SHOW`。这两个命令不能互换——`SW_RESTORE` 还会把最大化或全屏的窗口退回它最大化之前的大小与位置（实测：隐藏着的最大化窗口用 `SW_RESTORE` 回来就不再最大化，这正是「收起再显示就退出全屏」的来历），`SW_SHOW` 则在原有大小与位置上显示；反过来 `SW_SHOW` 又不会把最小化的窗口弄回来，所以只有最小化那一种走 `SW_RESTORE`（`Get-ShowCommand` 就是这个判断，`-SelfTest` 会把它打印出来压住）。两者后面都接 `SetForegroundWindow`。改窗口只有 `Set-DshWindowShown` 一个出口：单击桌宠、右键菜单和宿主的 `tuck` 请求都走它，目标状态与当前一致时直接返回，所以重复的 `tuck` 不会把刚收起的窗口又放回来，`clickAction` 里的 `minimize` 仍单独用 `SW_MINIMIZE`。**单击该收还是该抬**由 `Get-ClickIntent` 判断：只有「在屏幕上**且**是最前面那个窗口」才收起，其余一律经 `Show-DshWindow` 抬到最前。后一个条件由 `Get-DshInFront` 提供，它比 `Get-DshForeground` 严：**只有前台窗口属于 DSH 进程才算**——按下桌宠的那一下会把桌宠自己变成前台窗口，若像宿主的自动收起那样把桌宠也算作 DSH，单击就永远判成「在前面」，DSH 也就再也收不起来。这个事实**在单击发生之前**采样（鼠标移上桌宠时，以及每秒一次的状态采样里），不在单击时现问。

**编码。** `pet.ps1` 保持纯 ASCII：Windows PowerShell 5.1 在没有 BOM 时按 ANSI 解码 `.ps1`，UTF-8 的中文会变乱码，甚至可能吞掉引号破坏语法。中文菜单文案放在 `pet/labels.json`，脚本按 UTF-8 读它；读不到就用英文兜底。`tests/smoke.mjs` 会断言脚本里没有非 ASCII 字符。

**素材。** `assets/<state>/1.png … N.png` 由 `tools/build-assets.py` 从一个表情一张精灵表切出来，切好的成品就是仓库里唯一的素材副本（约 24 MB 的源表删掉了，要重切得先按开发备注从 git 历史取回）。每张源图是若干角色排在一张 2048×2048 上的精灵表，但排版不统一：多数表情是 2×2 共 4 个，`干活中` 是 3 列 2 行共 6 个，`打盹` 两行之间只有 14 像素空隙。脚本因此不假设网格，而是按透明投影找角色：行投影里找空行分带（空行不足 8 像素不算分隔；过矮的段并入相邻角色，免得把 Zzz 气泡、齿轮当成角色），再在每条带内按列投影分人物段（列投影低于峰值 12% 算人物之间的浅谷），段内按实际不透明像素收紧包围盒。所有角色按自上而下、自左而右成帧，底部居中放进统一画布，并按所有表情里最大的角色算一个全局缩放，因此同一表情内不跳帧、表情之间角色大小一致。帧数由版面决定并写进 `assets/frames.json`，桌宠自己数文件而不是读固定值——换素材不必改代码。

</details>

<a id="model-experience"></a>
## 模型体验

无。插件不增加模型可见输入、提示词、工具或会话事件，只读取 agent 与 job 的运行状态。

## <a id="known-limitations-and-deferred-work"></a>已知限制与延后工作

**出错没有单独的表情。** `agent/error` 还在事件表里，而 `alert` 现在归「等你抉择」用（见上）。要让报错也露个脸，可以在宿主半再监听它、给状态机加一个输入，并准备对应素材。

**「收起」用的是 `SW_HIDE`，不是最小化。** DSH 窗口从屏幕和任务栏一起消失，回来的入口是桌宠本身，以及 DSH 主进程常驻的那个托盘图标（`apps/desktop/src/tray.ts`：点击回到窗口，右键是「打开应用 / 退出应用」）。桌宠**不再**建自己的 `NotifyIcon`：通知区里已经有一个属于 DSH 的图标，一个挂在 DSH 上的小挂件不该再占第二个。DSH 若被别的方式退出，桌宠最多 45 秒后（或发现宿主进程消失时）自行退出。

**退出是先请求、后强杀。** 宿主不直接 `kill`：它先写 `quit` 文件，桌宠一个 200 ms tick 内就会读到，存好位置、按顺序关掉自己的窗口再退出、并把请求带走；真不回答才在 1 秒后兜底强杀。这样正常收尾不会和桌宠正在写的位置文件打架。为此 `tests/smoke.mjs --pet` 也顺带压了两条：启动新桌宠前必须清掉上一个宿主留下的 `quit`（否则新桌宠第一拍就自杀），以及关掉「启用桌宠」时是先写请求、桌宠自己退出并把请求带走。

**内嵌浏览器不会自动登录。** 菜单里的**对话**与**常用网站**打开的都是 DSH 的右侧 Browser 标签，它的存储分区是**持久**的（本副本对上游的唯一一处改动：`apps/desktop/src/browser-guests.ts` 用 `persist:dsh-sidebar-browser-<工作区标识的摘要>`，改动、重建与恢复步骤见 [UPSTREAM.md](UPSTREAM.md)），所以在那里登录过一次 chat.deepseek.com 之后，重启 DSH 仍然保持登录——但**不会**用 DSH 自己的账号自动登录：DSH 手里的凭据是 `platform.deepseek.com` 那一份（`platform-view.ts` 只对那个 origin 注入 Cookie，官方用量页跑的就是这条路），而 chat.deepseek.com 是另一套 Web 会话；插件也塞不进 Cookie——宿主半边没有 Electron API，浏览器半边是 sandbox，那个分区归 `apps/desktop` 管。另外 DeepSeek 自己会对嵌入式环境提示「使用环境异常」，那是服务端判断，插件这一层改不掉。**重新 build 也一样保得住**：`--user-data-dir` 现在指向 `$DSH_HOME\desktop\electron-user-data`，不在 `pnpm run clean` 会删的 `.desktop-build` 里（见工作副本 `_mytools/README.md` 里那段迁移说明）。分区的键是**工作区**：当前对话属于某个工作区时是 `cwd:<路径>`（稳定，重启、换对话都共用），不属于任何工作区时退化成 `session:<对话 id>`（换新对话就是新分区，登录也就跟着换）。

**网页版的小游戏。** 小游戏与**对话**一样由页面执行，只要那个插件装在同一个 profile 里就有；它不依赖 Browser 标签，也不依赖右侧栏，所以**玻璃鱼缸**在网页版同样可用（前提是装了 3D 玻璃鱼缸插件）。

**网页版可能没有 Browser 标签。** 右侧 Browser 类型在 Web profile 默认关闭，没有右侧栏的构建连 `ctx.sidebarRight` 都没有；偏好是**应用内侧边栏**时，**对话**与**常用网站**会**回落到系统浏览器**——和 `ui-chat` 处理对话链接时的回落是同一条判断——并记一条 `console.warn` 说明回落原因。桌面端装了自带 Browser 标签，所以正常可用。回落到 `window.open` 在网页版由浏览器执行，而这次点击发生在**桌宠那个进程**里、不是页面上的用户手势，可能被弹窗拦截挡下；桌面端走的是主进程的 `shell.openExternal`，不受影响。**Git 改动**不受这一条影响：那一页的类型是插件自己注册的，只要右侧栏在（Web profile 也有 `ui-sidebar-right`）就能开。

**Git 页只在明确点击快进拉取时移动本地内容。** 打开或刷新页面会更新当前分支的远端跟踪引用，让**最近提交**旁的状态保持实时，但不会移动本地分支、暂存区或工作树。**拉取**是唯一直接移动本地内容的动作，而且不会合并已经分叉的历史；**提交并推送**仍只是把一句话发进对话、交给模型执行（见上）。仓库由当前会话的工作目录决定，所以它显示的是那个项目的仓库，而不是 DSH 自己的。工作目录不在仓库里、目录消失、机器上没有 `git`，各显示一句说明。

**活动只来自 DSH 页面和桌宠本身。** 上报来自 DSH 页面的输入事件，所以 DSH 被收起、最小化或被别的程序盖住时没有输入：收起状态按 `sleepWhenHiddenSeconds` 打盹（默认 20 秒，只有拖动桌宠能续命），这正是想要的；在别的程序里操作不会让它醒着，只有回到 DSH 打字点鼠标、拖动桌宠，或者把 DSH 放回来才会。

**桌宠不在菜单里退出自己。** 菜单的**系统**子菜单提供**更新 DSH**、**重启 DSH**与**退出 DSH**，没有「退出桌宠」：桌宠的生死由设置里的**启用桌宠**开关控制（关掉就退出，再打开才回来）。这样停桌宠只有一条路，也不会让某次误点把它关掉。要结束 DSH 用**系统**里的最后一项（会先确认）。

**重启靠重放启动命令行，不是应用自己的重启。** 桌面端自己的重启（`app.relaunch()`）在 Electron 主进程里，插件够不到：宿主是它的 Node 模式子进程，页面是 sandbox。所以桌宠走的是「读它自己的命令行 → 结束它 → 照原样再拉起」，代价是这条链路依赖「原样重放」——命令行里出现当时环境独有的东西（比如某个只在那次启动时设过的变量、或启动器临时拼的参数）时，重放出来的进程未必和原来一致。按这个仓库的启动方式（`_mytools/build/start-desktop.bat` → `start-dsh-service.vbs`）没有这类东西，环境本身由父进程继承、原样传下去。工作目录也只是一个启发式（命令行里最后那个存在的目录）。要更稳的话，得在上游 `apps/desktop/src/main.ts` 里加一条自定义窗口消息（桌宠已经会用 `0x8001` 给主窗口发消息）让主进程自己 `app.relaunch()`——那样还要重建 desktop 包，并记进 [UPSTREAM.md](UPSTREAM.md)。

**位置只按虚拟屏幕夹取。** 换显示器布局后窗口会被拉回可见范围，但不按显示器记忆位置。

**动画只有四帧。** 素材决定了表情切换是 4 帧循环；更细的动作（敲键盘、Zzz 气泡）需要重做素材并放进对应的状态目录。

**听歌表情是手加的素材。** `assets/music/1.png … 4.png` 与 `frames.json` 里的 `music` 键是手工加的，不是从精灵表切出来的；而 `tools/build-assets.py` 会用「它切出来的表情」整体重写 `frames.json`，所以为了重切那几个有源表的表达而重跑它时，`music` 键会被抹掉。桌宠的帧数是从磁盘数的，所以没有这个键也照常动；冒烟测试会因为缺这个键失败，那就是把它加回来的信号。

**菜单里两项是配置，所以由页面执行。** **音量（N%）**滑条与**添加 B站链接…**写的是设置卡写的那几个字段，而设置服务拒绝任何发生在 HMR 事务里的写入——宿主定时器就在那个上下文里，因为它是在插件被加载的过程中创建的。所以这两条命令要到达页面，和菜单里其它「会改东西的条目」一样；没有页面在听时它们不会生效。**听歌**里其余的功能——播放、打开目录、补全缺失——仍然归宿主，没有页面也能用。

**网页版是二等公民。** 那里没有可控制的 DSH 窗口，所以右键菜单只留**对话**、**常用网站**、**Git 改动**、**打开工作目录**、**听歌**、**截图**、**特殊功能**与**设置**（没有**系统**子菜单——没有可构建或控制的桌面端进程；两边都没有窗口类条目），单击桌宠不做任何事；窗口、表情、拖动等行为与桌面端一致。**常用网站**和**对话**一样优先走右侧 Browser 标签，网页版默认关掉它时地址回落到系统浏览器并记一条警告；**Git 改动**在网页版一样能用，**打开工作目录**也一样：开文件夹的是宿主，和右侧栏没有任何关系；**截图**本来就是桌宠自己的活，同样不需要窗口；**设置**要的是一页而不是窗口，所以在网页版也一样。**听歌**也和桌面端一样：子菜单与音频都在桌宠进程里，下载由宿主做。

**多机协同是软 KVM，不是远程桌面。** 注入不了「以管理员身份运行」的窗口和 UAC 安全桌面，鼠标按屏幕比例映射、不是 1:1 位移。走这条链路的只有键盘和鼠标——不做剪贴板、文件传输与画面传输。卡顿来自链路而不是映射（实测有线一段 0–1 ms，经笔记本 Wi-Fi 的端到端往返 2–619 ms），所以要在那台机器上处理：关掉无线网卡的省电、优先 5GHz，或者改用网线。

**机器之间只搬链接。** 仓库的 [../../settings/pet-settings.yml](../../settings/pet-settings.yml) 只带 `musicLinks` 这一个数组、曲库里别的东西一样都不带，所以另一台机器 `git pull` 后有列表、没有音频，要自己补全——这是设计而不是缺陷：音频体积大、不该由这个仓库携带，而且从链接随时能重新下出来。播放同样由桌宠进程承担：桌宠退出或插件关闭时音乐停止；改 `musicDir` 也不会迁移已经下载好的文件。

<a id="dev-note"></a>
### 开发备注

```text
python tools/build-assets.py          # regenerate assets/ (bundled DSH Python: Pillow + numpy)
node tests/smoke.mjs                  # state machine, art, state-file write, one real screen capture, and pet.ps1 -SelfTest (no window)
node tests/smoke.mjs --pet            # additionally runs the apply() lifecycle: start the pet, measure
                                      # that its window is on screen, change state, dispose
                                      # (a real pet window appears for about 25 seconds)
```

重切素材要先取回源精灵表：它们不在仓库里了（`git log --diff-filter=D --oneline -- _mytools/Plugins/dsh-littleIcon/IconImage` 找出删除那次提交，再用 `git checkout <那次提交>^ -- _mytools/Plugins/dsh-littleIcon/IconImage` 取回），或者把别处的表用 `--source` 指给脚本。默认的 `--source` 就是取回后的路径。

`--pet` 会在桌面上**真显示一只桌宠窗口**（左上角、约 25 秒，用的是自己的临时 `$DSH_HOME`，所以能和正在使用的那只并存），运行时也会打印一行说明。它故意放在左上角而不是默认的右下角：万一你看到一只陌生的桌宠，那就是这个测试的，而不是插件多起了一只。

改了 `index.js`、`music.js`、`package.json` 或 `cordis.patch.yml` 要重启 DSH 才生效（宿主半边不热更新，现在可以直接右键桌宠选**系统 ▸ 重启 DSH**）；插件以 `link:` 装进 profile 时 `client.js` 是直接按文件提供的、没有单独的构建步骤，所以改它刷新页面即可——刷新后如果设置卡还是旧的，重启一次 DSH 最稳——而以 `file:` 装成的副本由 `_mytools/build/sync-plugins.bat` 刷新，它的单文件清单里也带上了 `music.js`；改 `pet/pet.ps1`、`pet/labels.json` 或 `assets/` 只需重启桌宠进程（把设置里的**启用桌宠**关掉再打开，或重启 DSH）。

桌宠的重启只在**真点下去**时才会跑完整条链路（等待进程 → 重放命令行 → 新实例），所以 `tests/smoke.mjs` 只压它能压的部分：`pet.ps1 -SelfTest` 会打印它解析出的重放目录与等待进程脚本，断言启动前确实删掉了 `ELECTRON_RUN_AS_NODE`、等 DSH 退出后先等 4 秒、再让 cmd 展开命令行；真正的重放要手动验——最省事的办法是点一次菜单里的**系统 ▸ 重启 DSH**，看应用是不是自己回来了。**打开工作目录**同理只压到宿主那一层：`openWorkingDirectory` 用注入的启动函数压（所以不会真去开文件夹），路由用一个不起桌宠的宿主实例压（所以不会弹出失败说明框）；点一次菜单真的开出资源管理器这件事要手动验——目录不在时那一句说明也一并看掉。

**截图**则不用人参与就能压：`pet.ps1 -ShotProbe` 真的截一次屏幕左上角 320×200，`tests/smoke.mjs` 断言它写出来的确实是一张尺寸分毫不差的 PNG，且大小与探针报出的一致。不需要屏幕的那部分由 `pet.ps1 -SelfTest` 压——截图文件落在状态文件旁的 `shots/` 里、命名带毫秒、「往左上拖」和「往右下拖」得到同一个矩形，以及**常用网站子菜单**：自测会为空列表和两条网站各建一次子菜单、把每条的文字与提示地址打印出来（`site-menu:` 一行），并**真的点一次第一条**，断言空列表仍写着说明与**管理常用网站**、两条网站各带自己的地址、备注留空的那条用域名顶上，以及点下去写进命令文件的确实是**这一条**的地址。自测还打印「把 DSH 弄回来该用哪条 ShowWindow 命令」（`show-commands:` 一行），断言只是被收起的用 `SW_SHOW`(5)、最小化的用 `SW_RESTORE`(9)；以及「单击该收还是该抬」（`click-intent:` 一行），断言只有在最前面的窗口才收起、被盖住的和不在屏幕上的都抬到最前。需要窗口的部分（压暗的遮罩、拖动、选区边框、桌宠上方那句提示）手动验：在菜单里点一次**截图**，拖一块区域。

**听歌**和截图一样不用人参与就能压：`pet.ps1 -MusicProbe <文件>` 只跑音频那一段——媒体播放器、解码器、声卡与一个文件，不开窗口、不读曲库——成功打印 `music-probe: opened duration=…`，失败打印 `music-probe: failed error=…` 并以 1 退出，和 `-ShotProbe` 是同一个用途：放不出已下载文件的机器在这里就失败，而不是等到第一次点菜单。`tests/smoke.mjs` 用一个不起桌宠的宿主实例压曲库、发布的 `music.json` 与五条路由；`pet.ps1 -SelfTest` 会为一个有曲目的曲库建一次听歌子菜单，断言每一行变成了什么，包括打开目录与补全那两条各自让宿主去做哪件事；`tests/smoke.mjs --pet` 则带着真桌宠窗口跑完整条链路。
