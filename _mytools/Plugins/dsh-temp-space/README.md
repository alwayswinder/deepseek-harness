# dsh-temp-space（临时空间）

DSH 的一块「只有一页」的画布：图片、文本、任意文件丢进去就锚在放下的位置，文字直接在里面写。关掉不用记着保存——改动防抖半秒就回写。跨机器靠它自己的一个 Git 仓库上传/拉取，与本仓库、与 `$DSH_HOME` 里的会话数据都没有关系。

入口有两个：桌宠右键 **特殊功能 → 临时空间**，或左侧栏的「临时空间」图标（两者都只是把中栏面板切过去）。

## 数据放在哪

默认 `$DSH_HOME/temp-space`（`$DSH_HOME` 未设置时是 `~/.dsh`），可以用插件配置的 `dataDir` 改成任何路径。这个目录本身就是一个 Git 仓库的克隆：

```
index.json       画布状态：每个条目的坐标、尺寸、层级、文字或文件名
files/           文件字节，按原文件名存（重名自动加 (2)）
.gitattributes   `* -text`：不做出入换行转换，存进去是什么字节就是什么字节
.gitignore       *.tmp（写 index.json 时的临时文件）
```

换一台机器：把仓库 `git clone` 到这台机器的 `$DSH_HOME/temp-space` 就行，插件不做克隆。

## 配额

单文件 10 MB、总量 100 MB，两个都能在插件配置里改（`maxFileBytes` / `maxTotalBytes`）。超限在宿主侧就被拒（HTTP 413，`file-too-large` / `space-full`），画布会说明原因，不会先落盘再报错。

## Git 的语义

这里的 Git 只做四件事：`提交`（`git add -A` + commit）、`拉取`（`git pull --ff-only`）、`上传`（`git push <remote> <branch>`）、以及读状态（分支、ahead/behind、未提交改动数）。

**冲突不在这里解决**：拉取只接受快进，分叉了就是失败并显示 Git 自己的输出；上传遇到落后也会被远端拒。二进制文件没法合并，所以两台机器都改过同一条目时，脚本会明确报错，而不是自作聪明地合并——这种情况请去终端处理。

**凭据必须是已经配好的**：插件进程没有终端可以回答密码提示（子进程显式设了 `GIT_TERMINAL_PROMPT=0` 和 `GCM_INTERACTIVE=Never`），所以首次认证要在终端里完成一次，之后凭据管理器或 ssh-agent 能自动回答，画布上的「上传」才能用。

## HTTP 路由

页面没有文件系统，所有事实都由宿主半边在这三条同源路由上提供（都先过 `connection.requestRejection`：Host 围栏 + 同源 + 浏览器 Cookie）：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/temp-space/state` | GET / PUT | 读画布；整份写回，带 revision 乐观锁（对不上返回 409 + 当前 revision） |
| `/api/temp-space/blob?name=…` | GET / HEAD / POST / DELETE | 回读（按扩展名给 content-type，`<img src>` 直接可用，流式）、存字节、删除 |
| `/api/temp-space/git` | GET / POST | 读状态；POST `{action: fetch\|pull\|push\|commit, message}` |

文件名在宿主侧净化：去掉路径分隔符与控制字符、挡住 Windows 设备名、保留扩展名、限长；名字在写盘前再和自身净化结果比对一次，所以条目只可能指向本空间 `files/` 里的文件。

## 安装（本机）

插件目录 `E:\AI\DSH\_mytools\Plugins\dsh-temp-space`。桌面 profile 由 Electron 独占管理，命令行加不进去，走界面：**插件 → 安装 → 填绝对路径**，然后重启 DSH。Web profile 由 `_mytools/build/start-dsh.bat` 的 `DSH_LOCAL_PLUGINS` 自动注册（已加好）。

装载方式在本机是 `link:`（junction），改源码后：宿主半边 `index.js` 要**重启 DSH**；浏览器半边只需重新打包再刷新页面：

```
node client/build.mjs
```

打包用的是本仓库 pnpm store 里的 esbuild，不需要装依赖。

## 页面上的约定

- **不给任何控件静默失败。** 每个点击都立刻在标题下的提示行里写一句（`正在拉取…` → `已拉取`），抛出的异常也会变成同一行的 `失败：…`。桌面外壳里 `window.prompt` 根本没实现、调用即抛错，所以这个面板**不用任何 `window.*` 对话框**：删除靠同一个 × 按两次，第一次旁边会出现「确定删除 / 取消」，点画布空白处也算取消。
- **拖拽不捕获指针。** 把手在按下时只记下起点，移动和抬起监听挂在 `window` 上，而且**位移超过 3 像素才算拖动**。早期版本用 `setPointerCapture`，结果捕获后的指针会把随后的 `click` 派发给捕获元素本身，标题和删除按钮永远收不到点击——所以现在卡片头部的标题（双击改名）和 × 都能正常工作。
- **保存 = 提交 + 上传。** 一个按钮做完两步，提示行会分清三种结果：`已提交并上传`、`本机已是最新，没有需要保存的改动`、`已提交到本机，但上传失败：<git 原文>`（远端领先时则是「先拉取再保存」——提交已经落地，只是没传）。提交信息由插件生成，不带对话框。
- **卡片可以改标题。** 双击标题进入编辑，Enter 确认、Esc 放弃；标题是人的叫法，和文件名独立，清空就退回文件名。改了名的卡片在正文里仍然写着它装的是哪个文件。
- **滚轮缩放，锚在指针下。** 范围 25%–300%，一次滚轮一格（×1.1）；`−`/`+` 走 25% / 50% / 100% / 200% / 300% 这几档，所以「正常比例 → 缩小一倍」是一次点击；点中间那个百分比回到 100%。缩放只作用于显示：卡片存下来的永远是内容坐标，所以任何缩放下拖动都跟着指针走（指针位移按缩放折算）。两个实现细节值得记着——滚轮监听必须**非被动**（React 的 `onWheel` 是被动的，`preventDefault` 在那里无效，画布会一边缩放一边滚动），所以由元素自己注册；而「同一个内容点留在指针下」需要的滚动位置，只能在缩放后的层重新渲染之后才设得下去，于是它先存进 ref、由 `[zoom]` 的 effect 应用。
- **右键拖动 = 平移画布。** 滚轮被缩放占用后，画布靠拖拽移动；右键在**任何位置**都平移（卡片上也一样），左键只在空白背景上平移。分工是有意的：左键在卡片标题上是移动卡片，右键从来不移动卡片——画布铺满卡片时不必去找一块空地。右键同时被 `onContextMenu` 吃掉，免得外壳的菜单打断拖拽。
- **不做拼写检查。** 便签里粘的常是 key、路径、代码，浏览器给它们画的红色波浪全是噪声；便签的 `textarea` 和标题的 `input` 都显式 `spellCheck={false}`。
- **画布是一块固定大小的平面。** 坐标以平面中心为原点（`x ∈ [-2000, 2000]`、`y ∈ [-1500, 1500]`），所以卡片可以被放到原点左上，平面本身**不会因为卡片移动而移动、变大或重新居中**——这是关键：卡片移动时视图绝对不能跟着挪，否则看起来像画布在动而不是卡片在动。拖动只被平面自己的边界拦下（`clampToPlane`），而那边界远到平时感觉不到。
- **打开时把视角对准卡片。** 第一次加载完成后按卡片包围盒的中心定位一次（空画布就是平面中心），此后不再动。比视口小的平面由 `margin: auto` 居中（**不用 `justify-content: center`**，那个会让平面的左上角滚不到，而放大后平面必然比视口大）。平面本身画了出来（浅底 + 描边），所以它的边界是看得见的。
  两处布局陷阱：拖拽提示原来是 `position: sticky`，而 sticky 元素**仍在流内**，会变成平面旁边的第二个 flex 子项、把居中挤偏；另外空状态与拖拽提示原来都在**滚动容器内部**，而打开时视角是对准卡片的（不是容器左上角），它们会被滚到屏幕外——现在两者都放在滚动容器之外、由外层定住。
- **拖动按「指针位移」算，不按「落点」算。** 位置 = 起始位置 + 指针位移 ÷ 缩放。这不是风格问题：早先版本用「落点」反推位置，而落点要减掉层偏移；层偏移一旦随卡片变化（动态包围盒那版），每个 move 事件都会再叠一次累计位移，卡片会加速逃逸。用位移算，画布自身的布局完全不进入算式。
- Git 命令要等网络（SSH 握手在本机约 4 秒），这段时间几个按钮会一起禁用，但提示行会说明正在做什么。

## 测试

```
node tests/smoke.mjs
```

用真 Git 仓库 + 真 HTTP 监听跑通三条路由：文件名净化、两处配额拒绝、revision 冲突、字节往返、四个 Git 动作、以及「目录不是仓库」的报错。不需要 DSH_HOME、浏览器或网络远端。

```
node tests/client-smoke.mjs   # 浏览器半边
```

按 DSH 客户端的方式加载打包后的 `client/client.js`（走 `window.__ModuleLoader__.load`），用一个会保留 state、按声明序跑 effect 的最小 React 渲染面板：空空间、有便签/图片/普通文件/文件缺失的空间、五种 Git 关系、三种入口（新增便签、拖入文件、删除），以及面板服务和侧栏行。

**为什么浏览器半边也要有测试：** 真实渲染器把崩溃的 entry 藏在一个空的 `<div data-slot-error>` 后面并把它退休，界面上只表现为「中栏一片空白」，没有任何报错。这个测试存在的直接原因就是它抓到过一个这样的 bug——挂载 effect 读 `latest.current`，而写入它的 effect 声明在后面，React 按声明序跑 effect，于是首帧必崩。
