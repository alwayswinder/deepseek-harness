# dsh-temp-space（临时空间）

DSH 的一块「只有一页」的画布：图片、文本、任意文件丢进去就锚在放下的位置，文字直接在里面写。关掉不用记着保存——改动防抖半秒就回写。跨机器靠它自己的一个 Git 仓库上传/拉取，与本仓库、与 `$DSH_HOME` 里的会话数据都没有关系；`$DSH_HOME` 里只有一行本机路径指针和一个可选远端地址。

入口有两个：桌宠右键 **特殊功能 → 临时空间**，或左侧栏的「临时空间」图标（两者都只是把中栏面板切过去）。

## 数据放在哪

默认 `$DSH_HOME/temp-space`（`$DSH_HOME` 未设置时是 `~/.dsh`），可以用插件配置的 `dataDir` 改成任何路径。页面标题栏的「路径」可以在不重启 DSH 的前提下改用这台机器上的另一个目录：选中的路径写在 `$DSH_HOME/temp-space.location.json`，下次启动仍然生效，并覆盖配置里的 `dataDir`；那个文件只在这台机器上，跟着仓库走的只有临时空间自己的 Git 历史。插件配置的 `repoUrl` 是缺仓库时的默认远端地址，页面上填过并成功拉取的地址会覆盖它、同样记在这个文件里。

这个目录本身就是一个 Git 仓库的克隆：

```
index.json       画布状态：每个条目的坐标、尺寸、层级、文字或文件名
files/           文件字节，按原文件名存（重名自动加 (2)）
.gitattributes   `* -text`：不做出入换行转换，存进去是什么字节就是什么字节
.gitignore       *.tmp（写 index.json 时的临时文件）
```

换一台机器：在页面上点「路径」，选一个目录再点「拉取到此路径」。目录里已经是仓库就直接采用并快进拉取；空目录或新目录就用「远端仓库地址」把仓库克隆进去，克隆成功后那个地址会记下来，下次缺仓库时自动填好。也可以「直接使用」一个已经在这台机器上的仓库——这正是本地路径被配错时把页面接回现有克隆的方式。Git 的凭据仍然要在终端里预先配好（见下面「凭据必须是已经配好的」）。

## 配额

单文件 10 MB、总量 100 MB，两个都能在插件配置里改（`maxFileBytes` / `maxTotalBytes`）。超限在宿主侧就被拒（HTTP 413，`file-too-large` / `space-full`），画布会说明原因，不会先落盘再报错。

## Git 的语义

这里的 Git 做六件事：`提交`（`git add -A` + commit）、`拉取`（`git pull --ff-only`）、`上传`（`git push <remote> <branch>`）、`丢弃`（`git reset --hard HEAD` + `git clean -fd`，只碰本机）、读状态（分支、ahead/behind、未提交改动数），以及在路径设置里把缺的仓库 `克隆` 到指定目录（`git clone --origin <remote> -- <url> <dir>`，只在目标不存在或是空目录时执行）。

**冲突不在这里解决**：拉取只接受快进，分叉了就是失败并显示 Git 自己的输出；上传遇到落后也会被远端拒。二进制文件没法合并，所以两台机器都改过同一条目时，脚本会明确报错，而不是自作聪明地合并——这种情况请去终端处理。

**丢弃只丢本机未提交的东西。** 索引与工作区一起退回 HEAD，还没被任何提交收进去的文件也一并删掉——留着它们，空间就还是「有东西可提交」。所以一次丢弃之后状态必然是干净的，远端一个字节都不动；已经提交（但没上传）的改动不会因此消失，要退回那些提交得去终端用 Git。初始仓库还没有任何提交时 `reset --hard HEAD` 会失败，这种情况退化为清空索引、再删掉未跟踪的文件，结果一样：工作区与 HEAD 一致。

**凭据必须是已经配好的**：插件进程没有终端可以回答密码提示（子进程显式设了 `GIT_TERMINAL_PROMPT=0` 和 `GCM_INTERACTIVE=Never`），所以首次认证要在终端里完成一次，之后凭据管理器或 ssh-agent 能自动回答，画布上的「上传」才能用。

## HTTP 路由

页面没有文件系统，所有事实都由宿主半边在这六条同源路由上提供（都先过 `connection.requestRejection`：Host 围栏 + 同源 + 浏览器 Cookie）：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/temp-space/state` | GET / PUT | 读画布；整份写回，带 revision 乐观锁（对不上返回 409 + 当前 revision） |
| `/api/temp-space/space` | GET / POST | 读当前本地仓库路径；POST `{action: use\|pull\|reset, dir, repoUrl}` 采用已有仓库、拉取到新路径，或恢复配置里的路径 |
| `/api/temp-space/blob?name=…` | GET / HEAD / POST / DELETE | 回读（按扩展名给 content-type，`<img src>` 直接可用，流式）、存字节、删除 |
| `/api/temp-space/git` | GET / POST | 读状态；POST `{action: save\|pull\|discard}`，丢弃回传它数到的改动数与刷新后的状态 |
| `/api/temp-space/reveal` | POST | 在系统文件管理器里选中 `files/` 里的一个文件（`{name}`）；空间里没有这个名字返回 404，方法不是 POST 返回 405 |
| `/api/temp-space/clipboard` | POST | 把 `files/` 里的文件放进系统剪贴板（`{names:[…]}`，Windows/macOS 上是文件列表）或把文本放进去（`{text}`，走子进程的标准输入）；两者都没有返回 400，名字不在盘上返回 404，平台没有对应命令返回 501 |

文件名在宿主侧净化：去掉路径分隔符与控制字符、挡住 Windows 设备名、保留扩展名、限长；名字在写盘前再和自身净化结果比对一次，所以条目只可能指向本空间 `files/` 里的文件。

## 安装（本机）

插件目录 `_mytools/Plugins/dsh-temp-space`（相对本仓库根）。桌面 profile 由 Electron 独占管理，命令行加不进去，走界面：**插件 → 安装 → 填绝对路径**，然后重启 DSH。Web profile 由 `_mytools/build/start-dsh.bat` 的 `DSH_LOCAL_PLUGINS` 自动注册（已加好）。

装载方式在本机是 `link:`（junction），改源码后：宿主半边 `index.js` 要**重启 DSH**；浏览器半边只需重新打包再刷新页面：

```
node client/build.mjs
```

打包用的是本仓库 pnpm store 里的 esbuild，不需要装依赖。

## 页面上的约定

- **不给任何控件静默失败。** 每个点击都立刻在标题下的提示行里写一句（`正在拉取…` → `已拉取`），抛出的异常也会变成同一行的 `失败：…`。桌面外壳里 `window.prompt` 根本没实现、调用即抛错，所以这个面板**不用任何 `window.*` 对话框**：删除靠同一个 × 按两次，第一次旁边会出现「确定删除 / 取消」，点画布空白处也算取消。
- **路径设置就是「把页面接到仓库上」。** 本地仓库不存在时，画布位置换成设置卡：路径（可「浏览…」或用系统目录选择器）、远端仓库地址、以及「拉取到此路径」「直接使用」两个动作。路径存在且是仓库时「拉取」先采用它再快进拉取；目录不存在或是空的就按远端地址克隆进去。已经有仓库但页面指错了地方，就用「路径」→「直接使用」把页面接回那个克隆。路径必须是绝对路径；不是仓库、不是空目录、上级目录不存在、没填远端地址都会被按原因说明，而不是落到 Git 的原始报错。页面设置的路径只影响这台机器，并覆盖配置里的 `dataDir`；「恢复配置路径」清掉这层覆盖。
- **拖拽不捕获指针。** 把手在按下时只记下起点，移动和抬起监听挂在 `window` 上，而且**位移超过 3 像素才算拖动**。早期版本用 `setPointerCapture`，结果捕获后的指针会把随后的 `click` 派发给捕获元素本身，标题和删除按钮永远收不到点击——所以现在卡片头部的标题（双击改名）和 × 都能正常工作。
- **保存 = 提交 + 上传。** 一个按钮做完两步，提示行会分清三种结果：`已提交并上传`、`本机已是最新，没有需要保存的改动`、`已提交到本机，但上传失败：<git 原文>`（远端领先时则是「先拉取再保存」——提交已经落地，只是没传）。提交信息由插件生成，不带对话框。
- **「丢弃」是回到上次提交的按钮。** 它丢掉本机所有未提交的改动（含还没提交的文件）。执行前按两次：第一次只把按钮变成危险色并在提示行说明要丢什么，点画布空白处算取消，第二次才真的执行（和「清理」一个规矩）。真的丢完会从盘上重新读一遍画布，撤销历史一起清空（历史里的卡片已经指不到文件了）。本机已经与上次提交一致时它一次点击就直接回答「没有可丢弃的改动」，不再要求确认。它不碰远端，也不撤销已经提交的改动。
- **卡片可以改标题。** 双击标题进入编辑，Enter 确认、Esc 放弃；标题是人的叫法，和文件名独立，清空就退回文件名。改了名的卡片在正文里仍然写着它装的是哪个文件。
- **双击卡片正文 = 在文件管理器里定位它，拖动正文 = 移动卡片。** 正文（图片，或写着文件名与体积的那行）就是第二个把手：按在图片上拖和按在标题上拖一样，都是移动卡片（选中的话就是整组）。双击则叫宿主打开系统文件管理器并选中 `files/` 里的那个文件：Windows 用 `explorer.exe /select,`（目标是转义过逗号与等号的 file URI，非 ASCII 保持字符形式，否则 Explorer 会去开「文档」），macOS 用 `open -R`，Linux 打开所在目录——那里没有可移植的「选中这个文件」。标题栏的双击仍然是改名，两个手势互不干扰。**卡片上没有下载按钮**：字节本来就在每台拉过这个仓库的机器的 `files/` 里，要看文件就去文件管理器里看，宿主只负责把窗口开在对的位置。文件不在的卡片只把「文件不在了」写进提示行，不会去开一个不存在的路径；文件管理器起不来同样报在那一行。
- **只有从面板外面拖进来的东西才算入库。** 面板内部发起的拖拽一律不进库，也不亮「松手即入库」。两道闸：图片显式设了 `draggable={false}`（浏览器默认会为拖动中的图片准备一份「文件」，松手交回画布就是一个副本——这就是「拖一下图片库里的图，库里就多一个副本」的来源），并且拖拽的起点在面板内时整个 drop 都不受理（`onDragStart` 打标记，`onDragOver` 直接不 `preventDefault`，画布因此根本不是可放下的目标）；宿主之外还有第三道：`dataTransfer.types` 里必须带 `Files` 才算文件，光有 `text/html`、`uri-list` 的拖拽（拖便签里选中的文字就是这种）只当没发生。
- **宿主启动文件管理器是不等待的。** Explorer 会把请求交给已经在跑的桌面进程然后自己以 1 退出，等它的退出码就会把「窗口明明开了」报成失败；所以这里只回答「能不能起来」，起来之后进程就 `unref`，不跟着插件进程活。
- **滚轮缩放，锚在指针下。** 范围 25%–300%，一次滚轮一格（×1.1）；`−`/`+` 走 25% / 50% / 100% / 200% / 300% 这几档，所以「正常比例 → 缩小一倍」是一次点击；点中间那个百分比回到 100%。缩放只作用于显示：卡片存下来的永远是内容坐标，所以任何缩放下拖动都跟着指针走（指针位移按缩放折算）。两个实现细节值得记着——滚轮监听必须**非被动**（React 的 `onWheel` 是被动的，`preventDefault` 在那里无效，画布会一边缩放一边滚动），所以由元素自己注册；而「同一个内容点留在指针下」需要的滚动位置，只能在缩放后的层重新渲染之后才设得下去，于是它先存进 ref、由 `[zoom]` 的 effect 应用。
- **右键/中键拖动 = 平移画布，左键拖空白 = 框选。** 滚轮被缩放占用后，画布靠拖拽移动：右键在**任何位置**都平移（卡片上也一样），中键在空白处平移；左键在空白背景上拖出一个框，框到的卡片就被选中（按住 Ctrl/Shift 是加到已有选择上，不按就是替换掉它）。分工是有意的——画布铺满卡片时也得能框选，所以左键拿去框选，平移退到右键和中键；而左键在卡片标题上仍然是移动卡片，右键从来不移动卡片。右键同时被 `onContextMenu` 吃掉，免得外壳的菜单打断拖拽。
- **选中卡片有三种方式。** 点一下卡片（按下到抬起没超过 3 像素）就选中它，并且只选它；按住 Ctrl 点一下是切换这一张，按住 Shift 是再加一张；`Ctrl+A` 全选，`Esc` 取消选择，点画布空白处也取消。选中的卡片用品牌色描边加一圈光晕画出来。
- **整组移动是刚体。** 拖动选择里的任意一张，整组跟着指针走同一段位移，卡片之间的距离不变；能走多远取「组里最受限制的那张卡」允许的值，所以既不会有卡片被推出平面，也不会有卡片先停下。拖动不在选择里的卡片时，那一张会被选中并单独移动——选择在**真的动起来**时才改，否则拖动一张已选中的卡片会先把整组解散。
- **`Delete` 删除选中，`Ctrl+Z` 撤回。** 删除键（`Backspace` 同义）把选中的卡片一次全拿掉。焦点在便签或标题输入框里时这三个键都不生效：那里的 Delete 是一个字符，Ctrl+Z 是浏览器自己的文本撤销。每次画布编辑（加入、拖动、改名、便签、删除）都会先存一份快照，`Ctrl+Z` 一步步往回走，最多 50 步；一次手势算一步，便签按「一次进入编辑框」算一步，不会每敲一个键就存一版。
- **删除只把卡片从画布上拿掉，字节留给「清理」。** 这样 `Ctrl+Z` 能把卡片**连文件一起**还原，另一台机器上还显示着的卡片也不会因为一次拉取就没字节。代价是 `files/` 里的字节要等清理才消失，所以标题栏会数出「N 个未引用文件（大小）」，那个按钮按两次（第一次只是问一句）才真的删掉它们，并跟着下一次保存提交；字节删掉之后撤回历史会一起清空——历史里的卡片已经指不到文件了。
- **剪切板两个方向都走宿主。** 往外：选中卡片后 `Ctrl+C`——选择里有文件卡就把这些**文件本身**放进系统剪贴板（Windows 用 `Set-Clipboard -LiteralPath` 写的是文件列表，macOS 交给 Finder `POSIX file`），于是能在资源管理器或任何别的程序里粘贴；全是便签时放进去的是它们的文字。页面读得到文件列表，却写不了一个，所以这件事只能宿主做，提示行会说明放进去的是什么。往里：窗口上挂着 `paste` 监听，面板外复制来的文件（资源管理器里复制的文件、截图工具截的图）一律入库成卡片，图片没名字时用 `clipboard-<时间戳>.<扩展名>` 补一个；剪贴板里只有文字就在画布上落一张写着那段文字的便签。焦点在便签或标题输入框里时这个监听不管事——那里的粘贴仍然是浏览器自己的文本粘贴。
- **复制同时接 `keydown` 和 `copy` 两个事件。** 前者是常规路径（处理了就 `preventDefault`，浏览器的默认复制动作因此不会发生，两者不会各跑一次），后者是兜底：万一有谁在上游把 Ctrl+C 吃掉了，浏览器自己发出的 `copy` 仍然落到这个面板上。选择为空时 `copy` 不管事——那多半是别人在正常复制网页文字。宿主半边是**启动时加载一次**的，所以浏览器半边刷新过、宿主还没重启时，这条路由会以 web server 自己的 404 页面作答，提示行会直接说「宿主半边还没有这条路由：重启 DSH 之后再试」，而不是抛一段 JSON 解析错误。
- **宿主执行剪贴板命令是等待的。** 和启动文件管理器不同，这里的退出码就是答案：文本走子进程的标准输入（不拼进命令行，便签里的任何字符都不用转义），失败原样报到提示行；平台没有对应命令（Linux）时返回 501，提示行说清楚而不是假装成功。
- **不做拼写检查。** 便签里粘的常是 key、路径、代码，浏览器给它们画的红色波浪全是噪声；便签的 `textarea` 和标题的 `input` 都显式 `spellCheck={false}`。
- **画布是一块固定大小的平面。** 坐标以平面中心为原点（`x ∈ [-2000, 2000]`、`y ∈ [-1500, 1500]`），所以卡片可以被放到原点左上，平面本身**不会因为卡片移动而移动、变大或重新居中**——这是关键：卡片移动时视图绝对不能跟着挪，否则看起来像画布在动而不是卡片在动。拖动只被平面自己的边界拦下（整组一起拖时，取组内最受限制那张卡允许的位移），而那边界远到平时感觉不到。
- **打开时把视角对准卡片。** 第一次加载完成后按卡片包围盒的中心定位一次（空画布就是平面中心），此后不再动。比视口小的平面由 `margin: auto` 居中（**不用 `justify-content: center`**，那个会让平面的左上角滚不到，而放大后平面必然比视口大）。平面本身画了出来（浅底 + 描边），所以它的边界是看得见的。
  两处布局陷阱：拖拽提示原来是 `position: sticky`，而 sticky 元素**仍在流内**，会变成平面旁边的第二个 flex 子项、把居中挤偏；另外空状态与拖拽提示原来都在**滚动容器内部**，而打开时视角是对准卡片的（不是容器左上角），它们会被滚到屏幕外——现在两者都放在滚动容器之外、由外层定住。
- **拖动按「指针位移」算，不按「落点」算。** 位置 = 起始位置 + 指针位移 ÷ 缩放。这不是风格问题：早先版本用「落点」反推位置，而落点要减掉层偏移；层偏移一旦随卡片变化（动态包围盒那版），每个 move 事件都会再叠一次累计位移，卡片会加速逃逸。用位移算，画布自身的布局完全不进入算式。
- Git 命令要等网络（SSH 握手在本机约 4 秒），这段时间几个按钮会一起禁用，但提示行会说明正在做什么。
