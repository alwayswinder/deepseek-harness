# 网站导航（个人网站库）

桌宠右键菜单 → **网站**，下面两个入口打开同一份库：

- **网站导航** —— 用系统浏览器打开生成好的 `dist/index.html`：**只读**，但窗口大、不依赖 DSH 在前台。
- **导航编辑** —— 在 DSH 的右侧栏打开**可编辑**的网站库页面：卡片上能改标题/分组/标签/备注/置顶，能加新网站、删网站。

唯一的事实来源始终是同一目录下的 `bookmarks.yml`；两个页面都是它生成的。

```
bookmarks.yml        网站库（进 git，跨机同步）
assets/<id>.png      图标（进 git）
library.mjs          读写与解析规则（导入、生成、编辑器共用）
import.mjs           一次性：浏览器导出的书签 HTML → bookmarks.yml
markdown.mjs         notes 的 Markdown 渲染（先转义再套规则）
build-page.mjs       生成 dist/index.html，以及宿主发的那份可编辑页
dist/index.html      只读展示页（生成物，不进 git）
tests/               node --test 跑的用例
```

## 在页面里编辑

编辑界面是桌宠插件自己的一个**右侧栏页面**（`little-icon-favorites`），读
`GET /api/little-icon/favorites/data`，保存走同源的 `POST /api/little-icon/favorites/save`：
宿主校验、写 YAML、顺手重建 `dist/index.html`，页面重新读取后就是新内容。

> 为什么不在 DSH 的 Browser 标签里？那个标签是独立存储分区里的访客，`apps/desktop/src/browser-guests.ts`
> 会取消它对本机 Host 的一切请求——嵌进去的页面连读都读不到。插件自己的页面渲染在主窗口里，
> 同源、带连接身份，才写得回库。

- 卡片右上角悬停出现 **✎ 编辑** 和 **✕ 删除**；页头 **＋ 添加网站** 打开表单。
- 表单里能改**网址、标题、分组、标签、备注、置顶**。分组框是自由输入，会列出已有分组；
  标签用空格或逗号分隔，最多 8 个。
- 标题留空就用域名；分组留空归到「未分组」；网址必须是 http/https，同一地址不能重复添加。
- 删除会先问一次。每次改动都是一次保存，保存成功后重新读取库，所以看到的永远是文件里的内容。
- **身份按网址定**：改标题、换分组、改标签都不动 `id`，图标和添加时间跟着走。换网址等于换一张卡片。
- 页面本身不抓图标：新加的卡片先显示首字母色块，想要图标就把 `assets/<id>.png` 放进去
  （`<id>` 是该条目的 `id`，新条目等于规范化网址的 sha1 前 12 位）。

保存接口校验的是 DSH 自己的连接身份：系统浏览器直接开那个 `http://127.0.0.1:...` 地址会被拒
（401），这是有意的——不这样的话，本机任何一个网页都能改你的库。

## 日常怎么用

```sh
# 1. 从浏览器导出的书签 HTML 导入（重跑安全：已有条目不动，只补新增）
node _mytools/favorites/import.mjs                 # 默认取 _mytools/Note/favorites_*.html 里最新那份
node _mytools/favorites/import.mjs D:\导出.html     # 或指定文件
node _mytools/favorites/import.mjs --dry           # 只看会做什么，不写文件

# 2. 生成展示页（DSH 开着时宿主会自己重建，手动跑也可以）
node _mytools/favorites/build-page.mjs

# 3. 测试
cd _mytools/favorites && node --test
```

DSH 运行时，宿主在每次状态采样里比较 `bookmarks.yml` 与 `dist/index.html` 的修改时间，库更新了
就自动重建；在页面里保存一次也会立刻重建。**改完记得 commit + push**，另一台 `git pull` 下来就是
新的（页面会在那台机器上重新生成）。

## 数据格式

```yaml
version: 1
bookmarks:
  - id: 6f3a1c2b9d40              # 规范化 URL 的 sha1 前 12 位，分配后不再变
    url: https://www.bilibili.com/
    title: b站
    group: Unreal/Study            # 你自己那套：导出文件里的文件夹路径，斜杠分层
    notes: |
      素材站，**收藏向**
    autoTags: [Unreal, 素材]        # 机器那套：模型给的自由词标签，1–3 个
    icon: assets/6f3a1c2b9d40.png
    pinned: false
    addedAt: 2026-10-15T10:55:19+08:00
    updatedAt: 2026-10-15T10:55:19+08:00
```

**两套分类**：`group` 是你管的（浏览器导出的文件夹，只有人会改）；`autoTags` 是模型给的标签，
用来横向筛选。重跑分析时**只补没有标签的条目**，不覆盖已有的（要整份重刷得显式说明），因为换个
模型或换个时间，分词就会不一样。

- **`id` 是关键**：跨机合并靠它对不对得上。改标题、换分组、搬目录都不要动它；改 `url` 也一样
  （备注和图标跟着 id 走）。新建条目按 URL 派生 id，撞上了就说明这条已经在库里。
- 可空字段（`notes`/`autoTags`/`icon`/`pinned`/`updatedAt`）没有值就省略，文件里一条一个块，diff 干净。
- `title` 和文件夹名在导入时会清掉**看不见的字符**（零宽空格/连接符、双向控制符、BOM 等）并折叠空白：
  从飞书文档复制的标题前面可能挂着几十个，页面上显示成一段空白、搜索也搜不到。
- `group` 为空的条目在页面上归到「未分组」（直接放在浏览器工具栏下的条目就是这种）。
- 浏览器自己那层容器目录（中文界面的「收藏夹栏」、英文的 `Bookmarks bar`）不进 `group`：每个路径都带一遍它没有信息量。规则在 `library.mjs` 的 `CONTAINER_FOLDERS` 里，导入和以后的编辑器共用。
- 文件末尾由脚本按固定格式重写（块序列、`lineWidth: 0`），所以手改之后最好再跑一次
  `build-page.mjs` 让页面跟上；`git` 的合并冲突按条目手解即可。在页面里编辑时宿主写的就是
  同一套格式，所以两条路径写出来的文件长得一样。

## 展示页

自包含单文件、零外部请求、零依赖：图标内联成 data URI，`notes` 在生成时渲染成 HTML。带搜索
（标题/网址/备注/标签/分组）、分组筛选、分组折叠、置顶区、深浅色跟随系统。顶部那行筛选**只有
你那一套**（文件夹）；AI 标签出现在**每条卡片上**（虚线边框，表明是机器给的），搜索框也能搜到，
但不占筛选行——两套分类不抢同一个控件。

页面有两个：同一份库生成两份产物，另外宿主还提供一份 JSON 给插件自己的侧栏页。

- `dist/index.html`（系统浏览器打开的那份）**只读**，不内嵌任何书签数据，也不带编辑脚本。
- `GET /api/little-icon/favorites` 现场生成的可编辑 HTML（带内嵌数据、`data-id`、悬停按钮和
  编辑对话框）——给网页版 DSH 用；桌面端的 Browser 标签够不着这个 Host，所以那边走的是：
- `GET /api/little-icon/favorites/data` 的 JSON + 插件自己的侧栏页（`little-icon-favorites`）。

保存请求都带一份**版本戳**：页面打开之后库要是被别处改过，保存会被拒并要求刷新，不会拿旧列表
覆盖新改动。

已知限制：

- 置顶条目在「置顶」区和它自己的分组里各出现一次。
- 新加的网站没有图标，先显示首字母色块；页面不会去站点抓 favicon，要图标得自己放 `assets/`。
- 不能调整卡片顺序，也不能重命名/合并分组（改 `group` 文本即可，空出来的分组自然消失）。
- 导出文件里的空文件夹不会出现在页面上（数据里没有"组"这个实体）。
- 图标是导出那一刻的快照，站点换了 favicon 不会自动更新。
- Markdown 只支持一层列表嵌套；段落里单个换行就是换行（与严格 Markdown 不同）。
- 页面里的备注链接只放行 http/https。

## 为什么这么设计

- **数据在仓库里，同步就是 `git pull`**：不需要额外的同步步骤，合并粒度是行级的，冲突 git 自己会标出来。
- **数据与页面分开**：页面随时可以从库里重建，坏了就删掉重生成。
- **导入永不破坏已有数据**：备注、标签、图标是手写的，比导出文件可信。
- **编辑只在宿主提供的那份页面上**：`file://` 打开的页面没有写文件的通道，与其在浏览器里存一份
  影子数据（下次重建就丢），不如让保存走 DSH 的同源路由——校验、写 YAML、重建页面都在宿主进程里
  一次做完，页面刷新看到的就是磁盘上的内容。
