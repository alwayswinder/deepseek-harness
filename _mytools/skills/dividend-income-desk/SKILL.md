# 收息持仓 · 下一交易日开盘方案

面向长期持有、以分红现金流为目标的 A 股组合。每次只产出一份「下一交易日开盘执行清单」：明天做什么、做到什么价、什么条件下不做。不做中长期预测，不给必涨结论。

## 准备

本文件所在目录就是 skill 根目录 `SKILL_ROOT`。脚本都用绝对路径调用，先确定根目录再执行：

```sh
node "$SKILL_ROOT/scripts/next-trading-day.mjs" --count 3
node "$SKILL_ROOT/scripts/dividend-dossier.mjs"
```

个人阈值在 `SKILL_ROOT/config.json`：目标股息率、加仓下限、减仓下限、单只上限、计划现金比例、按代码的 `overrides`，以及不套股息率阈值的价值修复类 `repairCodes`。用户明确改了偏好时，改这个文件，不要改脚本。

账户总资产（现金 + 持仓市值）记在持仓插件的同一台机器上：插件页「总资产」一行读写 `$DSH_HOME/ths-holdings.assets.json`，脚本按「总资产 − 持仓市值」算可用资金。用户临时给出新数字时，用它写入，不要只在回答里口算：

```sh
node "$SKILL_ROOT/scripts/set-assets.mjs" --total 1000000
node "$SKILL_ROOT/scripts/set-assets.mjs" --clear
```

## 第 0 步：确定日期与时段

```sh
node "$SKILL_ROOT/scripts/next-trading-day.mjs" --count 3
```

- 交易日只按周末推算，不查法定节假日：春节、国庆这类长假前后先确认交易所当天是否开市，拿不准就在结论里写明。
- 输出里的时段决定口径：盘中（15:00 前）现价还会变，按「今日尾盘到下一交易日」写；收盘后按「下一交易日开盘」写。
- 结论开头写明：当前时间、处于哪个时段、这份方案面向哪一天的什么时段。

## 第 1 步：取持仓与数据

```sh
node "$SKILL_ROOT/scripts/dividend-dossier.mjs"
```

- 默认把 Markdown 表打到 stdout，直接读；要留档再加 `--out "$env:TEMP\dividend-desk.md"`（PowerShell 里 `$TEMP` 是空的，必须写 `$env:TEMP`）。
- 加 `--json` 取结构化字段，加 `--no-news` 跳过公告。
- 输出里的「可用资金：未设置总资产」：问用户账户总资产是多少（或沿用他说过的数），拿到后用 `set-assets.mjs` 写入再重跑；没拿到就按「现金未知」出结论，不要假设满仓。
- 权重口径会写明按「总资产」还是「持仓市值」；总资产已设置时，单只权重按总资产算，现金不摊进任何一只标的。
- 「行业权重」表按东财行业名汇总；超过 `config.json` 的 `maxIndustryWeightPct`（默认 35%）会进「⚠」。ETF 归在 `ETF/基金` 一类，不参与产业链集中度判断。
- 快照时间显示「N 天前」且 N > 7：提醒用户先在插件页（Settings → Plugins → `dsh-ths-holdings`）更新持仓，并在结论里标注数据时点。
- 「数据问题」一栏有内容：逐条说明缺了什么数据，相关标的的判断要降级为「数据不足」。
- 带「分红缺口」的数据问题：公告写明已实施分派、东财分红表却没有这条记录（典型是特别分红），脚本已按公告正文补录每股金额与除息日。补录只进「TTM 股息率」，年度股息率、目标价仍按分红表口径——判断时两列一起看，但一次性特别分红不能外推成经常性收益。
- 「提醒」里标了「价值修复类」的标的：不按股息率阈值判断，按 `reference/framework.md` 第 5 节给它们各自设退出条件。
- 持仓文件路径与 `exported_at` / `updated_at` 必须出现在最终答复里，让用户能核对。

插件若配置了同花顺账本 Cookie，卡片数字来自账本接口，与持仓文件可能不同步。这种情况写明「本次用持仓快照」，并提示用户在卡片上核对当前数量。

## 第 2 步：查消息与公告（只查要决策的）

数据脚本拉取每只标的最近 6 条公告（明细里列前 4 条，JSON 里是全量）和披露日程。按标题定位事件：定期报告、分红实施、减持解禁、诉讼处罚、业绩预告、回购增持。

优先级：

1. 权重前 5 的标的；
2. 「提醒」里出现净利下滑、分红下降、财报临近、权重超限的标的，以及「进入目标价区间」一节里的标的；
3. 今日涨跌幅超过 4% 的标的（有异常必有原因）。

需要正文时用公告脚本，不要只凭标题下结论：

```sh
node "$SKILL_ROOT/scripts/announcement.mjs" --code 000895            # 最近 6 条标题
node "$SKILL_ROOT/scripts/announcement.mjs" --code 000895 --body     # 最近 1 条正文
node "$SKILL_ROOT/scripts/announcement.mjs" --code 000895 --index 3 --body
node "$SKILL_ROOT/scripts/announcement.mjs" --art AN202610091830271801
```

定期报告窗口（4 月、8 月、10 月）先看预约披露日：未披露的不要臆测业绩，只写「待披露」；已披露的用 dossier 的财报字段加公告正文里的管理层表述。

本机 `web_search` / `web_fetch` 可能不可用：`web_fetch` 会报 `multiple usable web providers are registered`，`web_search` 走 OpenCode 网关时也可能拿不到结果。此时用 `node -e "fetch(...)"`、`curl.exe` 或 `Invoke-WebRequest` 直连接口；抓不到正文就写「未取到正文，仅按标题判断」。

## 第 3 步：按框架判断

框架全文见 `SKILL_ROOT/reference/framework.md`。先看组合层面的现金，再逐只看标的：

- **可用资金 ≤ 0 或低于计划现金**（`config.json` 的 `cashReservePct`）：本轮只做减仓、换股和条件单；任何买入都要先有卖出回款，且买完仍要留住计划现金。
- **可用资金高于计划现金**：可以分批建仓，单日投入不超过「可用资金 − 计划现金」的三分之一。
- 这两条优先于个股信号：现金不够时，再好的股息率也只挂条件单，不市价成交。

对每只标的回答四个问题：

1. **分红能不能持续**：派息率是否超过 90%、最近两个年度每股分红是升还是降、净利润同比方向、经营现金流是否覆盖分红。
2. **价格对应多少股息率**：现价股息率与成本股息率，是否低于目标价（脚本已算好目标价）。
3. **财报有没有变坏**：最近一期营收/净利同比，和前两期连起来看是波动还是趋势。
4. **有没有必须规避的事件**：7 日内除息、财报披露前一日、监管处罚、大额减持、解禁。

结论落到三档：**加仓**（分红可持续 + 价格进入目标价区间 + 无事件风险）、**持有**（分红可持续但价格未到，或仅为短期波动）、**减仓/换股**（分红削减、现金流恶化、基本面逻辑破坏，或权重超限）。

价值修复类持仓（低股息、破净、行业底部）单独判断：它们是「修复」不是「收息」，要给出自己的退出条件，不套用股息率阈值。

## 第 4 步：输出执行清单

固定结构，先结论后细节：

1. **一句话结论**：明天开盘做什么，最多三件事。
2. **执行表**：

   | 代码 | 名称 | 方向 | 价格区间 | 数量/金额 | 触发条件 | 失效条件 | 理由（引用具体数据） |
   | --- | --- | --- | --- | --- | --- | --- | --- |

3. **组合检查**：单只权重是否超上限、行业权重是否超上限（报告已算好）、可用资金与计划现金的差额、未来一周的事件日。
4. **只观察的标的**：一句话说明为什么不动。
5. **数据与免责**：行情时间、持仓快照时间、没取到的数据；声明这是基于公开数据的个人决策辅助，不是投资建议。

硬性要求：

- 价格区间必须有来源：目标价、成本价、或最近成交价加减，不能凭空写数字。
- 数量按 100 股整手；分批时写清每批的价格与比例。
- 每条建议都要有触发条件和失效条件；没有触发条件的表述不算建议。
- 买入金额必须落在可用资金内，并留出计划现金；现金未知时只能给条件单，不给确定金额。
- 不预测指数点位，不写「必涨」「稳赚」，不建议融资或加杠杆。
- 红利税：持股不满 1 年卖出会补扣 10%–20%，核心仓不因短期波动卖出；减仓优先安排已满 1 年的仓位。
- 除息日前 7 个交易日内不新增大额买入。
- 数据缺失、快照过期、接口失败必须写明，不能用记忆补齐。

## 什么时候重跑

- 每个交易日开盘前；
- 持仓变动后（插件页修改或重新导出账本）；
- 定期报告披露当日或次日；
- 长假前后需要精确交易日时，先核对交易所的休市通知：脚本只跳过周末。
