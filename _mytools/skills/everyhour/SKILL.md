# everyhour · 整点推送

用户说 **everyhour** 就进入推送状态：每个整点推一条，他打 0–10 分，用分数改选材。说「停」「别推了」就退出。

目标不是信息量，是**他想转发给别人的那条**。

## 每次触发做什么

1. 读 `<个人隐私库>/feed/preferences.md`（偏好与打分）
2. 读 `<个人隐私库>/feed/history.md` 的最近 100 条（去重）
3. 选一条，**只发一条**
4. 追加一行到 `history.md`
5. 不问「还要吗」，不多发，不解释流程

个人隐私库的位置：取 temp-space 插件的当前数据目录 —— 先看 `$DSH_HOME/temp-space.location.json`，没有就看所用 profile 的 `cordis.patch.yml` 里 `dsh-temp-space` 的 `dataDir`。

## 选材

- **领域不限。** 历史、文化、科技、金融、自然科学、艺术、医学、工程、制度、地理、语言……都行；下面这类清单只是举例，不是菜单。
- **别总在一个池子里捞。** 不要连着两条同一领域，金融类控制在三分之一以内；用户在某领域打高分时再加权。
- 标准：两条路都算数——**有意思**（反直觉、有具体细节、可验证、能一句话转述），或者**有价值**（以后真用得上：一个方法、一个工具、一个机制、一个判断框架）。
- **优先机制拆解**：这东西怎么定义、怎么保证正确、出错会怎样、边界在哪。只有故事没有机制的选题（一段历史轶事、一个惊人的数字）不够格。
- 用户对「共识与参考系」类问题反应明显——「大家都用着错的东西却没人察觉」这类题目优先。
- **不限新闻**：冷知识、原理解释、历史案例、行业机制、数据口径都行，没新闻可讲时就讲知识。
- 当日新闻优先，但必须是「有意思」或「有用」，而不是「重要」——不复述行情、不复述政策原文。
- 避雷：鸡汤、成功学、烂大街的伪冷知识（「爱因斯坦数学不及格」「拿破仑矮」这类）。
- **金融类不许停在「谁赚得多」。** 光比财报数字会隐含「业绩好=该买」。有意思的是反差本身：利润差几倍，股价反应却相反——所以要交代市场在定价什么，不写任何能被读成买卖暗示的句子。
- 「有价值」不等于「能直接照着操作」：讲机制、讲方法可以，给结论性的买卖动作不行。
- 每条结尾一句「为什么有意思 / 为什么有用」，不超过一行。

## 打分闭环

- 用户回复 0–10 的数字，就是对最近一条的打分。
- 记入 `preferences.md`：日期、摘要、类型、分数。
- 推送前看判断段：高分类型加权，低分类型避开。
- **连续 3 条低于 5 分 → 换赛道**：换主题池，或换叙事方式（比如从「冷知识」换成「正在发生的事」）。
- 用户明确说「不喜欢 X」时，直接写进判断段的避雷清单。

## 输出

一条消息，手机上两到四行，不用标题、不用编号列表。像跟朋友说一件事，不像简报。

## 边界

- 每小时一条，深夜时段（23:00–08:00）不推。
- 抓不到可靠来源就不发，宁可这一小时空着，也不编。
- 不推送投资建议，金融类只讲事实和机制。
